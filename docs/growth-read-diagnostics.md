# 群聊成长数据读取与引用诊断

日期：2026-11-11。本批只增加只读诊断，不新增领域模型、模型调用或自动写入。私聊和桌面仍返回原来的检索条目，不保存本批群聊诊断。

## 范围与状态

角色全局授权完成后，QQ群聊读取偏好、语言习惯、进行中愿望；知识仍由已有语境分析的knowledgeQuery按需触发。未触发知识查询记not_needed；语境关闭/失败没有知识查询也保持not_needed，不因此推断用户问题不含知识价值。

| 状态 | 含义 |
| --- | --- |
| not_needed | 代码路径未触发读取，或偏好/愿望没有可用查询词；不是模型质量判断 |
| no_match | 本次有界候选中没有符合既有匹配规则的条目 |
| failed | 领域数据库/检索抛错，回复继续用原降级规则；不伪装无匹配 |
| budget_excluded | 有匹配，但序列化预算未能放入任何条目 |
| provided | 选出条目供本轮模型上下文装配，不表示模型已理解或使用 |

各检索器仍使用原来的SQL/词法排序/预算，未增加SQL或模型请求。偏好与愿望无查询词不查库；语言习惯的通用条目仍可每轮参与选择。所有领域仅取当前角色ACTIVE正式条目，候选不入模。

## 计数与版本

candidateCount是数据库已取回的候选切片，matchedCount是其中通过原有ACTIVE和词项/场景判断的条目。selectedCount为选入数；budgetExcludedCount记录被本地预算跳过，limitExcludedCount记录达到条数上限后剩余匹配。candidateLimitReached只表示取数达到上限，不证明全库仍有更多匹配。

偏好/语言/愿望候选最多100，知识最多300；最终偏好6、语言6、愿望4、知识8。偏好600、语言800、愿望1000是序列化字符预算，不是供应商精确token；知识当前没有本批新增的统一序列化预算，未选择部分只计条数限制。诊断不能声称对全部数据库资料完整统计。

provided仅保存条目ID和revision；知识使用updatedAt作为本次读取版本标记。不复制标题、正文、查询、Key、账号或错误原文。日志白名单限制4个唯一领域，每领域最多8个引用，计数有界；只能群聊保存。

## 使用信息

回复成功后，将模型返回且已通过提示词白名单的usedPreferenceIds、usedExpressionHabitIds、usedGoalIds与本轮provided再取交集。沉默轮清空usedIds，失败生成不伪造使用。知识暂时没有usedKnowledgeIds协议，页面明确“知识暂未回传引用”，不把空usedIds说成模型没用知识。

接口状态provided和引用字段provided保留为内部兼容命名，页面准确显示“已选入模型上下文”。读取时就记录选中集合，因此如果后续在模型请求前失败，不保证请求真的已发出；不能据此声称供应商已收到这些条目。“选入”是服务端选择及装配链路信息；“自报使用”是模型输出的引用，不等于已验证的语义因果。提供但未引用可能是未采用，也可能是未回报，不能直接判失败。本批不改变提示词输出协议或追溯已删除来源的策略。

## 日志与兼容

数据写入现有ModelTurnDetail.version1可选growthReads。成功与异常分支随群聊主日志保存，由原角色拥有者限定接口读取并再次sanitize。旧记录缺失显示未保存，不显示零条；私聊伪造字段不返回。没有新增表和迁移。

前端“成长数据读取与引用”显示状态、候选/匹配/选入、预算/条数排除、有限候选提醒，以及条目版本和模型自报引用。原协作阶段/HTTP诊断保持独立，SQL读取不计成模型请求。

- 现有偏好、语言、愿望和语境协作回归保持通过。
