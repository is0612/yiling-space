# 语料与表达习惯

第一批为独立的表达习惯管理与对话应用闭环，回答角色“怎么说”。管理入口为成长系统的“语料 / 表达习惯”。

## 与已有功能的分工

- 角色资料中的对话示例用于示范声音和语气，仍由用户在角色资料中维护。
- 梗语录用于在合适时机原样说出的具体台词，保留既有清单、冷却和记账。
- 表达习惯是可追溯的表达倾向，例如“闲聊倾向简短，解释复杂问题时可以展开”。不把喜好话题或别人的说话方式当成本人的表达习惯。
- 第一批不自动修改基础人设、对话示例、梗语录、社交关系或偏好。

## 数据与审核

新增 `CharacterExpressionHabit` 与 `CharacterExpressionHabitRevision`。类型为 TONE / WORDING / LENGTH，表达内容最多300字、适用场景最多200字（允许为空）、形成原因最多1000字。聊天范围 `chatScope` 为 ALL / GROUP / PRIVATE（默认 ALL，旧行按 ALL 兼容），由服务端按真实入口筛选，不靠正文里的渠道字样判断。角色拥有者才能管理相应记录。

状态为 PENDING / ACTIVE / REJECTED / DISABLED。手动添加默认待确认，也可明确选择立即生效；从来源形成的候选只能待确认。确认、驳回、停用与重新启用通过独立操作提交，不能与正文编辑混在同一次请求。修改必须携带expectedRevision；竞争更新只有一方成功，另一方返回409。无变化编辑不产生空版本。

每次成功操作在同一事务中追加操作结果的完整版本快照及USER审计。第一版有CREATE历史；旧版本不被覆盖。前端提供历史查看，不提供版本回滚或永久删除。

来源复用既有公开来源Gateway：最多5条当前角色全局ACTIVE忆泡或当前角色ACCEPTED反思建议。选择时返回指纹，创建及首次确认时在事务内重新校验角色、状态和内容版本；私人、跨角色、隐藏、删除或已变更来源不能越过审核。已确认习惯成为独立领域记录，来源删除不删除它；停用后重新启用保留已有人工判断。

## 可选模型辅助

用户明确点击后，使用当前角色聊天模型及每日额度，根据所选公开摘要提出一条草稿。证据不足可返回null；未知输出字段、非法类型和超长内容拒绝。模型调用不持有数据库锁，返回后重验来源；不直接创建候选或生效，不读取私人原文，不产生渠道动作。调用最多60秒、max_tokens4096，用量为other、metadata.source=expression-habit-suggestion，失败不透传供应商原文。重试由用户再次点击，第一批无后台周期自动生成。

## 聊天应用

桌面对话API和QQ渠道共同读取当前角色ACTIVE习惯，并把真实入口传入聊天范围：仅取 `ALL` 与当前场景（`GROUP` / `PRIVATE`）匹配的记录。空适用场景代表通用倾向，可参与每轮选择；非空场景使用确定性词项匹配。符合场景与范围的习惯先按用词（WORDING）优先，再按场景匹配程度和聊天范围排序。长期适用的用词纠正可将适用场景留空，并在正文写清适用条件，避免依赖群友刚好说到场景关键词。候选最多100条，最终最多6条，序列化字符预算800（含数组开销），不额外调用模型精排。

原会话限定（`conversationId` 非空）的记录仍只能在原会话使用，不能通过把范围改成群聊扩大。原会话经验派生习惯固定只在原私聊生效。

提示词版本为conversation-retrieval-v67。表达倾向不能覆盖角色身份、隐私、事实、当前明确请求或渠道限制；不要求复述描述，不强塞梗。冲突时结合当前场景处理，不捏造已经完成永久取舍。模型回传usedExpressionHabitIds只认本轮白名单，沉默轮清空；桌面对话将版本快照保存到usedSources.expressionHabits，QQ消息保存usedExpressionHabitIds与usedExpressionHabits，历史接口保留引用。引用来自模型自报，不等同于已验证的行为因果。

词法场景匹配不能充分理解近义场景；通用习惯较多时只选有界小集，不保证每条每轮都出现。已确认习惯可能存在矛盾，需用户维护。没有自动收集、批量导入、历史回填或角色卡携带，完整数据库备份可保留本领域。

## 跨场景教育候选

已授权私聊反馈经后台 Worker 分析后，可能生成 `sourceType = EDUCATION_TRANSFER` 的待确认习惯：只保存抽象表达倾向、聊天范围、自然场景和固定安全说明，不复制私聊原文、账号或原始原因。明确长期教育可凭一条证据提出；重复型需要不同反馈与跨日条件，不能把无关纠正相加。原经验继续留在原会话，生成的候选全局生效范围为空作用域。

主人可在语言系统查看候选的完整待共享内容与范围，编辑、驳回或确认；首次确认在事务内重验来源指纹和当前教育授权，之后由语言系统独立管理版本。撤权不影响已采纳习惯，但会阻止尚未采纳的候选启用。已采纳习惯的召回不读取来源引用，因此群聊与私聊都不会拿到私人摘录。原会话经验派生习惯仍固定原私聊，范围不能改成群聊。

后台分析有持久化租约与失败重试；只引用旧证据、重复证据不足或领域归属不匹配的建议丢弃不保存，不让整批失败。失败只记录白名单错误码。语义判断（是否长期、是否可跨场景、是否含私人信息）仍需人工审核与真实对话观察。

## 从群聊学说话

语言系统的「从群聊学说话」让主人手动选取已记录群聊中她没参与的一小段：开场、别人怎么接、对方后来怎么回。最多 12 条、15 分钟；明确是机器人或系统播报的消息不能当证据。角色模型只收到有限的文字和相对时间，发言人换成临时代号，不下载图片。记录缺少前因、可见后续或表情含义时，应返回无候选。不会开启额外群聊留存。

不想手选时，在同一弹窗选好群，开启「自动观察这个群」即可。开关默认关闭，重新开启从当时开始，只扫描过去 24 小时内已记录的新消息。现有常驻 Worker 按引用或明确回应挑短片段（例如不同人接话后，开场者明确表示理解），再让角色模型判断可见后续是否支持一条表达习惯。不会抓取聊天历史或改变现有记录策略，记录太少的群可能没有候选。每群两次模型尝试至少间隔约 30 分钟；角色已有 12 条待确认群聊观察时自动暂停，整理后继续。失败有持久进度和有限重试；关闭时不会再保存尚在分析的结果，已有候选仍保留。

有依据时保存一条 `GROUP_OBSERVATION` 待确认习惯，展示抽象表达、适用场景和观察原因。来源只记群会话与所选消息引用、时间和指纹，不存原话副本；采纳前重新核验来源。默认「所有聊天」，同角色网页、私聊和其他群都可按适用场景使用；聊天只收到表达与场景，不带观察原因或来源引用。采纳后可编辑、停用。当前沿用词项匹配、预算与人工语义审核，不能保证每一种相似措辞都能命中。

更新需应用 `20261119130600_group_expression_observation` 和 `20261119140000_automatic_group_observation`；迁移只扩展来源约束、增加进度表与接收顺序索引，不改写既有消息，也不启用任何群。更新网页服务和 Worker 后才会处理开启的群。

## 接口

`/api/characters/:id/growth/language` 提供GET分页/状态/搜索及POST创建；`/:habitId` PATCH编辑或状态操作；`/:habitId/history` GET历史；`/sources` GET公开依据；`/suggest` POST提出可编辑建议。契约在OpenAPI中同步。
