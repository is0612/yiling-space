# 语料与表达习惯

第一批为独立的表达习惯管理与对话应用闭环，回答角色“怎么说”。管理入口为成长系统的“语料 / 表达习惯”。

## 与已有功能的分工

- 角色资料中的对话示例用于示范声音和语气，仍由用户在角色资料中维护。
- 梗语录用于在合适时机原样说出的具体台词，保留既有清单、冷却和记账。
- 表达习惯是可追溯的表达倾向，例如“闲聊倾向简短，解释复杂问题时可以展开”。不把喜好话题或别人的说话方式当成本人的表达习惯。
- 第一批不自动修改基础人设、对话示例、梗语录、社交关系或偏好。

## 数据与审核

新增 `CharacterExpressionHabit` 与 `CharacterExpressionHabitRevision`。类型为 TONE / WORDING / LENGTH，表达内容最多300字、适用场景最多200字（允许为空）、形成原因最多1000字。角色拥有者才能管理相应记录。

状态为 PENDING / ACTIVE / REJECTED / DISABLED。手动添加默认待确认，也可明确选择立即生效；从来源形成的候选只能待确认。确认、驳回、停用与重新启用通过独立操作提交，不能与正文编辑混在同一次请求。修改必须携带expectedRevision；竞争更新只有一方成功，另一方返回409。无变化编辑不产生空版本。

每次成功操作在同一事务中追加操作结果的完整版本快照及USER审计。第一版有CREATE历史；旧版本不被覆盖。前端提供历史查看，不提供版本回滚或永久删除。

来源复用既有公开来源Gateway：最多5条当前角色全局ACTIVE忆泡或当前角色ACCEPTED反思建议。选择时返回指纹，创建及首次确认时在事务内重新校验角色、状态和内容版本；私人、跨角色、隐藏、删除或已变更来源不能越过审核。已确认习惯成为独立领域记录，来源删除不删除它；停用后重新启用保留已有人工判断。

## 可选模型辅助

用户明确点击后，使用当前角色聊天模型及每日额度，根据所选公开摘要提出一条草稿。证据不足可返回null；未知输出字段、非法类型和超长内容拒绝。模型调用不持有数据库锁，返回后重验来源；不直接创建候选或生效，不读取私人原文，不产生渠道动作。调用最多60秒、max_tokens4096，用量为other、metadata.source=expression-habit-suggestion，失败不透传供应商原文。重试由用户再次点击，第一批无后台周期自动生成。

## 聊天应用

桌面对话API和QQ渠道共同读取当前角色ACTIVE习惯。空适用场景代表通用倾向，可参与每轮选择；非空场景使用确定性词项匹配。按场景命中优先排序，候选最多100条，最终最多6条，序列化字符预算800（含数组开销），不额外调用模型精排。

提示词版本为conversation-retrieval-v55。表达倾向不能覆盖角色身份、隐私、事实、当前明确请求或渠道限制；不要求复述描述，不强塞梗。冲突时结合当前场景处理，不捏造已经完成永久取舍。模型回传usedExpressionHabitIds只认本轮白名单，沉默轮清空；桌面对话将版本快照保存到usedSources.expressionHabits，QQ消息保存usedExpressionHabitIds与usedExpressionHabits，历史接口保留引用。引用来自模型自报，不等同于已验证的行为因果。

词法场景匹配不能充分理解近义场景；通用习惯较多时只选有界小集，不保证每条每轮都出现。已确认习惯可能存在矛盾，需用户维护。没有自动收集、批量导入、历史回填或角色卡携带，完整数据库备份可保留本领域。

## 接口

`/api/characters/:id/growth/language` 提供GET分页/状态/搜索及POST创建；`/:habitId` PATCH编辑或状态操作；`/:habitId/history` GET历史；`/sources` GET公开依据；`/suggest` POST提出可编辑建议。契约在OpenAPI中同步。
