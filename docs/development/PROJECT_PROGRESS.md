## 验收状态怎么理解

每个任务只使用一个当前主状态，真实使用验收另记：

1. **待设计**：目标和边界还没确定。
2. **待开发**：方案已确认，尚未开始编码。
3. **开发中**：本地 AI 正在修改。
4. **待专项验收**：代码已提交或完成，等待针对性测试。
5. **待工程回归**：专项通过，等待类型、Lint、构建、数据库/隔离测试等整体检查。
6. **CI 修复中**：GitHub Actions 仍失败，当前任务没有关闭。
7. **待合并**：必要验收通过，等待合并目标分支。
8. **已完成**：代码已合并，约定的工程验收通过；真实使用验收若未做，必须额外注明。

**不要混淆以下结果：**

- 单项专项测试通过 ≠ 全量工程回归通过。
- 本地工程回归通过 ≠ GitHub Actions 全绿。
- GitHub Actions 全绿 ≠ 真实 QQ / 真实模型效果已验收。
- 文档写了方案 ≠ 代码已实现。
- 代码已合并 ≠ 用户已经完成真实使用验收。

## 每次开发交接必须更新

每次完成一个小批次，更新本文件对应行，并在相关功能文档记录技术细节。交接至少写清：

- **本次完成：** 修改范围与提交 SHA。
- **专项验收：** 实际执行的命令、结果；没跑的明确写未执行。
- **工程回归 / CI：** 运行链接、结论和失败步骤；不能只写「CI 失败」。
- **真实使用验收：** 未开始 / 待用户验收 / 已通过，并说明验证场景。
- **当前卡点：** 具体失败项及已确认/未确认的根因。
- **下一步：** 只指定一个最优先动作，避免多个任务并行导致进度混乱。
