- 本轮代码审查发现 / 待优化：
  1. **工作流正负提示词节点可能互相覆盖（中等优先级）**：`applyWorkflowTemplate` 分别把 positive 与 negative 写入对应节点，但当前模板解析只验证 positive；若模板把两条连线接到同一个文本节点，negative 会覆盖 positive，最终画面描述可能丢失。建议保存时校验 positive/negative 都连到有效文本节点且不是同一节点，并加回归用例。
  2. **多 KSampler 工作流的校验与注入规则不一致（中等优先级）**：保存校验用第一个 sampler，注入阶段遍历后留下最后一个 sampler 的正负节点；多采样器图可能校验通过却改错节点。第一版若只支持单采样器，建议明确拒绝多个 sampler；若要支持多采样器，则按实际输出链路定位并逐个验证。
  3. **模板解析会忽略非节点值（低/中优先级）**：`parseWorkflowTemplate` 用 `filter` 只保留对象节点，若顶层混入少量字符串/数字等非节点字段，会被静默忽略校验但仍留在最终图里，可能直到 ComfyUI 提交时才失败。建议要求顶层每个键都必须是有效节点对象。
  4. **第三方角色识别正则存在误判空间（低/中优先级）**：`THIRD_PARTY_COPYRIGHT` 只要遇到英文括号内含两个词就可能命中，不要求括号前一定是角色名；普通场景短语如括号中的风格/构图说明也可能跳过小鲸鱼形象档案。建议增加非角色括号负例，收紧到「角色名 + 作品名」结构。
  5. **工作流文件并发写入的临时文件名可加强（低优先级）**：当前临时文件名只拼 `process.pid`，同进程同时保存同一路径时会竞争同一个临时文件；可改为每次写入唯一随机后缀，并在失败时清理临时文件。
  6. **工作流模板测试偏结构/源码断言（验收缺口）**：`test:image-workflow-template` 覆盖解析、读写、mtime、删除及接口源码鉴权标记，但没有真正执行 ComfyUI 工作流，也未覆盖正负节点同源、多采样器和跨进程实际生图。当前最小测试图甚至把 positive / negative 都连到同一个文本节点，只能证明解析通过，不能证明实际提示词注入正确。需补真实注入回归及本机真机验收。

每个任务只使用一个当前主状态，真实使用验收另记：

1. **待设计**：目标和边界还没确定。
2. **待开发**：方案已确认，尚未开始编码。
3. **开发中**：本地 AI 正在修改。
4. **待专项验收**：代码已提交或完成，等待针对性测试。
5. **待工程回归**：专项通过，等待类型、Lint、构建、数据库/隔离测试等整体检查。
6. **CI 修复中**：GitHub Actions 仍失败，当前任务没有关闭。
7. **待合并**：必要验收通过，等待合并目标分支。
8. **已完成**：代码已合并，约定的工程验收通过；真实使用验收若未做，必须额外注明。

**不要混淆以下结果：**

- 单项专项测试通过 ≠ 全量工程回归通过。
- 本地工程回归通过 ≠ GitHub Actions 全绿。
- GitHub Actions 全绿 ≠ 真实 QQ / 真实模型效果已验收。
- 文档写了方案 ≠ 代码已实现。
- 代码已合并 ≠ 用户已经完成真实使用验收。
