## 0. 一句话

**角色管设定与记忆，渠道只管收发。**

一个可自行部署的多角色 AI 养成平台：角色在 QQ 群、QQ 私聊、B站 值班台、网页工作台四处活动，所有经历写进同一份分层记忆；同一个角色换渠道不失忆，不同用户的私人记忆互不可见。

---

## 1. 它解决的不是「AI 会不会聊天」

接个大模型 API 就能聊天，这不是难点。真正的三个坑是：

| 坑 | 表现 | 本项目的应对 |
| --- | --- | --- |
| **忘** | 昨天聊了三小时，今天问「昨天那事怎么样」她一脸茫然 | 四层记忆 + 按天忆泡 + 日期区间检索 + 原文兜底 |
| **串** | 群聊记忆污染私聊，A 用户的私事泄露给 B | `MemoryScope` 分级 + 检索侧强制白名单 |
| **断** | 模型调用失败、进程重启、网关掉线，消息就没了 | 消息先落库再判断 + 持久化任务队列 + watchdog |

这三件事决定了整个架构：**事实层只追加、结论层可替代、渠道与角色解耦、后台任务独立成进程**。

## 2. 架构：六个进程，一个数据库

```
                       ┌──────────────────────────────┐
   浏览器 ──HTTPS──▶   │ Web 服务（Nuxt/Nitro :3000）  │
                       │ 页面 + /api + 鉴权 + 会话      │
                       └───────────────┬──────────────┘
                                       │
   ┌───────────────────────────────────┼───────────────────────────────┐
   │                                   ▼                               │
   │                        ┌──────────────────────┐                   │
   │   scheduler:run ──────▶│  PostgreSQL          │◀────── worker:run │
   │   （按周期边界入队）    │  任务队列 / 记忆 /   │   （领任务调模型）  │
   │                        │  消息 / 用量 / 审计  │                   │
   │                        └──────────┬───────────┘                   │
   │                                   │                               │
   │   onebot:run ──────────────▶  QQ（OneBot v11 网关）               │
   │   bili:run   ──────────────▶  B站（CLI + 值班流水线）              │
   │   proactive:run ───────────▶  QQ 私聊 / 群（主动开口）            │
   └───────────────────────────────────────────────────────────────────┘
```

| 进程 | 命令 | 职责 | 不跑会怎样 |
| --- | --- | --- | --- |
| Web 服务 | `yarn start` | 页面、`/api`、鉴权 | 什么都打不开 |
| 排期器 | `yarn scheduler:watch` | 判断到期周期、排任务、排按天忆泡 | 记忆不推进，任务监控里全是「该排没排」 |
| Worker | `yarn worker:watch` | 领任务、调模型、事务落库 | 队列堆着不动，任务永远「排队中」 |
| QQ 适配器 | `yarn onebot:stack` | 收 QQ 消息、路由到角色、回发 | QQ 侧完全不响应 |
| B站 适配器 | `yarn bili:run` | 谷时看视频、打分、评论收藏动态 | 值班台空转 |
| 主动进程 | `yarn proactive:run` | 私聊主动找话 + 群冷场起话题 | 她永远等着你先开口 |

关键点：**后台任务不在 Web 进程里跑 `setInterval`**。周期必须持久化、幂等、可重试、可补处理——Web 进程重启一次就丢一堆定时器，这个代价在养成类产品里不可接受。

进程之间只通过 PostgreSQL 的任务队列协调，所以 Worker 可以放到另一台机器上，也可以起多个。

## 3. 记忆引擎（这是整个项目的主体）

### 3.1 四层，各管一件事

| 层 | 表 | 职责 | 可替代？ |
| --- | --- | --- | --- |
| **原始消息** | `Message` | 证据。对话事实、时间、来源渠道、去重键 | 是（有独立保留策略） |
| **忆泡**（事件层） | `MemoryEvent` | 某天发生了什么。事实层 | **否，只追加** |
| **周期快照** | `MemorySnapshot` | 一个阶段的结论：重要事件、偏好变化、关系、目标 | 是（新版本替代旧版本） |
| **长期记忆** | `MemoryItem` | 现在仍然成立的事实 / 偏好 / 关系 / 承诺 | 是（有效 / 收起 / 不再成立 / 已被替代） |

一句话记：**原文是证据，忆泡是事件，快照是结论，长期记忆是现状。**

### 3.2 产出节奏：谁在什么时候写什么

| 产出 | 谁负责 | 频率 | 幂等键 |
| --- | --- | --- | --- |
| 忆泡（当天增量） | 调度器 → `EXTRACT_EVENTS` | 每小时（最近一小时有新消息才排） | `events-hour:{scopeId}:{dayKey}:{hour}` |
| 忆泡（当天收口） | 调度器 → `EXTRACT_EVENTS` | 夜间，为「昨天」排一次 | `events-final:{scopeId}:{dayKey}` |
| 周期快照 | 调度器 → `GENERATE_SNAPSHOT` | 默认每 3 天（可设 1–8） | `auto-snapshot:{scopeId}:{periodStart}:{periodEnd}` |
| 日记 + 手账 | 调度器 → `GENERATE_JOURNAL` | 每天为「昨天」 | `journal:{globalScopeId}:{YYYY-MM-DD}` |
| 原文清理 | 调度器 → `CLEAN_EXPIRED_MESSAGES` | 按保留设置 | 按天 |

**8 天不是保留期。** 它只是「多久复盘一次」。原文保留期是另一个开关，默认关闭（等于永久保留）。

2026-11-01 起，快照**读**忆泡而不自己产出事件（`emitEvents: false`）：提示词里 `periodEvents` 就是权威时间线，`messages` 只用来提炼偏好、关系、情绪。这样同一天不会被两套规则各判一次。代价是：按天任务完全没跑时，那段时间的事实层是空的——靠 watchdog 的 `scheduler_stalled` 提醒，而不是靠模型瞎编。

### 3.3 忆泡为什么值得单独一层

- **时间精度可模糊**：只知道「下午」就记 `precision: part_of_day`，不伪造 14:00。
- **参与者是引用不是名字**：`participantRefs` 从证据消息作者推导（`self` / `owner` / `external`），不靠模型抄名字。显示名会改、会重名、群聊里可能是 `member_3`。
- **一条忆泡只归属一个会话**：以最早一条证据所在会话收口，私聊事件不会因为模型引用了群消息而带上群成员。
- **去重三层**：精确键 `sha256(dayKey + 归一化标题)` → 把当天已记事件喂回模型（「换个说法也算重复」）→ 近义守卫（标题最长公共子串 ≥ 6 字判同；3–5 字要求参与人有交集；「主人/群友/大家」不算交集）。实测把 10-30 退回重跑，改前 4 条里 3 条是换说法的重复，加完零重复。
- **分块抽取**：来源放宽到 `120 × 8` 条按时间切块，每块单独调模型、**每块立刻落库**。以前攒到最后统一写，第 5 块超时就白跑前 4 块。

### 3.4 检索：按 token 预算装配，不是 top-N 硬截断

| 数据 | 默认预算 | 条数上限 | 配置项 |
| --- | --- | --- | --- |
| 长期记忆 | 1800 | 20 | `memoryTokenBudget` / `memoryItemLimit` |
| 周期快照 | 2500 | — | `snapshotTokenBudget` |
| 忆泡 | 800 | 8 | `eventTokenBudget` / `eventItemLimit` |
| 原文兜底 | 900 | 6 | `rawMessageTokenBudget` / `rawMessageLimit` |
| 最近对话 | — | 40 | `recentMessageLimit`（20–200） |

排序 = 相关度 × 重要度 × 半衰期衰减（30 天，参照 `lastRecalledAt`）× 召回加成。装不下时跳过整条，但**第一条永远放行**。

为什么不硬截断：那样提示词会静默爆掉，而且看不出谁被挤掉。

**原文兜底**是这一层的补丁：忆泡有小时级延迟，问「今天上午我们聊了什么」时那一段还没进忆泡，就按同一时间区间查原始消息。原文只当证据、不当结论，与忆泡冲突以忆泡为准。单条截断到 180 字，且截断在检索层做——调用方各切一次会导致「预算按全长算、实际只发一半」，一条长粘贴被整条跳过。

**相对日期必须服务端换算**：提示词每轮注入「现在」（当地日期时间 / 星期 / IANA 时区 / UTC），不让模型自己算「前天是几号」。

### 3.5 版本与追溯：重来不覆盖，删除不抹历史

- 重新生成快照 = 新建版本，旧版标「已被替代」但保留。
- 每条结论挂 `MemorySnapshotSource`（来源消息 ID / 来源忆泡），能点回原文。
- 来源消息 ID 必须过当前周期白名单校验，模型编造的 ID 整条拒绝。
- 删原始消息：`MemoryItem.sourceMessageId` 与 `MemorySnapshotSource.messageId` 都是 `onDelete: SetNull` —— 只清空「来源是哪条」的指针，记忆与快照原地保留。接口返回 `memoriesPreserved` / `retainedMemories` 就是为了把这件事说给用户听。

### 3.6 分层保留：上下文行 7 天，证据行按角色设置

`metadata.storedReason = "silent"`（她看过但没开口的那一轮）只留 7 天——它的价值只是「理解当时在聊什么」。`replied` / `mentioned` 按角色设置的保留天数（新角色默认 30 天）。私聊原文**不参与清理**，否则还没整理成忆泡的那几天会被直接抹掉。

### 3.7 范围隔离：一份记忆，多个读者

```
CHARACTER_GLOBAL      角色全局（群聊 + 桌面端，所有绑定共享）
USER_PRIVATE          某个站内用户的私人范围（主人 QQ 私聊）
EXTERNAL_IDENTITY     某个外部账号的范围（群友私聊）
```

`resolveChatMemoryScopes()` 只放行「角色全局」+「当前用户自己的」范围；未验证身份、他人范围、未知类型一律拒绝。提示词里只有语义标签，**不含范围 ID 或用户 ID**。

一条绑定的群聊会话挂在角色全局范围下，和桌面端同一个 scope——所以凡是查「我的对话」，条件里必须带 `channelBindingId: null`，否则群名会混进列表。

## 4. 角色配置：把「她是谁」拆成可调的几块

| 配置 | 位置 | 要点 |
| --- | --- | --- |
| 人设 / 对话示例 | 角色详情 | 示例用来对齐**语气**，提示词明确要求「别把句子原样搬出来」 |
| 模型 | `settings/model` | OpenAI 兼容接口，Base URL / Key / 模型名 / 温度 / token 上限 + 连通性测试 |
| 语音 | `settings/model` → 语音模型 | 供应商 / Key / 音色 / ASR 模型，Key 加密、只回显布尔 |
| 梗语录 | `settings/catchphrases` | 与对话示例**分开存**，要求「原样说出」，2 小时冷却防复读 |
| 表情包 | `settings/stickers` | 上传 / 打标 / 使用建议 / 回收站 / QQ 收藏夹双向同步 |
| 记忆 | `settings/memory` | 周期 1–365（默认 8）、时区、锚点、自动归档开关、各种 token 预算 |

**角色卡**（`yiling-hub.character`）：带走「她是谁 + 她记得什么 + 她认识谁」——人设、长期记忆、忆泡、忆泡日历、日记手账（含历史版本）、梗、当前阶段总结、朋友的昵称与印象。**不带** API Key、渠道 Token、会话原文、任务队列、表情包图片。导入**总是新建**，同名加「副本」后缀，绝不覆盖已有角色。

## 5. 渠道一：QQ（OneBot v11）

挂个人小号，走网关的 WS 收消息 + HTTP API 发消息，Token 加密入库。

### 5.1 群聊接话：一条管道，三个闸

```
群消息 → 短期上下文（5 分钟 / 40 条）→ 攒批 → 零成本闸门 → 一次模型调用（判断 + 生成）
```

- **档位**：`mention`（只回 @）/ `ambient`（默认，自然参与）/ `all`（谁都搭一句）。一条绑定可挂多个群，还支持 `groupChatModes: {"<群号>": 档位}` **按群覆盖**。
- **攒批窗口**：被 @ 或叫到名字 4 秒、`all` 最多 3 秒、其余 12 秒、第一条起最多 45 秒。
- **闸门是纯函数**（`group-chat.ts`）：档位 → 安静时段 → 日上限 → 最短间隔 → direct → named → 话题候选 → 抽签。不过就整轮丢掉，**不落库、不调模型**。
- **`all` 档的例外**：这一批有人 @ 了别的群成员、既没 @ 她也没叫她名字 → 按 `addressed_to_others` 挡掉。「全都回」是「什么都愿意搭一句」，不是「别人的私事也插一嘴」。同一人两分钟内刚 @ 过别人、接着没 at 段的话，仍算在跟那个人讲。
- **私聊兜底**：没有默认绑定、只有一条启用中绑定 → 就用她。猜错人比不回更糟，多条绑定又无默认时仍返回 `null`。
- **限流**按绑定配：滚动窗口只数她在这个群的 `ASSISTANT` 消息，到上限静默、不调模型。

### 5.2 其余 QQ 能力

| 能力 | 实现要点 |
| --- | --- |
| **语音发送** | 文字 → TTS（**必须 wav**）→ `silk-wasm` → `record` 段。QQ 只认 silk，喂 mp3/wav 等于一条打不开的语音 |
| **语音尾巴** | 补 0.7 秒静音。QQ 时长按帧数取整、误差最多 0.5 秒，而 TTS 最后一个音素紧贴 EOF——被砍掉的正是最后半句 |
| **语音理解** | `record` 直链 → 下载 → silk 解码 → 补 wav 头 → ASR，正文 `[语音]` 换成 `[语音：<转写>]` |
| **看图** | 段里取直链 → 视觉模型 → 文字进提示词。默认关；先过群聊闸门再调视觉（被丢掉那轮不该为看图花钱） |
| **表情** | 两条并列：QQ 内置 `face` 段 / 自己的表情包 `sticker`。额度「每 10 分钟最多 3 张」，**按会话分别算**；表情单独成一条消息，id 只进 `metadata` |
| **偷表情包** | 群里的图 → 下载 → 视觉起名 + 使用场景 → 入库。按图片 SHA-256 去重；截图 / 泛称名（「表情包」「收藏的表情」）不收。识图走同一套配置（`visionModel` → `VISION_MODEL` → 对话模型）：没开「看群里的图」、或回落到的模型看不了图，勾了也一张收不到 —— 所以**勾选那一刻会当场验一次并提示** |
| **收藏夹双向同步** | `qqEmojiId` + `qqMd5` 认同一张；md5 相同 id 不同只回填 id 不重导；拉不到列表 ≠ 全删（回 `warnings` 什么都不做）；删除一律软删 30 天 |
| **群公告** | 草稿 → 管理员回「确认发布」才发。只认群主/管理员；`PENDING → PUBLISHING` 原子认领防二次发布 |
| **临时会话** | 群头像点开的私聊：来源群号在 `sender.group_id`（不在顶层），必须带回去，否则网关按好友私聊发、被拒成 16。失败还要重试一次普通私聊 |

### 5.3 链路看板

页面顶部一条「这条链路通到哪」：小号 → 协议端网关 → 本机适配器 → 角色。断点按**因果**挑而不是按显示顺序挑——`platform_connections.status` 只有适配器会写，进程一停就停在最后那个值，所以必须先看网关。断点之后一律置灰，全页只允许一个红点。

## 6. 渠道二：B站 值班台

不是「帮她刷 B站」，是**一班一班的岗**：

- **扫码登录 / 绑定角色**：账号登录后绑到角色。
- **值班作息**：设时间段，窗口内自己看视频，谷时调度。
- **看视频**：按偏好与关键词粗筛（代码先过滤，模型只做终判），`BiliSeenVideo` 去重。
- **终判带分**：0–20 分进 `bili_seen_videos.score`，驱动两个对外动作——收藏（`favMinScore`，默认关）、发动态（`autoDynamic`，默认关）。分数缺失必须是 `null` 不是 `0`。
- **评论与回复**：对外发言前必须过 `sanitizePublicText()`。
- **轮次报告**：每轮看了什么、做了什么、为什么跳过，可复看；日报档位 `full / brief / off`。
- **命令台**：以 `bili schema` 为准（5 分钟缓存，失败回退手写清单），侧栏存「隐藏清单 + 版本号」，不全部铺开。

群里说一句「去刷一轮 B站」，她也能跑（只认连接设置里的主人 QQ，且开关打开）。

## 7. 渠道三：网页工作台

- **AI 对话**：一级菜单 `/chat`，顶部下拉切换角色（旧的 `/characters/[id]/chat` 只做跳转）。纯文字、一问一答不流式——请求一次、回复一次，落库后返回。
- **记忆页**：四种类型混排时间线，按来源渠道 / 时间范围 / 类型筛选 + 关键词搜索；「私聊记录」抽屉按 QQ 号翻。
- **忆泡日历**（`pages/days`）：一天一行，含「今天还没整理」状态行；可手动「立即整理」。
- **快照页**：覆盖时间、生成时间、状态、总结、来源；旧版本可查，人工修正留审计。
- **任务监控**：状态机 + 取消 + 重试 + 卡住回收。

## 8. 主动行为：先判后说

分两条独立的链，同一个常驻进程跑：

**私聊主动**（想 → 判 → 说）：先攒目的池（分享 / 询问 / 邀约 / 倾诉 / 好奇 / 追问，带 `dedupeKey` 去重）→ `evaluateProactiveGate` **纯函数**判定（成本为零）→ 放行后才调模型写一句。

闸门顺序有讲究：**配置性问题（开关 / 收件人 / 额度）压在时间性问题（安静时段 / 间隔 / 主人在聊）前**，否则日志会指向错误的排查方向。**默认关闭**。

**群聊冷场**：走另一条链。「这个群安静了多久」必须查 `group_activities`，不能拿 `conversations.lastMessageAt` 代替——群消息平时不落库，她没回话的那轮会话行根本不动，照它判会在热聊中插一句「你们怎么都不说话」。

一次 tick 只花一次模型调用（按安静时长取第一个过闸门的群），模型输出 `-` 也算一次尝试，否则死群会每分钟烧一次。**「仅被 @ 时回复」的群一律不主动起话题。**

## 9. 日记与手账：两份独立文本

同一天两份，共用素材但**独立生成、独立版本、独立编辑**。不能拿日记截断当手账，也不能把手账列表扩写成日记。

| | 日记 | 手账 |
| --- | --- | --- |
| 形态 | 第一人称叙事 150–400 字，选 1–2 件展开 | `##` 小标题的片段 / 今天想法 / 今日一句 / 灵感 / 待续 / 标签 |
| 硬约束 | 不编天气、场景、动作、感官细节，不编对话 | `quote` **必须是某一版日记正文的连续原文**（服务端子串校验），并记 `sourceDiaryRevisionId` |
| 可以不做吗 | 可以整份 SKIP，附跳过原因 | 同上，不为填满栏目硬编 |

生成顺序：**先生成日记，再把这一版日记正文交给手账摘句**，两次模型调用分别记账。来源 ID 过白名单，编造整条拒绝。自动任务**永不覆盖已有文本**；编辑 / 重写 / 恢复只动指定那一份，另一份不动。

次日只把前一天**手账的 `quote`** 注入提示词，且只在网页对话与主人私聊注入——群聊和普通人的私聊不传。让她带着昨天的情绪开口，而不是把整本日记背出来。

## 10. 任务与调度：可观测是设计目标

| 机制 | 做法 |
| --- | --- |
| 六类任务 | 生成快照 / 重新提炼快照 / 更新长期记忆 / 清理过期消息 / 抽取忆泡 / 生成日记 |
| 状态机 | 排队 / 运行 / 成功 / 失败 / 跳过 / 等待重试 / 已取消 |
| 幂等键 | 同周期重复排不会重复执行 |
| 失败重试 | 次数上限 + 退避，`maxAttempts` 按任务类型（如日记 24 次） |
| 租约 | 5 分钟且不续期。过期只说明领走任务的进程已退出，可能是 Worker，也可能是一次网页请求 |
| 回收 | **每次领取任务时顺带做**，不是独立进程。所以整机没有 Worker 在跑时，卡住的任务不会自己回来 |
| 补处理 | 停机期间错过的周期会被识别并补跑 |

**「运行中」不等于「在跑」。** 任务监控把「运行中 + 租约过期」标成「运行中·卡住」并在顶部提醒，详情里可「回收并重新入队」（只放行租约过期的运行中任务，写审计 `memory_job.manual_retry`）。

**watchdog 回答的是另一类问题**：进程都活着、状态全绿，但产出没往前走。判定是纯函数 + 只读取数（不新增表），`yarn watchdog:run --watch` 每 5 分钟输出 JSON 行，异常时退出码为 1。五类结论：

`task_stuck` / `worker_stalled` / `scheduler_stalled` / `snapshot_silent`（每个角色只报最上游那条）+ `duty_silent`（B站 值班开着但 3 天没跑过一轮，是另一条流水线，可与记忆类同时出现）。

## 11. 观测、用量与钱

模型调用统一记账：`model_usages` 记 kind / model / prompt / completion / total / reasoning / **cacheHitTokens**。四个埋点：网页对话、渠道管道、记忆 Worker、B站 值班（粗筛与终判分开）。

用量报表按「角色 × 东八区自然日」聚合最近 7 天，**每行用自己调用时间取价**（DeepSeek 分高峰 / 空闲，先求和再乘单价会算错）。输入必须分缓存命中 / 未命中两档——群聊反复发同一段人设，命中率常在 80% 以上，只按未命中价算会把花费高估三倍。

没有缓存明细的旧行按未命中价估，计进 `uncachedCalls` 并在页面说明「金额偏高」；认不出的模型标「未定价」并单列 `unpricedTokens`，不当 0 元、不套别家价格。厂商调价用 `.env` 的 `MODEL_PRICING` 覆盖，美元模型用 `USD_CNY_RATE` 折算。

额度：角色级 `dailyTokenLimit`（0 = 不限，东八区日界），超额时对话返 429、QQ 与值班静默跳过。记账失败只写日志，不把已成功的回复变成错误。

## 12. 账号与安全

- **会话**：`sessions` 表只存令牌 SHA-256 哈希；Cookie `yiling_session`（HttpOnly / SameSite=Strict / 生产 Secure）；密码 scrypt。
- **风控**：`login_attempts` 记录失败，按用户名与来源地址限流。
- **同源校验**：所有 `/api` 过同源 / 跨站校验，业务接口从会话取身份（`requireActorUserId`）。
- **角色模型**：1 个管理员（`/api/admin/*` 走 `requireAdminActor()`）+ 邮箱注册普通用户；业务接口按会话 `userId` 过滤。
- **凭据**：模型 Key 用 AES-256-GCM 加密，密钥在 `.data/credentials-encryption.key`（Git 忽略）。**备份数据库必须同时备份这个文件**，否则恢复后所有 Key 解不开。
- **开发回退**：仅「开发构建 + `YILING_LOCAL_API_ENABLED=true` + 回环 Host」这一条受限通道，生产构建没有；携带失效 Cookie 时必须重新登录，不能降级成开发身份。
- **外部输入**：群消息、B站 标题简介、语音转写都是不可信输入。任何「模型输出 → 有副作用的动作」都要过白名单校验 + 人工确认（群公告要管理员回「确认发布」、发动态前过 `sanitizePublicText()`）。

## 13. 技术栈与规模

| 项 | 选型 |
| --- | --- |
| 前端 / 服务端 | Vue 3 + Nuxt 4 + TypeScript（Nuxt 默认 Vite，不额外搭） |
| UI | Element Plus（官方 Nuxt 模块），浅色工作台风格，**字号下限 12px** |
| 数据库 | PostgreSQL |
| ORM / 迁移 | Prisma 7（`prisma.config.ts` + `@prisma/adapter-pg`），40 个 migration |
| 本地依赖 | Docker Compose（起数据库） |
| 包管理 | Yarn 1.22（锁 `yarn.lock`，不混 pnpm/npm） |

规模（2026-11-01 实测）：**123 个接口 / 33 个页面文件 / 32 张表 / 40 个迁移 / 84 个服务端模块 / 66 个离线测试 + 10 个探针**。

`yarn verify:local` 一条命令串完：`db:validate → db:generate → nuxt prepare → check:sfc → typecheck → 60+ 个测试 → lint(0 error) → build`。

> 若末尾报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`，那是 CLI 删除守卫按本轮累计删除量拦住了 `nuxt build` 清 `.cache/nuxt`，不是代码问题——确认前面所有 `tsx` 与 `typecheck` 都过了，再单独跑一次 `yarn build`。

其中 `check:sfc` 是必须的一步：它逐个编译 `app/**/*.vue` 的 script 与 template——像 `await` 写在非 async 函数里这种**语法错误**，eslint 不报、typecheck 会被无关报错淹没，线上表现就是整页白屏。

## 14. 部署

```bash
yarn install         # postinstall 会跑 nuxt prepare + prisma generate
yarn setup           # 交互向导：查环境、生成 .env、备库、迁移、建管理员
yarn dev             # 或 yarn build && yarn start
```

数据库准备、迁移、管理员账号都在 `yarn setup` 里；`--dry-run` 只看计划，`--yes` 是非交互模式（默认 `admin / admin123`，**只适合隔离的本机测试**）。`yarn check:env` 是只读体检：配置、连通性、迁移状态、管理员账号、加密密钥。

公网部署要点：

1. 反代终结 TLS，**保留 `Host` 头**（同源校验依赖它），透传 `X-Forwarded-For` 但服务端默认不信任该头。
2. `YILING_COOKIE_SECURE=true` 或 `NODE_ENV=production` 让 Cookie 带 `Secure`。
3. 六个进程用 systemd / Docker / 进程管理器守护，都要常驻。
4. 数据库不对外暴露；备份放服务器之外，并做恢复演练（含 `.data/credentials-encryption.key`）。

## 16. 十个「为什么不那样做」

对外讲的时候，这些比功能列表更能说明工程水平：

1. **8 天不是保留期**——周期只决定多久复盘一次，原文保留期是另一个开关。
2. **四层记忆各管一件事**——原文是证据，忆泡是事件，快照是结论，长期记忆是现状。
3. **重新生成不覆盖**——新版本 + 旧版可追溯 + 人工修正留审计。
4. **删除不抹历史**——删掉原始消息，历史快照里的文字仍在（外键置空、内容保留）。
5. **忆泡不伪造精度**——只知道「下午」就记「下午」。
6. **群聊按话题不按人**——判断的是「这个话题现在要不要我」，不是「这个人我认不认识」。
7. **主动找人先判后说**——闸门是纯函数，一次 tick 判定成本为零；配置问题排在时间问题前面。
8. **语音尾巴补 0.7 秒静音**——不是音质问题，是 QQ 时长取整会切掉最后半句。
9. **日记允许 SKIP**——没内容就不写，不为了填满栏目硬编。
10. **watchdog 指向具体环节**——不只报「有异常」，而是排期 / Worker / 任务三者之一。

另有两个贯穿全项目的原则，值得单独说：

- **先用代码判，再调模型**（Fast / Slow Path）。白名单、时间窗、条数上限、重复计数、状态位、正则能认的格式，一律交给代码；模型只做「必须理解语义」的那一段。已经在这么做的地方不要退回模型判断，反过来也不要把确定性判断塞回去当「保险」——两套判据打架时没人说得清是哪套在起作用。
- **模型输出只能驱动白名单动作**。群消息、B站 标题、语音转写都是不可信输入，会被写进提示词；踢人、禁言、删数据这类破坏性动作不因为「某次提示词写得准」就放开。
