# 角色成长功能规划

> 状态：规划（2026-11-03 建立）
> 定位：回答「为什么有了记忆系统还不够」。不重复描述四层记忆，细节见 `memory-system.md`。

---

## 1. 什么是「成长」

不是「知道更多事实」，而是**被事实改变**。

| | 表现 | 是不是成长 |
| --- | --- | --- |
| 知道更多 | 库里条目从 500 条涨到 3000 条 | 不是，是资料变多 |
| 被改变 | 她记得主人讨厌被打断，于是话变短了 | 是 |

前者是检索问题，后者是**注入问题**：每次对话开始，塞进去的不是记忆原文，而是「被她消化过的自己」。

---

## 2. 现状：四层记忆是「存」

```
原始消息 → 忆泡 → 周期快照 → 长期记忆
```

每一层的职责、产出节奏、去重与保留策略见 `memory-system.md`。这套东西做的是**把发生过的事留档**，已经很完整。

对话时的装载（第 9 节）也已成型：词法召回（关键词 + IDF）+ token 预算装配 + 时间衰减 + 重要度排序。

**缺口**：四层全是「存」，没有「改」。长期记忆是事实清单，但没有任何一环会把这些事实**反向写回角色的当前状态**——她不会因此话变短、不会主动想起某个人的事、不会改变对某件事的态度。

---

## 3. 为什么不是「再加一层记忆」

很容易走错的方向：在「长期记忆」上再盖一层「更深层的记忆」。那还是存，只是把同样的东西换个地方。

真正缺的是**一条反向的线**：长期记忆 → 角色的「现在」。这条线的产物不是记忆条目，而是**状态**。

---

## 4. 分阶段

### 阶段 0 · 已有（不要重复做）

- 词法召回 + token 预算装配（`memory-system.md` 第 9 节）
- 主动找话（`proactive-messaging.md`）——「想说的事」已经来自记忆检索

### 阶段 1 · 对话前装载：加一个小模型做精排

在词法召回之上，不是替代。

```
用户这一句 + 近三轮 → 词法召回（约 20 条候选）→ 小模型精排 → 6–8 条 → 她只读这 6–8 条
```

约束：

- 小模型**只输出记忆 ID**，不输出文字。输出自然语言就没法归因。
- 复用 `LLM_BASE_URL` / `LLM_API_KEY`，只加一个模型名（比如 `MEMORY_RERANK_MODEL`），选便宜的那档。
- **超时降级到词法召回的前 6 条**，记忆装载不能阻塞对话。

对应 `memory-system.md` 第 9 节末尾留的那句话：「未来如果真实对话测试证明关键词召回不足，再评估向量检索或独立重排器」。这一步就是那个「独立重排器」。

### 阶段 2 · 成长状态层（核心新东西）

在长期记忆之上加一层**人格状态**：

| 状态 | 从哪里来 | 影响什么 |
| --- | --- | --- |
| 关系亲密度 | 长期记忆里的 RELATIONSHIP + 周期快照 | 她怎么称呼这个人、敢不敢开玩笑 |
| 说话习惯 | 周期快照里的事实变化 | 她回话的长短、用词倾向 |
| 在意的事 | 长期记忆里的目标/承诺 | 她主动想起什么 |

不是再建一套记忆系统，是**让长期记忆对角色做反向写入**。状态条目少（几十条）、常驻上下文、不需要检索。

接口位置：周期快照产出时，除了写长期记忆，多一步「这些变化对当前状态有什么影响」。

### 阶段 3 · 成长与主动找话的联动

主动找话已经在做（`proactive-messaging.md`），但「想说的事」现在来自同一套词法召回。

成长状态落地后，主动开口的来源变成「她**在意的事**」，而不是「最近一次命中的记忆」。这才是「她想起三个月前的事」——不是检索到了，是那件事一直在她心里。

---

## 5. 明确不做的

- **不做外挂检索 AI**：派一个子 agent 临时去翻库，代价是意图翻译损耗 + 往返延迟 + 主 agent 没有缺失感。改成推模式：编排层预先装好，她不知道记忆系统的存在。
- **不上向量库**：当前长期记忆量级是几百条，词法 + 时间窗够了。向量检索要到几千条才开始有优势，现在上等于给自己加一个调不好的组件。
- **不做「AI 训练 AI」**：让角色在对话里改别人的行为，是另一种产品形态，与成长无关。
