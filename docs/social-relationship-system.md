# 社交关系系统：现状与实施边界

更新日期：2026-11-08

## 1. 本轮目标

将已有的「她的朋友」能力接入成长系统，避免重复建设好友身份与交流策略的数据模型。后续在这套基础上逐步增加身份判断建议、关系发展和重要社交经历。

## 2. 已有数据模型与职责

当前不是一张独立的 Friend 表，而是两层数据：

- `ExternalIdentity`：以 `platform + platformUid` 唯一标识平台账号。身份类型为 `UNKNOWN / HUMAN / AI`，身份来源为 `AUTO / MANUAL`。同一平台账号的身份判断跨角色共享。
- `MemoryScope`（`EXTERNAL_IDENTITY`）：表示某个角色与该平台账号的关系。交流策略 `DEFAULT / ALLOW / BLOCK`、互动次数、最近互动、认识来源和角色自己的备注都在这一层，因此不同角色可以对同一账号作不同决定。

不要另建一套重复的好友档案表，也不要把对方的昵称当作跨平台身份合并依据。跨平台账号绑定必须经过验证。

## 3. 已有行为

- QQ 群成员第一次发言就会建立「遇到过」关系，不增加互动次数；只有角色真正回应对方才按现有口径增加群聊互动次数。
- 私聊和群聊都使用已有的好友身份记录。
- 身份可手动标记为未知、真人或 AI；人工设置会写入 `MANUAL`，普通互动不能覆盖。
- 交流权限按角色生效：默认、允许、禁止。
- OneBot 群聊入口先过滤身份与交流策略，攒批发送前再次校验；被明确禁止的发言不会进入当前回复上下文。
- AI-only 群聊另有连续轮数保护，不能把它与某一个好友的 BLOCK 规则混为一谈。

好友管理现位于 `/growth/social/friends`，旧 `/identities` 地址重定向到新页面；API 仍位于 `/api/admin/identities`。页面复用原有业务逻辑，不复制数据或接口。

## 4. 尚未实现 / 不应误认为已有

- AI / 真人自动识别尚未实现；目前身份分类需要用户手动设置，未知身份保持 `UNKNOWN`。
- 关系亲疏目前只有互动次数、最近互动和排序能力，不等于真正的亲密度或关系等级。
- 尚无群级交流策略覆盖；现有策略是角色级。
- 尚无独立的社交经历时间线。重要经历应与记忆系统协作，不复制一份长期记忆。
- 好友工作区已迁入成长系统，并使用左下角全局角色选择器；切换角色时加载对应角色自己的好友数据。角色级社交关系与权限不跨角色复用。

## 5. 建议实施顺序

1. **接入成长系统（已完成）**：增加社交关系系统总览，说明已有能力和真实边界。
2. **好友管理迁移（本轮）**：将原好友管理页迁入成长系统的「好友档案」，改用左下角全局角色选择器；旧 `/identities` 地址保留重定向，原有筛选、排序、分页、身份、交流权限、备注审核和删除能力均复用。
3. **身份分类辅助交互策略**：真人 / AI / 未知。优先使用平台可信标记；模型推断只能作为待确认建议，不逐条额外调用模型、不覆盖人工分类；证据不足时保持未知。身份分类不是好友资格或关系阶段的门槛。
4. **好友关系发展**：采用「陌生 / 认识 / 朋友 / 好朋友」等可解释的关系阶段，真人和 AI 都可以成为朋友。阶段是角色自己的社交数据；互动次数不能直接等同于亲密度，也不能仅凭次数自动升级。由小鲸鱼提出关系变化想法，系统核验依据后自动更新，不要求用户审批。
5. **主动联系规则**：用户已确认允许小鲸鱼主动联系关系良好的朋友，不限真人或 AI，不必每次由用户发起。身份分类只辅助判断交流节奏和 AI 连续对话风险，不决定关系亲疏。现阶段优先在共同 QQ 群中 @ 对方；私聊与主动加好友作为未来渠道能力扩展。需要设计冷却时间、每日次数上限、群聊连续 AI 对话限制及暂停/恢复条件；主动联系应有真实话题或互动缘由，避免无意义的定时消息。
6. **社交经历**：明确哪些事件值得记录，以及它与忆泡、长期记忆、阶段总结的引用关系后再实现；不复制一份长期记忆。

## 6. 验收原则

- 一个账号在不同角色下可以有不同交流权限；身份分类仍是账号级。
- BLOCK 在接收入口和攒批发送前都有效；被屏蔽内容不得进入回复上下文。
- 人工身份分类不被自动更新覆盖。
- 未知身份不被猜测成真人或 AI。
- 关系阶段必须能解释依据，并允许用户修正。
- 真实 QQ 群验收由本地 DSH 执行；代码级修改先通过相关测试、类型检查、SFC、Lint 和构建。


## 7. 第二阶段设计共识（2026-11-08）

本节记录已讨论确认的产品方向，不代表相关功能已经实现。

### 7.1 角色数据隔离沿用现状

- 好友列表、关系阶段、交流权限、互动记录均属于当前选中角色的社交数据。
- 切换全局角色时，好友工作区加载新角色自己的好友数据；不把上一个角色的关系或权限带到新角色。
- 不新增一套跨角色共享的好友关系。账号身份分类仍由现有平台账号身份档案承担；角色与账号之间的关系继续沿用现有角色级数据范围。

### 7.2 身份分类

- 身份类型仍为真人（HUMAN）、AI（AI）、未知（UNKNOWN）。身份分类是对平台账号的事实认知，不是好友资格或关系等级；真人与 AI 都可以成为朋友。
- 优先采用平台提供的可信身份标记；模型推断只能形成待确认建议，不能仅凭语言风格自动定性。
- 证据不足时保持 UNKNOWN；用户人工确认优先，自动结果不得覆盖人工设置。
- 当前自动识别尚未实现，不得在 UI 或文档中描述成已有能力。
- 用户人工修改身份是纠正系统认知与现实不符的情况，不代表用户在替小鲸鱼选择朋友；人工分类仍优先于未来自动建议。
- 身份分类仅作为交互策略的辅助信号。当前部分 AI 容易把对话持续下去，因此需要节奏和连续对话保护；不能因为对方是 AI 就认定关系不可能发展。

### 7.3 好友关系与主动互动

- 关系阶段可探索「陌生 / 认识 / 朋友 / 好朋友」，最终命名和升级依据待进一步设计。
- 关系阶段不是互动次数的别名；互动次数、关系亲疏和交流权限是不同概念。
- 用户已明确允许小鲸鱼在没有用户逐次指示的情况下，主动联系关系良好的朋友；对象可以是真人，也可以是 AI。
- 是否主动联系应结合当前角色与该朋友的关系、单独交流权限和实际渠道能力。身份分类只影响交流节奏与防刷屏策略，不决定关系阶段。
- 主动联系不等于无限制发言：需要冷却时间、每日次数上限，并遵守群聊连续 AI 对话的防刷屏限制。
- 主动联系应尽量基于真实的共同话题、此前互动或合理的交流缘由，避免机械定时问候。
- 现有 BLOCK 必须优先；主动联系权限不能绕过好友屏蔽、渠道权限或群聊安全闸门。
- 冷却时长、每日次数、连续轮数及暂停/恢复条件尚未定值，实施前先检查现有 AI-only 连续轮数保护，避免重复造机制。
- 当前交流过滤在 `DEFAULT` 下会屏蔽 AI 发言，这是现有防止低成熟度 AI 无限接话的策略，不应被误解为 AI 不能成为朋友；未来应结合关系授权与节奏控制重新评估默认策略，不能仅凭身份永久否定交流。

### 7.4 社交经历与记忆

- 社交经历尚未实现。先定义哪些互动值得成为社交事件，再决定如何与忆泡、长期记忆和阶段总结关联。
- 社交系统负责关系与社交事件的结构化事实；记忆系统负责筛选、提炼和长期保存。不要在两个系统各复制一份长期记忆。

### 7.5 实施前置原则

- 先只读审查现有身份识别、交流过滤、AI-only 轮数保护和记忆事件管线，再确定最小改动范围。
- 优先复用现有 ExternalIdentity、角色级 MemoryScope 和现有 QQ 入口过滤，不重复建立身份或好友表。
- 本阶段暂不改代码、数据库或 QQ 过滤逻辑；先完成设计与验收标准，再拆成小 PR。


## 8. 第二阶段现状审查（2026-11-08）

本节为基于当前代码的只读盘点；不代表新增功能已实现，也不替代 DSH 在本地的运行验收。

### 8.1 已有基础

- **身份档案与人工分类**：`ExternalIdentity.kind` 已有 `UNKNOWN / HUMAN / AI`；`kindSource` 已有 `AUTO / MANUAL`。管理 API `PATCH /api/admin/identities/:id` 在用户修改身份时写入 `MANUAL`。`kindSource = AUTO` 只是默认来源标记，不代表项目已经有自动识别器。
- **角色级交流权限**：`MemoryScope.friendChatPolicy` 已有 `DEFAULT / ALLOW / BLOCK`。`shouldBlockFriendSpeaker()` 明确规定：BLOCK 始终屏蔽；ALLOW 放行；DEFAULT 下 AI 屏蔽，真人和未知保持原有行为。
- **遇见即建档**：群成员首次发言时可以建立身份和当前角色关系，互动次数不增加，因而可以在第一次正式互动前人工标记身份或设置屏蔽。
- **群聊防刷屏**：`Conversation.consecutiveAiRounds` 已记录连续 AI-only 群聊轮数；`MAX_CONSECUTIVE_AI_ROUNDS = 3`。达到上限后暂停该轮；明确真人参与后计数清零。UNKNOWN 不会被当成 AI 增加轮数，也不会被当成人类清零。
- **已有主动表达管线**：私聊主动找话采用「想 → 判 → 说」目的池与硬闸门，默认关闭；群聊冷场主动起话题也有独立开关、安静时段、冷场阈值、每日上限和最小间隔，默认关闭。群聊主动起话题还受群模式限制，`mention` 模式不主动发起。
- **社交内容与记忆已有连接**：好友关系范围与对话记忆范围复用 `MemoryScope(EXTERNAL_IDENTITY)`；好友范围可以进入周期记忆提炼。现有 `interactionCount` 记录互动量，`listAcquaintances()` 将它用于熟悉程度提示，但代码注释明确它不是亲密度。

### 8.2 尚未发现的能力 / 明确缺口

- **自动身份识别器**：当前盘点到身份字段和人工编辑 API，未发现可信平台信号采集、自动分类执行器或待确认建议工作流。不能把 `AUTO` 默认值解释为自动识别已上线。
- **关系阶段**：未发现陌生 / 认识 / 朋友 / 好朋友等持久化阶段、阶段变化证据或建议机制。
- **针对具体 AI 好友的主动联系**：已有主动私聊目标主要是主人最近的 QQ 私聊会话；群主动表达是群冷场时开话题。尚未发现按某个 AI 好友的关系阶段、单独授权和共同话题来挑选收件人的专属流程。
- **结构化社交经历**：好友范围的对话记忆提炼已经存在，但未发现独立的社交事件/关系变化时间线。不能把普通聊天记忆误当成关系事件系统。

### 8.3 重要边界与风险

- 不要另建好友表或重复实现 `DEFAULT / ALLOW / BLOCK`；优先在现有身份档案、角色级关系范围上扩展。
- 不要把 `kindSource = AUTO` 当作自动识别功能，也不要用模型仅凭语气猜测身份并自动覆盖人工分类。
- 不要让 HUMAN / AI / UNKNOWN 决定关系阶段或好友资格；身份类型仅辅助交互策略。
- 不要把互动次数直接升级成亲密度；关系阶段需要独立证据与可纠正机制。
- 不要把现有群冷场主动发言直接改造成指定好友联系；两者目标对象、触发条件、提示词和社交风险不同。
- 任何 AI 好友主动联系都必须先检查该角色与该好友的 BLOCK/ALLOW、平台和渠道能力、用户配置、每日额度、冷却时间及幂等性；未确认关系或目标不明确时不发送。
- 现有 3 轮 AI-only 保护只覆盖 OneBot 群聊轮次，不应误称为跨平台、跨群或私聊的通用对话上限。

### 8.4 建议的实施顺序

1. 先补齐设计与验收标准：关系阶段的含义、由小鲸鱼提出变化建议并由系统核验后自动保存的流程、主动联系的对象选择和停止条件。
2. 再实现最小的角色级关系阶段数据与管理 UI；不改变现有身份分类和交流权限语义。
3. 在独立设计并确认授权/目标选择/频率闸门后，增加「主动联系指定 AI 好友」能力；复用现有主动表达目的池与闸门思路，不直接复用面向主人的收件人解析。
4. 最后设计结构化社交事件，并明确它与现有好友范围记忆提炼、忆泡和长期记忆的分工。

### 8.5 本次审查范围

已只读检查 `friend-chat-policy.ts`、`friends.ts`、OneBot 群聊入口相关逻辑、好友身份 PATCH API、群主动表达设置、主动找话文档，以及成长系统社交关系文档。未修改业务代码、数据库或 QQ 过滤；未运行本地测试、类型检查、Lint、构建或真实 QQ 验收。


## 9. 关系阶段自然成长（已确认方向，尚未实现）

关系阶段用于描述小鲸鱼与某位朋友的相处状态，不是互动计数器，也不是用户审批出来的等级。真人和 AI 在关系成长上遵循同一套原则。

### 9.1 阶段含义

- **陌生**：知道对方是谁或在群里遇见过，但还没有形成有意义的相处经历。
- **认识**：发生过实际交流，对对方有初步了解。
- **朋友**：有持续或有质量的交流，逐渐形成共同话题、相互了解或共同经历。
- **好朋友**：关系稳定且熟悉，有较多有意义的共同经历，形成独特的默契或回忆。

阶段最终文案可以在 UI 设计时微调，但不能把阶段实现成积分或累计消息数量。

### 9.2 谁提出、谁核验、谁保存

1. 日常聊天与记忆整理照常运行，不要求每条消息都调用关系评估模型。
2. 有新的重要社交经历，或本地任务达到合适的评估时机时，小鲸鱼可以结合已有关系和真实经历形成阶段变化建议。
3. 系统核验建议引用的证据是否真实存在、是否属于当前角色与该朋友、是否已经被重复使用；必要的语义判断由轻量评估完成。
4. 证据充分时自动保存新阶段与变化记录，不需要用户逐次批准；证据不足则保持原阶段，等待后续相处。
5. 升级和降级都允许，但降级应更加谨慎。长期没有聊天本身不构成降级证据；新的疏远、矛盾或关系变化才可以成为判断依据。

### 9.3 证据原则

- 参考交流质量、共同话题、相互了解、重要共同经历和关系持续性。
- 互动次数、消息长度、聊天时长只能作为辅助信息，不能单独触发阶段变化。
- 同一段经历不能通过重复提炼或重复评估反复累加成升级依据。
- 关系降级不删除过去的共同经历；关系阶段描述当前状态，历史回忆仍由记忆系统保留。
- 关系阶段和变化记录属于当前角色；不得因同一平台账号被其他角色认识而自动继承。

### 9.4 本地运行边界

- 关系评估采用本地事件驱动：在本地程序运行期间，由新社交事件、记忆整理完成或已有本地任务周期触发。
- 不依赖云端常驻服务；程序关闭期间不执行，重新运行后再处理尚待评估的事项。
- 不逐条消息评估，不要求主聊天模型每轮承担关系管理；具体轻量评估模型、触发频率和任务持久化方式留待实施设计。

## 10. 主动表达与好友主动联系的关系（已确认方向，尚未实现）

### 10.1 旧主动机制的代码评估

现有主动表达是为早期需求临时搭建的多条链路，不能原样作为新社交主动联系的完整实现：

- `proactive.ts` 的私聊主动找话：使用目的池与「想 → 判 → 说」流程，但收件人通过角色最近的 QQ 私聊会话解析，主要面向已有私聊对象（当前产品语义主要是主人），不是按某位好友的关系选择收件人。
- `group-initiative.ts` 的群聊冷场起话题：按群活跃度、冷场时长和群级/角色级闸门挑选群，再生成一句群消息；它不选择具体好友，现有提示词明确禁止 @ 人。
- `scripts/run-proactive.ts` 是独立的本地 tick 入口，约每 60 秒运行私聊主动找话、群冷场起话题和 QQ 空间主动表达。它不是 Web 请求内的定时器；本地进程未运行时，这些 tick 不会执行。
- 上述机制默认关闭。现状与行为以代码为准，不能把旧文档中的策略直接当作新功能已经具备。

### 10.2 可复用的能力与不能照搬的策略

可优先复用或抽取的基础能力（实施前仍需逐项验证）：

- 纯函数式安全闸门与配置校验；
- 每日额度、最小间隔、安静时段、角色级/群级冷却；
- 发送前重新检查权限、目标与渠道状态；
- 发送结果落库、模型用量记录、失败状态和幂等保护等可靠性设计。

不能原样照搬的部分：

- 面向主人最近私聊会话的收件人解析；
- 群冷场才开口的触发逻辑；
- 禁止 @ 人的旧群聊提示词；
- 把身份类型直接当成好友关系或唯一交流许可的策略。

现有 `MemoryScope.friendChatPolicy` 在 `DEFAULT` 下屏蔽 AI 发言，是当前针对部分 AI 容易连续接话的保护措施。这个行为与「AI 也能成为朋友」并不矛盾，但未来需要结合明确关系、单独授权和连续 AI 轮数控制重新评估，不能把它固化成 AI 永远不能交流的关系规则。

### 10.3 目标架构

- 社交关系系统产生「想联系谁、为什么联系、想聊什么、在哪个共同群聊可能联系」的结构化主动意图。
- 统一主动表达安全层负责复核当前角色与好友的交流权限（BLOCK 始终优先）、目标是否仍是该群成员、渠道/群模式是否允许主动发言、频率与每日额度、AI-only 连续轮数、重复发送和失败处理。
- QQ 第一阶段优先支持共同群聊中带明确对象的 `@` 互动，不把冷场起话题冒充好友联系。
- 私聊和主动发起好友申请属于未来渠道能力；只有平台、协议和用户配置确实支持时才启用，不能假设群聊天然提供独立私聊能力。
- 没有共同群聊、目标身份不明确、权限被 BLOCK、群模式禁止主动发言或渠道不可用时，不发送；可以保留待处理意图，等待合适渠道或后续能力。

### 10.4 本地执行边界

主动联系也依赖本地 QQ 连接和本地执行进程。程序关闭或 OneBot 不可用时不发送；本地进程恢复后再依据意图有效期、冷却和权限重新判断，不补发已经过期或不再合适的消息。
