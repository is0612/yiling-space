# 主人 QQ 私聊的群历史核查

状态：已实现有界检索与短期追问连续性；不等于每轮加载全部聊天。

## 接入与权限

`channel-adapter/pipeline.ts` 在现有 `loadMemoryCandidates` 中接入主人专用历史任务。资格由服务端 `isOwnerTurn`、QQ 平台、当前绑定及主人私人范围共同决定，不能由模型的工具参数或 metadata 自行授予。

群证据的每一次查询（关键词、兜底、前后扩展、证据重载）都固定 `characterId`、QQ 绑定平台、`g:` 会话和绝对时间范围；指定群时额外固定群号。只查群消息，不查其他人的私聊。普通私聊与群聊维持现有授权和路径，不获得这项能力。

`cross-channel-context.ts` 的自动精简背景不变。原有按人物查询首次/最近互动的路径仍用于未进入本任务的时间线问题。

## 检索和回答

`owner-private-history.ts` 建立有界群历史计划；`owner-history-intent.ts` 在已有私聊 context 阶段内理解本轮是话题查询、边界核查、明确翻页、重试、普通确认还是结束任务。只在明确历史入口或未过期核查存在时增加这一次只读语义判断，与私聊知识分析共用一次 context 逻辑调用预算。模型只给白名单读取意图、检索问句和待核实的人名，角色、群、时间与权限始终由服务端约束。人物无法唯一识别时不扩成全群查询，话题查询没有词命中时不退回其他群或最新闲聊来假装找到相关证据。

沿用候选加载入口，匹配原文后，按同一会话分别查询目标发言者的前后 USER 消息与前后 ASSISTANT 消息。分方向、分角色取数，避免热群的旧闲聊挤掉命中后的回复。翻页最多扩展四个锚点，话题查询最多八个锚点；每方向 USER 十二条、ASSISTANT 八条；最终最多二十四条、约三千二百 token，单条最多三百六十字符。话题词由现有语义判断返回最多八个精确词，服务端保留有界长度和身份/群/时间过滤；不使用长问句开头的通用片段替代真正主题，也不修改其他记忆检索的停用词。

这些是相近时间内的**候选片段**，并不由代码认定每条 ASSISTANT 都是在回复目标人物。证据标注来源群、原始发言人、时间及覆盖不完整的边界，语义关系由最终回复模型判断。引用关系采用真实 `quotedMessage.messageId`，不能跨会话关联。

`memory-assistant.ts` 的 `requiredHistoryLookup` 在只读工具早退前执行候选加载；不需要主模型先输出 `memoryAssistantQuery`。已筛选的有界互动片段直接进入最终原文证据白名单，不再经过关键词 top-N 或另一个模型挑选而丢失回答。话题与翻页成功只进行一次最终生成，并关闭该轮重复只读工具调用；边界核查直接使用数据库 count/min/max 生成标明范围的本地回执，不调模型、不把统计伪装成原文。普通确认或表达纠正不查历史但保留未结束的任务，明确切换到其他查询则释放群历史计划并允许原有检索。普通任务的工具链不变。

无结果与查询异常分别返回「指定范围内没有足够记录」及「本次查询失败」，不生成“全部不存在”或“无法访问所有群”的解释。诊断分别记录 `success`、`no_sources`、`failed`，数据库核查不伪造成供应商模型调用。

## 短期连续性

当前主人私聊 `Conversation.metadata.ownerHistoryContext` 只保存检索条件、冻结后的绝对时间、锚定时刻和证据 ID，不复制历史原文。复用既有会话 metadata 的短期状态方式；原有群聊 `workingContext` 的同群限制不变。

有效期从**最近一次成功查询**起算二十分钟（首次提问同样算一次；单纯追问不刷新）。新话题、显式取消、换群或换人物会清除或重建适当条件；未指定新时间的追问沿用冻结范围，因此午夜之后不会把昨天晚间改查成今天。凌晨六点前“今晚”指向前一晚到本次提问时刻，范围解析使用角色时区。

适配器重载或状态过期后，形如「现在呢 / 还是呢 / 再看看 / 再试试」的整句短追问会按最近一次主人自己写过的群号重建一次今晚的历史任务，而不是凭旧回答断言读不到。群号必须能在最近两小时的主人发言里找到并校验为当前角色的 QQ 群会话；找不到就保持不查，不凭空猜群。这条恢复只在主人私聊生效。

状态 load/save 均校验当前角色、绑定、主人私聊会话和主人私人范围。保存独立比较加载时的 `ownerHistoryContext` 原值，读最新 metadata 后做整字段 CAS 合并；若后台摘要恰好抢先写入，最多重读合并一次，无关摘要不会导致历史任务静默丢失，也不会被覆盖。历史任务自身已更新时拒绝旧轮写入。证据每轮重新经过群权限与时间过滤，历史 ID 本身不是访问凭证，存储失败不让成功回复变失败。

活跃任务支持「群号 那边……」补充群目标，以及「更早、往前、之前」等方向追问。首次同时指定日期和更早时，按该范围的时间正序取早期证据；后续有游标时先在同一范围向前翻，范围内没有更早记录才扩展到前二十四小时，避免跳过已存在的同日记录。日期、游标、原问题冻结范围及证据 ID 保存在短期任务中。新的话题或人物追问切回原问题范围并清除翻页游标，不能继续拿旧页回答新问题；只有明确翻页才向前移动。指代群只从主人自己近期明确引用的群号恢复，并重新校验该群属于当前角色的 QQ 会话。

数据库额外返回 `ownerHistoryCoverage`：当前范围的真实记录数与首末时间、当前样本首末时间、是否被裁剪及是否确有更早记录。覆盖信息与本轮证据一同进入最终回复和调用诊断；提示词 v72 区分真实覆盖与样本起点，并要求服务端当前能力和新查询原文优先于旧记忆、经验或摘要里的故障自述；过去的临时故障不是永久读取权限。反馈处理区分事实纠正、用户观点及表达偏好，不从简单否定编造新的确定动机；正常告别不复读旧纠错。长期记忆、事件、接续摘要和反思提炼使用相同的时间与来源归因原则，反思提示版本为 v4。`hasEarlier=true` 时不得声称更早记录不存在、断开或无法访问。本轮主人专项结果替换自动原文样本，避免旧样本混入当前页。

## 回归与限制

运行 `yarn test:owner-private-history`：使用合成聊天与 mock 模型/查询，无真实模型或真实聊天访问。覆盖跨午夜范围、过期与话题切换、人物歧义、热聊中的问答和澄清、所有 SQL 的权限谓词、metadata CAS、工具路径实际先检索后生成、来源白名单、失败与无结果、普通人与群聊不进入主人分支，并回放成功查询→普通确认保留任务→边界统计→新人物话题→指代追问→表达纠正不再查群的完整序列。`yarn test:evidence-feedback` 验证当前证据优先、反馈归因和提炼请求的规则；这些 mock 测试验证请求结构与状态行为，不保证真实模型每次的语义表现。

边界：这不是不限量全群转播。取数和上下文预算可能截断长互动，无法从无结果证明一件事没发生；没有持久化引用的回复不能仅按相邻关系确认归属。此版本不增加普通私聊的共同群检索权限。
