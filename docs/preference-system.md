# 偏好系统

第一批实现：角色自己的喜欢、不喜欢和兴趣，由用户明确建立，或从选定公开经历提出候选，经人工确认后参与对话。

## 数据与来源

- `CharacterPreference` 保存当前主题、类型、原因、状态、版本和来源快照，按角色隔离。主人的喜好与其他人的喜好仍属于相应记忆，不自动变成角色偏好。
- 类型为 LIKE / DISLIKE / INTEREST；主题最多100字，原因最多1000字。
- `CharacterPreferenceRevision` 按每次操作的结果追加完整版本，包括 CREATE、EDIT、ACTIVATE、REJECT、DISABLE，并与 USER 审计同事务提交。无变化编辑不增加版本。
- 手工添加可明确选择立即生效或待确认。从来源添加只能进入 PENDING，最多5个来源：角色全局范围内 ACTIVE 忆泡，或当前角色 ACCEPTED 反思建议。私人范围、其他角色、隐藏和删除的忆泡不接受。
- 来源选择返回内容指纹；创建候选和首次确认时在事务内按角色→范围/反思任务→来源顺序锁定并重新校验。来源发生修改或失效返回409。
- 来源快照是当时依据，并非来源当前状态。已生效偏好独立保留，原来源删除不会连带删除偏好；停用后重新启用也保留人工确认的结果。尚未接受的候选不能越过失效来源生效。

## 页面与人工操作

入口为成长系统中的偏好系统。支持状态筛选、主题/原因搜索、分页、编辑、历史查看、候选确认/驳回、停用及重新启用。状态操作需要当前 revision，过期表单返回409；角色切换或关闭弹窗会使旧请求失效。

来源候选可自行填写判断，也可明确点击“根据所选来源提出建议”。该操作使用当前角色聊天模型及每日额度，最多读取5条来源摘要，不读取私人记忆或原始聊天；建议只填入可编辑草稿，不直接创建或生效。模型可返回证据不足；不得以另一个人的喜好推断角色喜好。模型调用在来源事务之外，返回后再次核对来源。调用最多60秒，用量记为 other，metadata.source 为 preference-suggestion，失败不透传供应商原文。

状态转换：

| 起点 | 操作 | 结果 |
| --- | --- | --- |
| PENDING | 确认 | ACTIVE，重新验证来源 |
| PENDING | 驳回 | REJECTED |
| ACTIVE | 停用 | DISABLED |
| DISABLED | 重新启用 | ACTIVE |
| 任意状态 | API 内容编辑 | 状态不变，版本递增 |

第一批没有永久删除偏好、自动周期抽取、自动接受、批量历史回填或关系/人设改写。

## 对话注入

桌面对话 API 与 QQ 渠道共用确定性的词项匹配，数据库只查询当前角色 ACTIVE 偏好。按主题/原因相关度排序，候选最多100条，最终最多6条，序列化字符预算600（作为保守 token 上界；首条也不得超预算）。没有匹配则不注入，不增加模型调用。当前是词法匹配，近义表达可能召回不足。

提示词区分角色本人的偏好与交谈者的偏好，要求只在相关时自然表现，不强行转移话题；相反偏好同时保留，不默选一方为事实。模型返回的 usedPreferenceIds 只能取本轮注入白名单，沉默轮清空。

桌面对话把实际使用的偏好版本快照写入 usedSources.preferences；渠道消息写入 usedPreferenceIds 与 usedPreferences。它们是模型自报并经白名单校验的引用，不代表已证明每条偏好都影响了语气或语义。提示词版本升级为 conversation-retrieval-v54。

## 验证

- `yarn test:preferences`：输入白名单、状态转换、预算、矛盾依据并存、建议解析、模型引用白名单与沉默轮。
- `yarn test:preferences-page`：脚本级页面竞态与草稿保护，不替代真实浏览器交互验证。
- `yarn test:preferences-isolated`：只允许本机一次性测试库，执行全部迁移，覆盖角色隔离、来源生命周期、版本审计、并发更新与分页，最后删除临时库。

迁移随版本提供；本次实现不直接修改业务数据库。部署或升级时按既有流程应用迁移。角色卡导入导出对新增偏好领域的携带尚未接入，备份数据库能保留偏好与历史。
