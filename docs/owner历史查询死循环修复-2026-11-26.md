# owner 私聊历史查询死循环修复（2026-11-26）

提交：`ea09201`（`fix(owner-history): 查空任务不再续命，回复摊开实际查询窗口`）

## 一、问题现象

owner 私聊对「鲸宁宁」说了一句当下陈述：

> 「你看群里的鱼小七现在就在弄自己的形象了」

之后私聊完全卡死——**无论再说什么，角色都只回同一句**：

> 「这次在指定范围内没找到足够的群聊记录，暂时不能确定；可以再给我一句原话或缩小范围。」

期间 owner 补了两次群号（「这个群 389834620」「389834620」），均无变化。

## 二、根因：三层叠加

1. **入口误判**：当下陈述被 owner-history 意图分类器（`server/utils/owner-history-intent.ts`，LLM 分类，temperature 0）误判成历史查询 `topic`。
2. **时间窗口错位**：任务窗口被定在 15:19–17:19，而「鱼小七」（openid `1962605653`，群内 233 条发言）最后一次发言是 11-24，窗口内零命中 → 查空。
3. **死循环**（本次修复核心）：`pipeline.ts` 保存逻辑里，**每轮查询完成（含查空）都会把 `anchoredAt` 刷新为当前时间**，20 分钟 TTL 被无限续命；同时任意短句都满足「跟进继承」条件（正则含「了/怎么/这/那」等万能字），任务永远不死、窗口永远钉死 → 每句话都查同一个空窗口 → 每句话都回同一句兜底文案。

## 三、数据止血（先恢复可用）

```sql
UPDATE conversations SET metadata = metadata - 'ownerHistoryContext'
WHERE "externalConversationId" = 'c:546280821';
```

只清 20 分钟 TTL 的临时任务状态，不动任何消息/记忆。清除后私聊即恢复正常。

## 四、代码改动明细（3 文件）

### 1. `server/utils/channel-adapter/pipeline.ts` —— 断死循环

保存 owner 历史任务处：查询结果为 `no_sources`（且 `localHistoryReceipt`，即确属本地历史查询路径）时，`nextPlan` 直接存 `null`，**查空即结束任务**，不再续命。

- `failed`（查询异常，暂时性故障）仍保留任务供重试——行为不变。
- `success` 照旧续命 + 更新游标——行为不变。

### 2. `server/utils/memory-assistant.ts` —— 查空文案摊开实际窗口

`unavailable("no_sources")` 默认分支，文案前后对比：

| | 文案 |
|---|---|
| 改前 | 「这次在指定范围内没找到足够的群聊记录，暂时不能确定；可以再给我一句原话或缩小范围。」 |
| 改后 | 「我查了 {开始} 到 {结束} 这段时间的群聊记录，没找到足够相关的；可以说得更具体些，或者换个时间范围（比如『查更早的』）再试。」 |

时间用 `formatLocalTimestamp(coverage.start/end, zone)` 按用户时区格式化（复用 boundary 分支现成模式）。设计意图：查空最常见原因是**窗口与发言时间错位**，把实际查的范围摊开，用户一眼能看出查错了时间段并直接纠正，而不是对着模糊的话反复补群号。

未动：`failed`、`unresolved_participant`（补昵称/账号）、`unresolved_group`（补群号）三条文案保持原样。

### 3. `scripts/test-owner-history-coverage-prompt.ts` —— 回归断言

在 boundary 查空用例后补三条：

- 回复必须含窗口日期（`/2026-11-17/`）
- 回复必须含新引导语（`/换个时间范围/`）
- 回复不得再含旧模糊措辞（`指定范围内没找到足够`）

## 六、遗留问题（回去继续的方向）

### 未修：「当下陈述 → 历史查询」的入口误判

本次只保证**误判之后不再卡死**（查空即结束 + 回复带窗口，用户可纠正），但误判本身仍可能发生一次。

曾尝试的方向：正则识别「现在/正在/就在…了」等现在时标记做确定性短路——**已被否决**。理由：同一句式换个语境意思不同（「鱼小七现在在弄形象」是陈述，「鱼小七现在在弄形象，你去看看她发了什么图」是指令），正则必误伤。相关改动已回退，未进入代码库。

可行方向（按推荐度排序）：

1. **收紧跟进继承与触发条件**：`planOwnerHistory` 的 `historyTask` 正则含「了/怎么/咋」等万能字，`followup` 条件含「他/她/这/那」等常见指代——几乎任何短句都会被吸进历史任务。把这些改成更强的历史意图词（「记录/历史/说过/聊过/上次/之前」），普通聊天自然不会被吸进去。**改动集中在 `owner-private-history.ts:59-119`，有现成测试 `test-owner-private-history.ts` 可扩展。**
2. **意图分类提示词加固**：在 `analyzeOwnerHistoryIntent` 的 systemPrompt 里显式补「描述现在正在发生的事（现在时/进行时）属于日常对话，不得发起历史查询」。改动小，但依赖模型理解，效果有波动，适合与方向 1 叠加做第二道防线。
3. ~~确定性正则短路~~：已否决，勿再尝试。
