# 统一模型设置页面

用户需求是减少分散的填写入口。本批统一页面，不迁移服务端配置和密钥，不静默共享凭据。

## 页面结构

工作空间增加“模型设置”，统一入口为`/models?c=<characterId>&section=<能力>`。当前角色通过全局选择器切换。

能力导航集中包含：

- 对话模型：主聊天配置、参数与原有用量/测试。
- 语音模型：TTS合成与ASR识别，保留各自服务、模型、Key、音色和协议选项。
- 图片模型：当前看图识别配置，不把图片生成模型当成视觉理解。
- 记忆助手、语境助手：保留各自独立配置与已有测试接口。
- 知识助手：候选整理及原自动收集设置。
- 关系评估助手：独立模型、Key、预算、启用与连接测试。

已有对话页的五类表单抽取为CharacterModelSettings；知识和社交表单抽取为独立组件。统一页面按需挂载并缓存当前角色的表单：切换能力不丢草稿，切换角色重新读取，不能复用前一个角色的明文Key或迟到请求结果。保留原有保存范围并在页面明确提示：对话、语音、图片、记忆和语境这五项草稿由原“保存设置”一起提交；知识助手和关系评估分别保存。不是全部七类的原子批量保存。保存/测试/获取模型进行中禁止切换能力或离开当前页，避免不同表单并发覆盖配置；保存只清理与提交时一致的密钥草稿，新输入和未提交修改保持未保存状态。

## 旧入口与兼容

旧角色`/characters/:id/settings/model`跳转统一页并携带角色、能力、来源及hash；旧知识设置和关系评估设置页分别跳转knowledge/social。角色管理、知识和社交页面入口更新为统一地址；其他已有书签经过旧入口继续可达。

页面统一不改变API字段、Key留空沿用语义或各助手专用Key规则；服务端已有模型配置继续使用，不需要数据库迁移。不把TTS/ASR协议混成一个聊天接口，也不自动把已有角色Key抄到其他能力。表单仍通过原接口保存、获取模型和测试，凭据不回显。

模型日志统一从页面头部进入。后台反思、忆泡等继续按既有模型配置解析，本批未新建并不存在的独立助手或额外配置项。

## 验证

新统一页及抽取组件增加脚本回归，既有知识设置竞态测试改为组件入口；共享测试harness增加prop注入与组件暴露支持。测试应覆盖能力切换/角色切换、独立保存、旧地址定位、迟到响应、Key草稿隔离、调用日志入口和表单功能保留。

本批未执行付费模型测试、真实语音合成或渠道动作，实际接口连通性仍需用户使用原测试按钮。新统一页和助手组件脚本回归、原知识竞态/批量、QQ链路和社交历史回归、完整typecheck、79个SFC编译、全量lint和隐私扫描通过。保存保护后再次专项/类型/SFC/lint及生产build复验通过。构建仍有既有媒体下载BigInt目标环境和Vite耗时警告，本批未修改相关模块。
