# 下一阶段整体开发实施方案

更新：2026-11-18。

## 开发顺序

一次只推进一个阶段，严格按以下顺序实施：

1. 知识系统最终验收。
2. 私聊助手协作整合。
3. Web 助手协作整合（按用户最新决定，不开发桌面端）。
4. 成长数据中心真实消费者接入。
5. 反思 / 成长闭环。
6. 自我认知系统。

按用户最新决定，状态系统从本轮整体开发范围中移除，不再作为后续阶段或自我认知系统的前置依赖。既有文档中的暂缓规划与占位页面不代表本轮开发任务。

## 实施原则

- 群聊、私聊和 Web 共用统一助手协作基础，各入口提供自己的上下文与权限；桌面端不在当前开发范围内。
- 私聊教育先判断长期价值，再形成经验、偏好或表达习惯候选，不直接变成全局提示词。
- 成长数据中心优先接入经验、偏好、表达习惯、目标与社交关系的真实消费者，延续 mixed sharing、reference relationships、mixed AI updates 与 coordination 统筹层设计，不单纯扩表。
- 反思闭环区分原始经历、候选成长和已确认成长，候选不能直接等于事实。
- 自我认知综合身份、经历、关系、偏好、表达习惯、目标、成长变化、重要记忆与知识，允许随经历变化，并与外观形象分离。
- 不引入向量数据库或向量检索，继续使用时间、类型、关键词与 PostgreSQL 文本检索，有实际瓶颈后再评估。
- 不把所有经验自动变成全局偏好，不把所有知识写入提示词；AI 整理必须保护知识归属与来源。
- 不堆叠人格提示词，不增加情绪值、人格值或状态切换器。

## 完成标准

每阶段完成代码、适用的 TypeScript 检查、相关自动化测试、数据边界测试、真实功能验收和文档同步，确认没有破坏已有系统后再进入下一阶段。明确记录完成位置与未验证事项，未执行的检查不得标记通过。

目标是让角色连续地记住、理解、经历和成长，并逐渐形成对自己的理解。角色名称、模型与渠道由数据驱动。

历史规划如与本实施顺序冲突，以本方案及用户最新指令为准。
