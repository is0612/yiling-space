# 使用版打包与分发

「使用版」有两种运行方式：在现有源码目录中用生产模式继续使用原来的账号和数据；或者把 Docker 镜像发布包发给另一台机器安装。两个批处理按所在目录选择对应方式。

## 1. 本机生产模式与 Docker 分发的区别

| | 本机开发模式 | 本机生产模式 | Docker 发布包 |
|---|---|---|---|
| 所在目录 | 已安装依赖的源码仓库 | 同一份源码仓库（有 `package.json`） | 发布文件夹（没有 `package.json`） |
| 启动 | `启动忆灵空间.bat` → `nuxt dev` | `启动忆灵空间-使用版.bat` → `node scripts/launch.mjs --production` | `启动忆灵空间-使用版.bat` → Docker |
| 网页默认端口 | 3000 | 8801 | 8801（仅本机回环） |
| 配置和数据 | 本机 `.env`、原数据库、`.data` | 沿用同一份 `.env`、原数据库和 `.data` | 发布目录 `.env` 与独立 Docker 数据卷 |
| 账号 | 原有账号 | 沿用原有账号和密码 | 新安装时创建首个管理员 |
| 更新 | 修改源码后热更新 | 更新源码后双击 `更新到最新版.bat`，重新构建并启动 | 提供新镜像包后双击更新 |

### 在现有电脑继续使用原账号和数据

先停止原开发版及其后台进程，再在源码目录双击 `启动忆灵空间-使用版.bat`。入口复用原 `.env` 的数据库连接和 `.data` 中的凭据密钥，首次没有构建产物时自动构建，之后运行已构建的网页和共享后台 Worker；不会通过 seed 重设已有账号密码。无需另外创建生产数据库或填写一套新账号，也不需要使用版 Docker 镜像。

同样可以在项目根目录运行：

```bash
node scripts/launch.mjs --production
# 更新源码后重新构建并启动；对应源码目录的「更新到最新版.bat」
node scripts/launch.mjs --production --rebuild
```

本地更新入口构建当前目录已有的源码，不负责从 GitHub 下载新代码。普通启动复用已有构建，改过源码后需使用更新入口。**本机开发模式和本机生产模式使用同一个数据库，只能运行其中一套 Web、Worker 和渠道适配器**，避免重复消费任务或收发消息。

下文第 2–7 节专门说明 Docker 发布包。它适合独立安装，使用项目名 `yiling-space-prod`、数据库卷 `yiling_space_prod_pg_data` 和应用数据卷 `yiling_space_prod_app_data`，不会自动接入本机原数据库。Docker 版可与本地版本共存，但必须保留数据隔离，不要让两套后台进程连接同一个数据库。

## 2. Docker 发布包由什么组成

镜像里同时装了两样东西，缺一样就会出现「网页能开、但记忆不更新」这种最难查的故障：

1. **网页**：`yarn build` 产出的 `.output`，由 `node .output/server/index.mjs` 提供服务。
2. **后台 Worker**：`scripts/run-memory-worker.ts`，用 tsx 直跑 TypeScript 源码，
   负责记忆提炼、忆泡/周期快照、社交关系评估、成长事件消费。
   所以运行层必须带上 `server/`、`scripts/`、`src/generated/prisma` 和完整 `node_modules`
   （含 `tsx`、`prisma` 这两个 devDependency）。这不是疏漏，是这张架构的必然。

`scripts/launch-prod.mjs` 是容器入口，按顺序做三件事：

1. `prisma migrate deploy` —— 每次启动都跑，幂等。**使用者的数据库就是这样自动更新的。**
2. 库里一个用户都没有时，用 `.env` 的 `DEV_OWNER_*` 建首个 ADMIN（只建一次，不覆盖已改的密码）。
3. 起 Web + 守护 Worker；任一进程退出就整体退出，交给 Docker 的 `restart` 策略。

## 3. 打一个发布包

```bash
node scripts/docker-pack.mjs
# 或者跳过构建，复用当前 latest 镜像只重新打包
node scripts/docker-pack.mjs --skip-build
# 只构建镜像，不导出（自己机器上直接用）
node scripts/docker-pack.mjs --no-save
```

产出在 `dist/使用版-<版本号>/`（版本号取自 `package.json` 的 `version`）：

```
启动忆灵空间-使用版.bat
更新到最新版.bat
docker-compose.prod.yml
scripts/usage-desktop.ps1 ← 两个批处理共用的启动/更新逻辑，必须一并分发
prod.env.example        ← 已填入本包专属的随机数据库密码与管理员密码
使用说明.md             ← 含本包的管理员账号与排错指引
updates/yiling-space-<版本>.tar
backups/                ← 空目录，更新前备份会写这里
```

把整个文件夹压成 zip 发出去即可。脚本最后会打印本包的管理员密码——**每位收件人一份独立随机密码**，
不要把一个包转发给多人用（那样管理员密码就共用了）。

发版前记得改 `package.json` 的 `version`：它同时是镜像 tag、发布目录名和更新包里显示给对方的版本号。

## 4. 对方怎么用

1. 装 Docker Desktop（只需一次）。
2. 解压文件夹，双击 `启动忆灵空间-使用版.bat`。首次会自动 `prod.env.example → .env`。
3. 浏览器打开 `http://127.0.0.1:8801`，用 `admin` + 使用说明里的密码登录。
4. 模型 API Key 在网页里按角色配置，加密存数据库——**不写进 `.env`，也不随发布包传播**。

## 5. 怎么更新（对方视角）

把新版发布包里的 `updates\yiling-space-*.tar` 放进对方的 `updates\` 目录，双击 `更新到最新版.bat`：

1. 暂停应用，必要时启动原使用版数据库；导出并校验 `backups\pre-update-<时间>.dump`，同时备份应用数据卷为 `-app-data.tar.gz`（含解密密钥与素材）、保存同名 `.env` 配置备份。备份失败即中止；
2. 从 `updates` 中按版本号选择最高的 `yiling-space-X.Y.Z.tar`（也兼容 `.tar.gz`），只加载这一份并确认包含配置指定的镜像；加载失败即中止，迁移前失败会尝试恢复原容器运行；
3. 重建容器，容器启动时自动迁移；检查 **app 容器本身**健康且宿主机 `/api/health` 可访问后才报告成功。超时、异常退出或健康检查失败返回非零并显示应用日志。

脚本不会从 GitHub 自动下载或编译源码；保留旧镜像包再次运行，也只能安装该包的版本。使用镜像仓库时，在配置中设置 `YILING_IMAGE` 并移走旧的本地包。迁移已经执行后，不自动回退旧镜像；恢复必须配套考虑数据库、应用数据卷和配置备份。备份含私人数据和凭据，请安全保存。

Docker 发布包更新保留原数据卷，迁移更新数据库结构；聊天记录、记忆、角色及已加密的 Key 随原卷保留。发布目录 `.env` 不覆盖，端口和管理员密码沿用已有设置。本机源码目录的批处理走第 1 节的本地生产模式，使用原 `.env`，不使用 `.env.prod`。

尚无使用版容器时，更新入口转入首次启动流程。已有容器但没有本地包时，只有配置了带域名的 `YILING_IMAGE`（如 `registry.example.com/yiling-space:latest`）才尝试拉取；默认本地镜像则在停机前提示补齐更新包，现有服务继续运行。本机源码更新后先执行 `node scripts/docker-pack.mjs`，再使用生成的镜像包更新。

## 6. 必须记住的三件事

1. **`credentials-encryption.key` 在 `yiling_space_prod_app_data` 卷里。** 删卷 = 网页里存过的 API Key 全解不开。
   `docker compose down` 安全，`down -v` 会删数据。
2. **迁移只向前。** 新版本跑过的迁移，回退到旧镜像不会自动撤销结构变更；
   真要回滚得用 `backups\` 里的 dump 恢复，所以更新脚本把备份放在第一步。
3. **使用版不要挂源码目录。** 它只引用镜像（`image: yiling-space:latest`），
   如果有人把 `build: .` 加回 `docker-compose.prod.yml`，等于在对方机器上编译，那又变回开发版了。

## 7. 本机验证 Docker 发布包

需要测试「另一台电脑首次安装」时，构建完整发布包，再进入 `dist/使用版-<版本号>/`，双击其中的 `启动忆灵空间-使用版.bat`。这个文件夹没有源码 `package.json`，因此会运行 Docker 路径。测试 Docker 发布包时不要双击源码根目录的同名入口，后者运行第 1 节的本地生产模式。

```bash
node scripts/docker-pack.mjs
```

进入发布目录后可用以下命令查看日志或停止，数据卷保留：

```bash
docker compose -f docker-compose.prod.yml logs -f app
docker compose -f docker-compose.prod.yml down
```

Docker 版首次安装会在独立的空库应用迁移并创建管理员；原电脑已有的账号、角色和记忆不会自动出现在这里。只想继续使用本机原有数据时，使用第 1 节的本地生产入口即可。
