# QQ 小号接入部署清单（SnowLuma + yiling-space）

> 目标：用个人 QQ 小号，让 yiling-space 里的角色在 QQ 上收发消息、带记忆。
> 前提：QQ 小号和 yiling-space 先跑在同一台 Windows 电脑上（`127.0.0.1` 直连），跑通后再考虑上服务器/换设备。

## 0. 一句话原理

```
QQ 群/好友发消息
   → SnowLuma（挂在你登录的 QQNT 客户端里，把 QQ 操作翻译成 OneBot v11）
   → OneBot 正向 WebSocket（ws://127.0.0.1:3001）推给 yiling-space
   → yiling-space 的 qq-onebot 适配器 → 角色 + 记忆 → 模型回复
   → OneBot HTTP API（http://127.0.0.1:3002）发回 QQ
```

SnowLuma 是"传话筒 + 翻译官"，yiling-space 是"大脑"。两者是各自独立的程序，靠 OneBot v11 通信：
**WS 只收，HTTP 只发**，所以两个端口、两个 Token 缺一不可。

## 私聊引用消息

QQ 私聊中引用一条消息时，适配器按引用 ID 回查网关的 `get_msg`，确认属于当前私聊后，把该条原文单独传给模型。回复拆成多条发送时，只读取被选中的那一条；不把整轮回复当作引用。引用关系同时保存在用户消息的 metadata 中，正文保持原样。

回查失败、网关不支持接口或无法确认消息属于当前私聊时，仍正常处理用户消息，并告知模型引用原文不可用，避免猜测。原文最多 2000 字符，超出明确标记截断。无引用的消息不会增加回查请求。修改适配器源码后需重启 QQ 适配器才生效。

## 1. 装 SnowLuma

| 项 | 值 |
|---|---|
| 下载 | `https://github.com/SnowLuma/SnowLuma/releases`，选 `win-x64.zip`（自带 Node 运行时，不用另装环境） |
| 管理面板 | `http://127.0.0.1:5099`；**配置 OneBot 的是 `/config` 页**，不是 `/settings` |
| Token | WS 与 HTTP 是**两个不同的值**，都要抄下来 |
| 许可 | 源码可见但**非商业**许可，核心注入组件闭源 |

> SnowLuma 没有独立窗口：双击 `start.bat` 会开一个命令行常驻（关掉即停），所有操作在浏览器面板里。
> 它靠注入已登录的 QQNT 客户端工作，**那个 QQ 窗口不能关**。

### 1.1 准备

- 装好**新版 QQ（NTQQ，9.9.x）**，并用 QQ 小号**先登录一次**。
- 强烈建议用**小号**：非官方协议有风控/封号风险，小号损失可控。
- 小号先"养"几天（正常聊天、别一上来高频群发），降低风控概率。

### 1.2 登录小号并挂上注入

1. 先用**官方 QQ 客户端**登录小号（不是面板里扫码），窗口保持开着。
2. 启动 SnowLuma：双击 `start.bat`，或直接在 yiling-space「QQ 渠道」页第 2 步点**启动 SnowLuma**。
   页面这条路不经过 `start.bat`：它直接跑发行包自带的 `node.exe index.mjs`（原因见文末「启动踩过的坑」）。
   日志照旧写在 SnowLuma 目录的 `runtime.log`，要停就点页面上的**停止**。
   **它会开一个黑窗口，标题是 `...\SnowLuma\node.exe`**：那是 SnowLuma 的应用进程（它以管理员权限再起了一层），
   `[App] SnowLuma starting`、`[Hook] login detected`、每条群消息这些都实时刷在这个窗口里。
   日志同时也写进 `logs\` 和 `runtime.log`。这个窗口**不能关**（关掉就等于把面板停了）。
   如果窗口里空空如也，说明跑的是旧版启动方式（输出没接进控制台），点一次「停止」再「启动」就恢复。
   **面板密码不用手抄**：全新安装（还没有 `config/webui.json`）时，忆灵空间会替它生成一个密码、用
   `SNOWLUMA_WEBUI_BOOTSTRAP_PASSWORD` 播种进去，并立刻写进「连接设置 → SnowLuma 面板密码」。
   这串密码同时**明写在「连接管理」卡片里那一行「面板密码」**（等宽字体、可复制、可遮住），要登录面板直接点旁边的「复制」；
   想换成自己记得住的，点那行下面的「在连接设置里改」，改完自动配节点会跟着用新的。
   接管不了的场合（面板早就初始化过、或者还没有 QQ 连接可写）：初始密码不会进连接设置，
   它只打印在刚开的那个窗口里（`★ WebUI 初始登录凭据` 那一段），抄下来登录面板、立刻改掉，再填进连接设置。
   页面上那行状态会自己认出安装目录：先看有没有存过，再看 5099 上跑的进程是谁（最准），最后扫一遍下载 / 桌面 / 文档 / Program Files / 各盘根目录下两层。所以用 AI 装到下载文件夹里也能自动认出来，正常情况**不用填路径**。真认不出来（提示「没找到程序」）时，点「换目录」填一次，存进 `.data/snowluma-home.json`。
3. 打开 `http://127.0.0.1:5099`，同意条款后登录（密码就是「连接管理」里那行「面板密码」，点「复制」粘过去）。
   **面板密码只有一处真相**：连接设置里那一格（页面上显示的就是它）。你在面板里改了密码，必须回来同步，否则自动配节点 / 自动挂 QQ 会报「面板密码不对」。
4. 看日志：出现 `[Hook] pipe connected` 与 `login detected … UIN=你的小号` 就说明已经自动挂上了。
   只有日志里没有这两行时，才需要去面板「进程注入」→「探测登录」→「加载」，等指示灯变绿。

## 2. 开启 OneBot v11 正向 WebSocket + HTTP API

### 2.1 端口规划（先避开 3000）

yiling-space 的 dev server 默认占 **3000**，SnowLuma 的 HTTP API 默认也是 3000 —— 同机运行必然撞。

| 用途 | 端口 | 说明 |
|---|---|---|
| OneBot 正向 WebSocket | 3001 | SnowLuma → yiling-space 推消息，保持默认 |
| OneBot HTTP API | **3002** | yiling-space → SnowLuma 发消息，从默认 3000 改到 3002 |

### 2.2 面板里点哪里

1. 进 **`/config`** 页（`http://127.0.0.1:5099/config`）—— 端口和令牌都在这里。
   ⚠️ 不在 `/settings`，那页只有备份、存储、外观，翻不到任何 OneBot 项。
2. 左栏选中你的 QQ 小号。
3. 右边「节点配置分类」切到 **WS 服务端**：已有端口 3001 的节点（如 `ws-default`）就直接用，别再新建 ——
   两个节点抢同一个端口，后启动的起不来；列表空才「新建」，弹窗默认值（3001、数组、Universal）不用改，「创建节点」。
4. 再切到 **HTTP API**：已有节点就把端口从默认的 3000 改成 **3002**；没有才「新建」一个端口 3002 的。
5. 令牌：**连接里空着的话不用手抄**。页面的「启动 SnowLuma / 重连」会读面板里同端口的那个节点，
   把 `accessToken` 抄进连接设置（「WS Token」/「HTTP Token」）并落库 —— 抄的动作是「连接里没填」时才做，
   你填过就以你填的为准。要换令牌、或者面板节点里本来就没令牌，才需要手动：点开节点复制授权 Token，
   WS 的填「WS Token」，HTTP 的填「HTTP Token」—— **它们是两个不同的值**，最常见的报错就是拿 WS 的 token 去配 HTTP，握手直接 401。
6. 保存，重启 SnowLuma。

> 界面找不到也能手改配置文件：`config/onebot_<QQ号>.json` 里的 `networks.wsServers[0].port`、
> `networks.httpServers[0].port` 与各自的 `accessToken`，改完重启。

### 2.3 验证端口已监听

```powershell
Get-NetTCPConnection -LocalPort 3001 -State Listen
Get-NetTCPConnection -LocalPort 3002 -State Listen
```

两条都有输出，说明 WS 和 HTTP 都起来了。

> 顺便验证 HTTP 通道能发：带面板里那个 HTTP Token 请求 `POST http://127.0.0.1:3002/get_login_info`，
> 返回 `{"status":"ok","data":{"user_id":…}}` 就通了；返回 `retcode 1401 unauthorized` 是 Token 不对。
> 本机开着系统代理时（如 `127.0.0.1:56435` 这类），`127.0.0.1:5099` 可能被代理转走并回 502 ——
> 把 `127.0.0.1` 加进代理白名单，或用 `curl --noproxy '*'`。端口没监听时也是这个 502，别误判成"面板坏了"。

## 3. 在 yiling-space 里添加「QQ 小号」

1. 启动 yiling-space（`yarn dev`）。
2. 打开「系统管理 → QQ 渠道」，点右上「添加 QQ 小号」。
3. 平台固定为 **`qq-onebot`**（这个页面只管 QQ 小号，B站 走「B站值班台」）。
4. 填表单（新建时可以点「填入默认地址」一键填好两行地址）：

| 字段 | 填什么 |
|------|--------|
| QQ 号（必填） | 你的 QQ 小号数字，例如 `123456789` |
| OneBot WebSocket 地址 | `ws://127.0.0.1:3001` |
| OneBot HTTP API 地址 | `http://127.0.0.1:3002` |
| WS Token | SnowLuma「WS 服务端」节点的授权 Token；没设就留空 |
| HTTP Token | SnowLuma「HTTP API」节点的授权 Token（**与 WS 那个不同**） |
| 面板密码 | SnowLuma 面板（`127.0.0.1:5099`）的登录密码。填了才能「一键」：自动对齐节点 + 自动把这个号挂上面板 |
| 群聊中仅在被 @ 时才回复 | 建议勾选（群聊只在被 @ 时说话，更像真人、更安全） |
| 显示名 | 例如「我的 QQ 小号」 |

5. 保存。
6. 在这张连接卡片上点「绑定角色」，选一个角色。**不绑角色，消息进来不会有人回。**
   路由键留空 = 私聊 + 所有群都响应；填群号 = 只响应那个群（多个群就绑多条）。
   已经绑在这个号上的角色在选项里是灰的（名字后面带「已绑定」）——同一个角色再绑一次不会产生新绑定，
   只会把原记录原地写回去，所以这条路直接挡掉。要改群号就展开清单里那一行改，不走这个弹窗。

> 凭据（WS/HTTP 地址 + Token）在库里是 AES-256-GCM 加密的，但管理员在「连接设置」里能回看明文，方便核对填没填对。
> 同一个 QQ 号再保存一次是更新，不会重复创建。

## 4. 启动 QQ 小号适配器

三种方式等价，选一个：

- **一键（推荐）**：`yarn onebot:stack`，或双击 `scripts/start-qq.bat`。
  它会先把 SnowLuma 拉起来、等 3001/3002 通了再挂适配器，一个窗口管到底 ——
  省得「协议端还没开端口，适配器已经在重连」，也避免手滑起两个协议端实例抢同一个库。
  协议端目录不用改代码：在网页「QQ 渠道」点「换目录」填一次即可（脚本与服务端读同一份配置），
  也可以用 `SNOWLUMA_HOME` 临时覆盖。SnowLuma 是第三方程序，需自行下载，不在本仓库内。
- 网页上点：QQ 渠道页第 4 步的**启动适配器**按钮（协议端已经在跑时用这个）。
- 新开一个终端，在项目根目录执行：

```bash
yarn onebot:run
```

看到日志里出现 `onebot-connected` 即表示连上 SnowLuma 了。

新版适配器运行后会定期读取连接设置，修改地址或 Token 后，在网页「连接设置」点击「保存并重新连接」即可，无需手动关闭终端。请求写入数据库，连接卡片显示「等待适配器重新连接」；稍后点击「刷新」，看到「适配器已按新设置连接过网关」后，再核对当前连接状态是否为「已连接」。历史重连完成不代表当前仍在线。

首次使用仍需执行一次 `yarn onebot:run` —— QQ 渠道页第 4 步的「启动适配器」会替你在项目根目录开一个命令行窗口跑这条命令，窗口里能看到 `onebot-connected` 这类日志，**关掉窗口即停**。网页只负责开窗口，不接管这个进程：不会替你杀它、也不会重启电脑；已经手动开着时再点会被拦下（两个适配器会抢同一条连接）。如果你运行的是更新前启动的旧版适配器，请在它的终端按 `Ctrl+C` 停止，再运行 `yarn onebot:run`；旧版不会处理网页请求。

> SnowLuma 那个黑窗口（标题是 `...\SnowLuma\node.exe`）**不能关**，关了 QQ 就掉线 —— 从 `start.bat` 起、从页面起都是它。`onebot:run` 这个进程也要保持运行，关掉它的终端等于停掉适配器。
> 两个都是普通前台进程，**重启电脑、注销或关掉承载它的终端就没了** —— 重新按 1.2 和这一节各起一次。

### 面板在跑，3001 却没人听？（QQ 没挂上面板）

面板端口 5099 在听，不等于 3001/3002 在听：那两个 OneBot 节点要等**这个 QQ 号的会话**建立之后才会 listen，
而会话来自注入进 QQ 客户端的 hook。所以下面这个顺序必然卡住 —— 先开 QQ 客户端，再点「启动 SnowLuma」：

- 面板只有 WebUI（日志里只有 4 行 `[App]` / `[WebUI]`，没有 `[Hook] login detected`、没有 `[OneBot] session started`）；
- 3001/3002 一个都不 listen；
- 适配器每 30 秒刷一次 `onebot-disconnected ... code=1006`；
- 页面链路带上写「节点没开」，但进面板一看节点明明配着。

现在不需要人进面板手点「加载」：面板密码存在连接凭据里，页面的**启动 SnowLuma / 重连**、
以及打开 QQ 渠道页时的自动补起，都会用同一个密码登录面板 → `GET /api/processes` 找到这个号的进程 →
`POST /api/processes/:pid/load` 注入 hook → 等 3001 起来 → 再挂适配器。
挂不上时会把原因原样说出来，三种常见情况：没填面板密码、密码不对（面板按 IP 锁 5 次，所以只试一次）、
面板里没有这个号的进程（说明 QQ 客户端没登这个号）。

## 4.1 群公告（可选）

1. 在 QQ 里把小号设为群管理员（只有群主能设置）。
2. 到「QQ 渠道 → 连接设置」勾选「允许群主/管理员让她拟群公告」并保存。
3. 群主/管理员在群里 @ 小号，说「写个群公告：本周六晚八点活动」。
4. 她会先回一份草稿；管理员回复「确认发布」后才会真正发到群公告。

普通成员触发无效；草稿 10 分钟内有效。发布失败时，她会在群里回复失败原因（常见是小号不是管理员）。

## 4.2 群发言频率限制（群规）

群规要求「单只鱼 5 条消息」时：

1. 在「QQ 渠道 → 角色在 QQ 上的行为」找到这个角色对应的卡片。
2. 在「群聊发言限流」里设成「每 **10** 分钟最多回复 **4** 条」。
3. 点「保存群聊行为」。

滚动 10 分钟内最多回 4 条，第 5 条起静默；0 表示不限。时间窗和条数都可改，只作用于这个群，只统计这条鱼自己的回复。

## 4.3 主人让她刷 B站（可选）

1. 在「QQ 渠道 → 连接设置」填 **主人 QQ 号**、**主人称呼**（例如群名片上的名字），保存。
2. 在「角色在 QQ 上的行为」里给这个角色打开「刷一轮 B站」。
3. 确认角色已在「B站 值班台」绑定好账号。
4. 主人（只认填的那个 QQ）在群里 @ 小号说「去刷一轮 B站」。

她会先回执，再在后台跑一轮；额度、评论/收藏/动态等仍按 B站 值班设置执行。其他群友发同一句话会被忽略。

## 5. 验证能收发

1. 用**另一个 QQ 号**（你的主号或朋友的号）给 QQ 小号**发私聊**「你好」。
2. 角色应该会回复（内容来自 yiling-space 里配的模型 + 记忆）。
3. 如果开了「群聊仅 @ 回复」，去群里 **@ 一下小号**，它才会回。

## 6. 常见问题

| 现象 | 处理 |
|------|------|
| 收不到消息 | 确认 SnowLuma 已登录、正向 WS 是 3001、`onebot:run` 在跑 |
| 页面提示「还没填 SnowLuma 面板密码」/ 点「重连」后 3001 还是没人听 | 这条连接的面板密码是空的，而自动配节点、挂 QQ 都得先登录面板（`/api/processes` 要 session）。全新安装时这一格会被**自动填好**；空着通常是「面板早就初始化过（例如你手动改过密码）之后才建这条连接」。两个办法：把面板密码填进去再点「重连」，或者按下一行重置让忆灵空间重新接管 |
| 忘了面板密码 / 想让忆灵空间重新接管 | 面板只存 hash + salt，谁也反推不出来。重置：① 页面「停止」SnowLuma → ② 把 `config\webui.json` 改名（原文件留着，随时能改回来）→ ③ 点「启动 SnowLuma」或「重连」，忆灵空间发现没有 webui.json 就自己生成新密码、写进连接设置 → ④ 之后面板密码就是这个值（要手动登录面板就从连接设置里抄出来）。注意：旧密码立刻失效 |
| 面板 5099 打不开 / 返回 502 | 先看端口有没有监听（`netstat -ano \| findstr :5099`）；没监听就是 SnowLuma 进程没了，在 QQ 渠道页第 2 步点「启动 SnowLuma」（或重新跑 `start.bat`）。有监听还报 502，是系统代理把 127.0.0.1 也转走了，把本地地址加进白名单 |
| HTTP 一直失败 | HTTP API 若是默认 3000，会和 yiling-space dev server 抢；改成 3002 并在渠道里同步 |
| 401 / 握手失败 | WS token 与 HTTP token 填反了；两个框的值不一样 |
| `onebot-connected` 后仍不回 | 检查角色是否已绑定该渠道；检查角色模型/API Key 是否配好 |
| SnowLuma 首次连接报 1006 | 已知行为，会自动重连；只要最后出现 `onebot-connected` 就没问题 |
| SnowLuma 启动报 `Client private-message reporting is unavailable` | 只是拿不到自己发出去私聊的送达回执，不影响收消息，可忽略 |
| 日志刷 `SQLITE_READONLY: attempt to write a readonly database` | 起了**两个**协议端实例抢同一个 messages.db。任务管理器里把路径含 snowluma 的 node 进程全部结束（正常单实例是 2 个：主进程 + 子进程，超过就是重复），再只启动一次 |
| 消息进来了但不回（`not_mentioned`） | 勾了「群聊中仅在被 @ 时才回复」就是这样；私聊不受这条限制 |
| 重启电脑后一片「连接异常」 | 直接 `yarn onebot:stack`（或双击 `scripts/start-qq.bat`）一次搞定；手动起的话三件事都要在：QQ 客户端登录着、协议端在跑（3001/3002 在监听）、适配器在跑 |
| SnowLuma 进程活着但收不到 | 「Hook 退化」已知问题：重启 SnowLuma，仍不行就查它自己的 `logs/` |
| 登录提示风控/验证 | 换扫码/短信登录，小号养几天再上 |
| 发消息频繁被吞 | 降低回复频率（QQ 对高频有管控） |
| 桌面上有一个黑窗口，标题是 `D:\Tools\SnowLuma\node.exe` | 那是 SnowLuma 的应用进程，**日志就刷在里面**（和双击 `start.bat` 时一样），同时写进 `logs\` 与 `runtime.log`。**别关它**，关了就等于把面板停了。窗口是空的 = 跑的是旧版启动方式，点一次「停止」再「启动」恢复 |
| 提示「HTTP 节点在连接里没填令牌，用的是面板原来那个」 | 旧版文案。现在连接里空着会自动把面板那个令牌抄回来（见 2.2 第 5 步）；还看到这句说明跑的是改之前的前端，刷新页面即可。真抄不到（面板节点自己也没令牌）会改说「面板里的 HTTP 节点也没有令牌」 |
| 改完令牌后适配器还是不认 | 令牌是适配器**启动时**读的，改完要它重连：页面「重连」按钮会提交重载请求；手动起的话在它的终端 `Ctrl+C` 再 `yarn onebot:run` |
| 改了 SnowLuma 端口后连不上 | 同步改 yiling-space 渠道里的 WS/HTTP 地址 |
| 页面点「启动 SnowLuma」后 5099 一直没人应答（`runtime.log` 一整天没有新行） | 见下面「启动踩过的坑」。现在页面不再经过 `start.bat`，这个故障已经修掉；只有你**手动双击** `start.bat` 起不来时才需要看 |

### 启动踩过的坑（2026-11-02）

现象：页面上点「启动 SnowLuma」秒回「已打开窗口」，但 `D:\Tools\SnowLuma\runtime.log` 一行新内容都没有，40 秒后页面报「面板还没应答」，`netstat -ano | findstr :5099` 也没人听。`.data/onebot-snowluma-launcher.json` 里 pid 记下来了，进程却早就没了。

根因在 SnowLuma 自带的 `start.bat`：那份文件被改过（组里的人为了绕开官方 `launcher.bat` 的 Node 版本闸门换成了自带 `node.exe`），保存成了 **UTF-8 + 纯 LF 换行**。cmd.exe 解析批处理要 CRLF，LF 叠中文会读串行，实测把子进程输出抓下来是这样：

```text
'门挡住?rem' 不是内部或外部命令，也不是可运行的程序
'查未通过，按任意键退出?' 不是内部或外部命令
'.exe' 不是内部或外部命令
```

也就是说 `.\node.exe .\index.mjs` 那一行被切碎了，`index.mjs` 一次都没跑起来 —— 面板自然永远起不来。同一个文件双击有时能起（交互式控制台和无控制台 spawn 走的解析路径不同），所以这个问题看着很“玄学”。

修法：`launchSnowluma()` 不再交给批处理，直接 `spawn(<home>\node.exe, [<home>\index.mjs], { cwd: home })`，也就是 `start.bat` 里真正干活的那一行；找不到这两个文件时才退回 `cmd /c start.bat`。对照实验：同一份内容压成 CRLF 再 spawn，2 秒起来；原样 LF，20 秒也不起。

所以：**不要再用编辑器把 `start.bat` 存成 LF**。真要手改，存成 CRLF，或者干脆别改 —— 页面这条路已经不看它了。

## 7. 将来换设备 / 上服务器

当前是「QQ 小号 + yiling-space 同机 `127.0.0.1` 直连」，跑通后：

- **换设备挂小号**（公司 / 家里 / 笔记本轮换）：在每台电脑都装好 SnowLuma 并登录小号（同一时刻只能一处在线），`onebot:run` 和 yiling-space 也随设备走。
- **yiling-space 上服务器**：QQ 小号继续留在家里/公司电脑，用内网穿透（frp / cpolar / cloudflared）把 `3001`/`3002` 暴露给服务器，然后在服务器 yiling-space 的渠道里把地址改成穿透后的公网地址。

## 8. 安全提醒

- 用**小号**，非官方协议有封号风险，别用主号、别给 bot 号充值、别存重要数据。
- OneBot 端口**只走本机/局域网**，不要映射到公网（未加密 + 未鉴权，暴露等于交出 QQ 控制权）。
- 私聊场景风险低于群聊，群聊建议开启「仅 @ 回复」降低频率。

## 9. 升级 SnowLuma

**一个版本一个目录**（`...\snowluma\v2.2.1`、`...\snowluma\v2.4.0`），回退只要把指针改回去 —— 所以升级一律「**复制**数据到新目录」，不要在旧目录上原地解压覆盖。

```text
1. 停掉协议端（页面上「停止 SnowLuma」，任务管理器确认没有 snowluma 的 node 进程）
2. 新版 zip 解压到 ...\snowluma\v2.4.0
3. 旧版的 config\ 和 data\ 整个复制到新目录（进程停着才复制）
4. 复制旧版的 start.bat 过去，或者自己建一个（见下）
5. .data\snowluma-home.json 的 home 改成新目录（或在页面「换目录」里填一次）
6. 启动，日志里应依次出现 WebUI listening / [Hook] login detected / pipe connected / [OneBot] session started
```

几个必须知道的点：

- **发行包里没有 `start.bat`**（只有 `launcher.bat`，它过 Node 版本闸门）。忆灵空间靠「目录里有 start.bat」认安装目录，也靠它决定能不能启动，所以新目录必须有 —— 内容就四行，**存成 CRLF**：

  ```bat
  @echo off
  cd /d %~dp0
  ".\node.exe" index.mjs
  pause
  ```

- `data\<QQ号>\messages.db{,-wal}` 是它自己的消息库，**进程没停就复制会拿到半截 WAL**。停稳再复制，两边文件大小应完全一致。
- 升级别只起不停：两个实例会抢 5099（后起的日志里会有 `port 5099 is in use, using 5100 instead`），更糟的是抢同一个 `messages.db`。
- 面板 API（`/api/login`、`/api/config/:uin`、`/api/processes`、`/api/processes/:pid/load`、`x-snowluma-token`）从 v2.2.1 到 v2.4.0 没变，自动配节点与自动挂 QQ 不用改代码。
- 端口、令牌、面板密码都在 `config\` 里，跟着目录一起搬；`webui.json` 也在，所以面板密码不变。
- 出问题回退：把 `.data\snowluma-home.json` 改回旧目录、停掉新实例再启动即可，旧目录里的库还是升级前的样子。
