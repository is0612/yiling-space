# CI 与可靠性检查记录

本次基于 main 的 `e7a49bc` 检查并修复。运行环境为 Node 24.21、Yarn 1.22.22、PostgreSQL 16；GitHub Actions 使用 Node 22，本次没有触发远端流水线。

## 修复

- OneBot：临时私聊已共享正式知识检索，空库诊断为 `no_match`。端到端测试仍期待旧的 `not_needed`，导致 CI 失败。修正期望，同时验证候选、选中和提供内容均为空；保留非主人私聊不能读取主人私人记忆的断言。
- 日记/手账：调度器此前只排昨天，停机多天会漏掉更早日期。现按角色时区从历史来源日期补排，每角色每轮最多 24 天；限额前排除已有任务键、完整文本和无需重新评估的 SKIPPED 日期，避免积压饥饿。范围仍限角色全局与主人私人记忆，保留缺份补齐与新来源重评规则。
- 数据恢复：`pg_restore` 加单事务保护，使清理和导入一起提交，恢复中段出错时一起回滚。新增无网络临时容器回归，正常恢复及中段失败都验证；无事务对照证明原流程会丢失目标原数据。该回归已接入 CI。
- API 冒烟：模拟模型端口可配置；模拟服务显式支持日记/手账 SKIP 决策。清理测试先完成历史归档依赖，再重试并核对实际删除与审计，不再假设第一次领取就能完成清理。
- 成长闭环：测试替身遗漏了互动经验新增的独立语义审核请求，误将审核请求当成反思请求处理，造成 REVIEW_FAILED 和退避。补齐审核响应并验证每条经验均经过审核后才以 ACTIVE 状态参与反思。

## 审查范围与限制

审查记忆任务租约、回收、候选领取、续期及结果提交的相关路径；成长事件投递的领取/过期回收、租约 token 与 fencing、处理及完成状态的同事务提交、有限退避和人工重试；后台进程启动与守护配置。除已修复的日记补排外，所读路径没有确认新的可靠性缺陷。并未逐行覆盖每个 Worker 和业务消费者，不代表真实负载下的完整故障演练。

权限检查涵盖同源中间件、会话鉴权入口、角色归属过滤、任务运维管理员鉴权、成长投递重试的角色和所有者约束、知识主题操作的角色约束。管理员接口鉴权入口做了抽样与搜索，并非所有接口逐个完整安全审计；具体运行证据以相应数据库测试及 API 冒烟为准。

没有调用真实 QQ、B站或模型供应商。未执行公网 HTTPS/反向代理部署演练、全新 clone 依赖安装或远端 GitHub Actions 重跑。渠道加密密钥与素材仍需按迁移文档一起备份恢复；本次数据库事务修复不替代这些文件的恢复。
