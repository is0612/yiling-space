# 知识系统

## 定位

知识系统负责收集、处理、整理、保存和检索角色学到的知识。它与记忆系统、社交关系系统并列，按角色独立积累。

- **记忆系统**回答：发生过什么、经历过什么。
- **知识系统**回答：学到了什么、理解了什么。
- **社交关系系统**回答：她认识谁、与对方处于什么关系。

知识可以来自经历，但不能把经历记录本身直接当作知识；用户偏好也不应仅因被提及就自动变成知识。

## 核心原则

1. **先处理，后入库**：聊天或资料中出现的内容只是候选，不等于正式知识。
2. **来源可追溯**：每条知识应尽可能保留来源类型、来源引用和获取时间；不能把模型推测伪装成来源事实。
3. **保留不确定性**：对来源不可靠、内容不完整或仍有争议的知识标记置信状态，不强行写成确定结论。
4. **去重与冲突并存**：重复内容应合并或关联；相互矛盾的说法应保留冲突关系，不能静默覆盖旧知识。
5. **角色隔离**：不同角色的知识默认独立；不因平台账号或相同标题而跨角色共享。
6. **按需检索**：不把整个知识库塞进每次聊天。语境助手判断是否需要知识检索，再按问题召回少量相关条目。
7. **知识与记忆分工**：知识条目不复制整段聊天经历；需要证据时引用记忆事件或原始来源。

## 建议的数据流

`来源 → 候选 → 处理 → 待确认/可入库 → 正式知识 → 按需检索`

### 来源

首批考虑三类来源：

- 聊天中出现、可能值得学习的内容；
- 用户主动提供或导入的资料；
- 用户手动创建的知识条目。

接入时保留来源引用和必要的元信息。不要默认把所有聊天内容都送去知识处理。

### 候选与处理

知识处理助手负责判断候选是否属于可复用知识，并执行：

- 提炼主题、核心结论和必要解释；
- 识别知识类别、关键词和关联概念；
- 检查已有知识中的重复项；
- 发现与现有知识不一致的内容并建立冲突提示；
- 记录来源与不确定性；
- 给出建议动作：丢弃、补充现有条目、创建新条目或标记待核实。

处理助手的输出先进入候选处理结果，不直接覆盖正式知识。

### 正式入库

正式知识与候选分开管理。入库操作应保留处理结果、来源引用和变更历史。对于冲突、低可信度或来源不足的内容，先进入待确认状态；明确可靠且符合规则的内容才可自动入库。具体自动入库门槛和人工确认策略在实现前结合现有 AI 助手调用方式确定。

### 检索与使用

检索由语境助手按需触发。知识系统只返回与当前问题相关的条目、来源和可信状态；主聊天模型仍负责最终回复。检索结果不能越过角色隔离，也不能把未确认候选当成正式知识。

## 与其他系统的边界

- 不接管忆泡、日记或长期记忆的写入职责。
- 不把「发生过的事」自动改写成知识；只有可复用的概念、规律、事实或技能等才适合进入知识系统。
- 不负责记录用户偏好；偏好由偏好系统负责。
- 不负责维护朋友身份或关系阶段；由社交关系系统负责。
- 可以引用其他系统的数据作为证据，但不复制其正文作为另一份事实来源。

## 页面结构（首阶段）

- **知识候选**：查看待处理内容、处理状态、来源和处理建议。
- **知识库**：查看已入库知识，支持搜索、分类、详情、修订、归档和来源追溯。
- **处理记录**：追踪处理助手的运行结果、失败和人工处置。
- **知识设置**：配置知识处理助手及其独立模型凭据、自动收集/处理范围和入库策略。

首阶段先完成候选—处理—入库—检索的主链路；批量资料解析、复杂知识图谱和自动推理暂不作为前置条件。


## 当前实现进度（2026-11-08）

### 已建立

- Prisma 增加 `KnowledgeCandidate` 与 `KnowledgeItem`，候选和正式知识分表保存，均通过 `characterId` 隔离角色。
- 迁移：`20261108120000_knowledge_system_foundation`。
- 知识系统页面支持手动添加候选、调用知识处理助手、查看处理建议、确认入库或忽略，以及搜索正式知识。
- 知识处理助手采用独立模型、API 地址、API Key、温度和输入/输出 Token 配置；Key 使用本地凭据加密，绝不回落聊天、记忆助手或语境助手 Key。
- 已增加候选列表/创建/处理/接受/忽略 API，以及正式知识检索 API。
- 处理助手会参考现有正式知识，返回 CREATE / DUPLICATE / CONFLICT / DISCARD 建议；所有处理结果先进入 REVIEW，必须由用户确认才会正式入库。
- 知识助手调用单独记入 `knowledge-assistant` 用量类别。
- 初版检索采用角色范围内的词项匹配与相关度排序，不读取候选、不跨角色搜索。

### 尚未完成

- 文档批量导入、网页来源采集。
- 正式知识的编辑版本历史、合并重复项、冲突处理工作流和归档管理。
- 私聊检索链路本轮已实现，仍需 DSH 对最新 main 做本地专项验收；验收前不视为已完成。

### 当前边界

- 处理助手只提出整理建议，不负责替用户决定正式入库。
- 只有 `KnowledgeItem` 会出现在正式知识库和检索结果中；`KnowledgeCandidate` 与其处理结果不会作为已掌握知识提供给聊天。
- 即使模型建议 DUPLICATE 或 CONFLICT，也不会自动覆盖、合并或删除现有知识。
- 候选来源已覆盖 MANUAL 与 CHAT（群聊及私聊自动发现）；IMPORT 仍待接入。聊天自动发现只创建候选，不代表自动处理或自动入库。


### 私聊候选发现与按需检索（候选发现已验收，检索待验收）

- 所有好友与角色的私聊均适用，不按主人身份或好友身份做额外限制。
- 本地预筛先过滤问候、普通闲聊和纯情绪表达；出现概念解释、知识问答、纠错、方法技巧、步骤、规则、语法/算法等信号时，才考虑调用语境助手。保留短知识问句（如“猫是什么？”），不因字数不长直接过滤。
- 使用私聊专用提示词和输入结构，不复用群聊分析入口；只提交当前轮消息 ID、发言人显示名和原始正文，不提交记忆、群聊背景、跨会话历史、其他好友数据或账号标识。
- 模型返回的消息 ID 必须通过当前轮白名单校验；候选正文由程序从原始消息拼接，不能使用模型改写。
- 候选来源引用包含 conversationId、messageIds、发言人、理由、采集时间及 PRIVATE 标记；同角色 30 天内相同原文去重。
- 自动收集开关默认关闭，只控制是否创建候选，不控制正式知识检索。语境助手失败、知识检索失败、候选持久化失败或用量记账失败均不得影响私聊正常回复。
- 私聊的 `knowledgeQuery` 由同一次私聊语境分析返回，不新增第二次模型调用；数据库检索只查当前角色 `KnowledgeItem(status=ACTIVE)`，经相关度排序最多返回 8 条给主聊天模型。检索不读取候选，也不跨角色或查询好友的私人记忆。
- 新增 `yarn test:private-knowledge-candidate`，并已并入 `yarn test:context-assistant`；覆盖候选 ID 白名单、仅检索无候选、查询长度上限、短知识问题预筛，以及私聊最终回复能收到已确认知识条目。DSH 已报告候选发现阶段六项检查全部通过；本轮私聊检索管道仍待专项验收。
