## 0. 一句话·

一个以小鲸鱼为主体的 AI 成长空间：**角色管设定与记忆，渠道只管收发**。当前主要交互入口为 QQ 群、QQ 私聊与网页工作台；B站值班能力仍存在于现有代码，但已决定整体移除，待清理完成后不再作为项目渠道。

规模：**216 个接口 / 52 个页面文件 / 68 张表 / 86 个迁移 / 256 个测试脚本**。

统计口径（2026-11-16 实测）：`server/api/**/*.ts` 端点数、`app/pages/**/*.vue` 页面文件数（含 bili 下的弹窗子页）、`prisma/schema.prisma` 的 `model` 数、`prisma/migrations/` 迁移目录数、`scripts/test-*.ts` 测试脚本数。旧版写的 122 / 32 / 32 / 40 是 10 月底的口径，一个半月翻了一倍多。

### 整体清理范围与顺序

1. **依赖盘点**：全仓搜索 `bili` / `Bili*` / B站专属配置与脚本，区分 B站专属实现和通用渠道、记忆、身份、调度基础设施；重点检查 QQ 群聊触发 B站值班的入口。
2. **前端入口**：删除 B站页面、菜单、组件、弹窗及相关导航入口。
3. **服务端能力**：删除 B站 API、专属服务、渠道适配器、消息处理与专属事件逻辑；保留其他渠道使用的通用 pipeline。
4. **后台执行**：删除 B站专属 scheduler、worker、定时任务、启动脚本与 watchdog 分支，不影响记忆等通用任务调度。
5. **数据与配置**：检查 `Bili*` 专属 Prisma 模型、外键、迁移、连接配置、环境变量、凭证与本地数据。确认无其他功能依赖后再移除 schema/迁移代码；不得未经用户确认清空已有数据库中的历史记录或账号凭证。
6. **配套清理**：删除 B站专属测试、依赖安装说明、菜单文案和仍把 B站列为现行能力的文档；纯历史设计记录可标注为已废弃/仅供追溯，不必为追求全文零命中而破坏历史背景。
7. **回归验收**：运行类型检查、lint、构建及受影响的 QQ、通用渠道、记忆任务和数据库测试；确认没有悬空引用、残留启动进程或失效环境变量。

### 未来重新接入原则

当前不保留旧 B站值班系统作为长期维护负担。未来当小鲸鱼确实需要 B站能力时，重新评估成熟插件或直接调用 B站 API，只实现明确需要的最小能力；不默认复刻当前整套值班、报告、评论与后台调度系统。

## 15. 如果要对外讲，最能打的 10 个点

按「别人没有 / 有也不好讲」排序：

1. **周期不是保留期** —— 周期只决定「多久复盘一次」（默认 3 天、上限 8 天），原始消息保留期是另一个开关。
2. **四层记忆各管一件事** —— 原文是证据，忆泡是事件，快照是结论，长期记忆是现状。
3. **重新生成不覆盖** —— 新版本 + 旧版可追溯 + 人工修正留审计。
4. **删除不抹历史** —— 删掉原始消息，历史快照里的文字仍在。
5. **忆泡不伪造精度** —— 只知道「下午」就记「下午」。
6. **群聊按话题不按人** —— 判断的是「这个话题现在要不要我」，不是「这个人我认不认识」。
7. **主动找人先判后说** —— 闸门是纯函数，一次 tick 判定成本为零；顺序把配置问题排在时间问题前面。
8. **语音尾巴补 0.7 秒静音** —— 不是音质问题，是 QQ 时长取整会切掉最后半句。
9. **日记允许 SKIP** —— 没内容就不写，不为了填满栏目硬编。
10. **watchdog 指向具体环节** —— 不只报「有异常」，而是排期 / Worker / 任务三者之一。
