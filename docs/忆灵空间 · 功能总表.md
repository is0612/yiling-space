## 2026-11-24 更新摘要

本轮从一个具体的故障现象出发（私聊两次没回话、她反复说看不到自己画的图），把「记忆过期 — 画图链路 — 失败兜底」三件事一起收了口。全部经过本地检查与构建，未做真实供应商端到端验收。

| 改动 | 落点 | 说明 |
| --- | --- | --- |
| 失效记忆体检 | 长期记忆页、忆泡日历页 | 模型只提名、人工勾选后批量标失效 / 归档；短 id 白名单、置信度下限、偏好与关系不接受「过期」，全部可恢复 |
| 本机引擎用形象档案 | 画图链路 | 挑一张参考图走图生图（`/upload/image` → `VAEEncode` → `KSampler`），`denoise` 可配，`mode` 记真实值 |
| 提示词翻译容错 | 本机引擎 | 认两行协议 / JSON / 围栏 / 中文标签名，失败重问一次，缓存只存成功结果 |
| 模型失败兜底 | QQ 私聊与被 @ 的轮次 | 模型整轮失败时发一句诚实的短句，不再静默；落库标记为服务端代发，画图 / 语音 / 表情一并跳过 |
| 运行状态不编造 | 聊天提示词 v89 | 「不限张数」不再以数字 0 交给模型；禁止声称查过后台、禁止复读自己上一轮编造的张数与冷却 |
| 提示词版本 | `conversation-retrieval-v89` | 版本断言、首行 marker、验收文档同步更新 |

规则细节见 [记忆系统 §4.1](memory-system.md)、[画图](image-generation.md)、[工程教训 3.28–3.30](engineering-lessons.md)。

**下一次可接着弄（都不是阻塞项）**：

1. 体检还会提名少数边界候选（群内玩笑 / 关系类条目），可考虑把置信门槛从 0.65 提到 0.70，或让「主体是长期设定」的判据再硬一点；
2. 翻译两次都失败时目前仍按原文出图，可评估改成「如实说明这次没生成」，代价是要翻掉一条既有产品约定与对应测试；
3. 临时进度与长期事实在写入时没有区分，都落在 `FACT`；若能从源头分开，体检的负担会小很多；
4. 角色卡 v8（形象档案、版本快照清单、表情包清单随卡走）已一并落地；换机器后参考图与表情包图片要重新上传，真实导入 / 合并的端到端验收仍待观察。

## 15. 如果要对外讲，最能打的 10 个点

按「别人没有 / 有也不好讲」排序：

1. **周期不是保留期** —— 周期只决定「多久复盘一次」（默认 3 天、上限 8 天），原始消息保留期是另一个开关。
2. **四层记忆各管一件事** —— 原文是证据，忆泡是事件，快照是结论，长期记忆是现状。
3. **重新生成不覆盖** —— 新版本 + 旧版可追溯 + 人工修正留审计。
4. **删除不抹历史** —— 删掉原始消息，历史快照里的文字仍在。
5. **忆泡不伪造精度** —— 只知道「下午」就记「下午」。
6. **群聊按话题不按人** —— 判断的是「这个话题现在要不要我」，不是「这个人我认不认识」。
7. **主动找人先判后说** —— 闸门是纯函数，一次 tick 判定成本为零；顺序把配置问题排在时间问题前面。
8. **语音尾巴补 0.7 秒静音** —— 不是音质问题，是 QQ 时长取整会切掉最后半句。
9. **日记允许 SKIP** —— 没内容就不写，不为了填满栏目硬编。
10. **watchdog 指向具体环节** —— 不只报「有异常」，而是排期 / Worker / 任务三者之一。
