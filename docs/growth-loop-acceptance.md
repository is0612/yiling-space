# 反思 / 成长闭环验收

本阶段承接消费者验收提交 `ba757d8`，只推进经历、理解、成长候选、审核与后续读取。不开发自我认知、状态系统或向量检索。

## 既有链路与三层语义

- 原始经历：会话原始 USER / ASSISTANT 消息，保存实际发生时间。
- 短期理解：自动互动经验任务做有界批量分析，经原文引用、消息 ID、范围、来源与租约校验后，形成只用于原会话的可衰减经验。ACTIVE 经验不等于全局偏好，也不等于已确认长期成长。
- 候选成长：同会话多条独立反馈、跨真实发生日期的经验，进入已有反思队列。模型分别输出观察、推断和建议；仅符合表达领域与证据门槛的变化生成 PENDING 表达习惯，不直接升级为正式规则。
- 已确认成长：角色主人审核激活后，表达习惯才参与后续原会话 PRIVATE 读取；其他会话和群聊不读取这些私人派生习惯。停用或来源变化后按既有来源规则停止读取。

长期互动指导另走既有教育授权、候选及审核路径，不将私人经验原文复制到群聊或全局提示词。

## 本批实际发现的断点

真实模型首次验收成功提炼出三条 EXPRESSION 经验，也成功执行反思，但没有生成表达候选。合成输出显示模型认为证据“时间极短”，未达到跨时段标准。

原因是经验在同一批次入库，反思任务的 periodStart / periodEnd 是经验入库时间窗口；原始反馈虽然跨三天，提供给反思模型的来源没有这些实际发生时间。数据库排程依据原始消息日期通过，模型却拿到另一个时间口径。

修复：`collectExperienceReflectionSources` 增加从本会话真实 USER 消息读取的 `feedbackOccurredAt`，并在反思提示词中说明：批次窗口不代表经历发生区间，跨时段判断以原始反馈时间为准。

后续真实验收还暴露了两处协议歧义：反思输出示例没有列出可选 expression，模型可能只在 recommendation 描述稳定表达而不返回候选字段；经验分类未说明表达组织顺序与应对策略的区别，有一轮将同一表达反馈归为 STRATEGY，服务端因此正确拒绝表达候选。已明确可选 expression 的结构与省略条件，并说明语气、措辞、长短和说话组织顺序属于 EXPRESSION，处理行动才是 STRATEGY。模型仍负责语义判断，代码不强行改写类别。没有调整自动生效、角色归属、来源哈希或人工审核规则。

## 贯穿测试

新增 `test-growth-loop-db.ts`，接入既有一次性 PostgreSQL 反思测试入口：

1. 创建跨日的原始交互，包含普通笑声与三次明确反馈。
2. 执行实际自动经验 Worker；模型模拟器只选择有价值的三条，保存原文引用，普通笑声不形成经验。
3. 再次运行不重复分析或制造相同经验，反思任务重复排程也只保留一条。
4. 实际反思模型请求必须携带三天的原始反馈时间，不能用经验入库时间替代。
5. 反思生成 PENDING 表达习惯，审核前读取为空；主人激活后原会话可读取，其他会话及群聊为空。
6. 来源经验被停用后，派生表达习惯在下次读取中撤出。

测试使用 Mock 验证确定性控制与完整数据流，不以 Mock 证明语义判断。另增加非表达证据反例：即使模型给 STRATEGY 经验返回 expression，也不创建表达候选。

## 真实模型验收

在随机命名的临时 PostgreSQL 库中，以 `deepseek-flash` 实际执行自动经验提炼、反思与确认后的主回复，共三个模型阶段，均只使用合成资料；原始经验、审核状态与后续读取均由实际领域服务处理，没有向真实 QQ 或其他平台发送消息。

修复后得到三条经验及 PENDING 表达习惯。审核前稳定表达读取为空；角色主人激活后原会话读取成功，其他会话及 GROUP 为空。主回复先给出备份后升级的结论，再解释理由，模型自报引用该已确认规则。自报引用不等于普遍的行为因果证明，只作为本轮合成回复的对照证据。停用来源经验后，下次读取撤出该派生习惯。临时库在成功和失败尝试后均按 finally 清理。

该结果不代表全部自然纠正都能正确分类，也不代表反思每轮必须生成候选。证据不足、分类不匹配或存在反证时保留不产出是预期行为。暂不开发自我认知与状态系统。完整反思隔离库套件通过，覆盖本轮贯穿链路、已有来源审核、空/伪造来源、任务并发与 fencing、重试、投递及成长总览；教育迁移、记忆连续性回归、完整 TypeScript 和独立输出目录生产构建均通过。此前 Windows 生产包启动限制未重新验收，构建通过不等于该启动问题已解决。
