## 本轮修了什么

| 问题 | 当前实现 |
| --- | --- |
| 讨论画画或替别人画也触发生图 | 只解析真实用户文字主句，并逐条检查来源和收件人；不扫描视觉描述、引用、背景或整批聊天授权付费。 |
| 纯确认或只读 AI 绕进自主分支 | 自主生成也需要合格的新的人类文字；无图提议的普通确认、只读 AI、背景和面向别人的话不触发收费。 |
| 聊天正文被当作生图素材 | 删除整段聊天兜底；仅使用已核验请求的独立主体、确认过的提议或合法画面描述，调用前拦截聊天截图类素材及成员占位符。 |
| 确认漏判、未启动却让用户等待 | 支持有限前缀短确认及一次同人图片澄清；额度、配置、取消、过期、缺画面等有具体执行记录，明确阻断与状态查询使用服务端真实状态回复。 |
| 泛状态词误接画图 | “好了吗”“发了吗”等只有可核验近期画图上下文时才按画图状态处理。 |
| 多张自己的图混淆 | 新图保存实际 prompt、模型、生成时间及独立图片平台消息 ID；引用按角色、绑定和会话关联资产。 |
| 把生成意图说成实际画面 | requestedDescription 与 visual.description 分开，只有成功视觉观察能证明实际画面；送达也必须有独立回执。 |
| 表情包分对了仍主动复述 | 已知表情包默认不跑视觉、不向最终模型提供画面细节；明确问附件内容时才例外。普通图片不受此默认折叠影响。 |
| 长答复逐字复读 | 共用一次修复预算重试，计入所有实际用量；再次重复不原样重发长段落，短确认及用户明确要求重复例外。 |

## 下次启动时先确认

1. 正常启动 QQ 网关并确认对应账号在线，再确认适配器就绪；不要为本次验收额外启动第二个适配器。
2. 最新 `onebot-connected` 应晚于本次代码加载时间；进程存在不等于网关已连接。
3. 保留你原有的画图、看图及额度配置。若临时修改额度用于验证，结束后恢复原值。
4. 先验证负例，再生成一张正例。后续图片引用、提示词与回看尽量复用同一张新图，避免无谓消耗生图额度；明确看图可能使用现有视觉服务额度。

## 真实使用检查表

下列全部是待人工验收项，不能因为离线测试通过就预先勾选。

| 验收项 | 做法 | 预期 |
| --- | --- | --- |
| 普通讨论不出图 | 私聊或群里聊画画、询问提示词、说准备给别人画 | 可以正常接话，不应因此新生成图片。 |
| 群里请求对象正确 | 向另一成员讨论画图；再明确 @ 本角色请求一个简单场景 | 对别人的请求不截接；对本角色的合法请求通过配置和额度后才执行。 |
| 正常画图 | 请求一只动物或一个简单场景 | 正文与图片分开；一次要求不多生成；不会在未执行时宣称已经完成。 |
| 提议确认 | 她确实提出具体画面后，当前人在短时间内说“出吧”或“嗯嗯，画吧” | 可核验的提议被消费一次；无提议的普通“嗯嗯”仍按普通聊天处理。 |
| 澄清、取消与过期 | 提议后问一次参考图问题再确认；另检查取消或过期后确认 | 图片澄清不轻易丢提议；取消、已执行、过期或换人不能复用旧授权。 |
| 额度不足 | 利用已经生成的一张图临时设定达到当日上限，再提出请求 | 明确说没有开始及额度原因，不说“卡住了”“再等一会”；不额外调用生成接口。 |
| 查询状态 | 问最近图片是否画好；在无图话题中问“好了吗” | 前者依据实际任务与回执回答，后者不被硬改成画图状态；不会偷偷重画。 |
| 引用新生成的图片 | 引用这张新图，问内容或当时实际提示词 | 对应同一张资产；提示词来自生成记录，不靠临时编写；不会混同其他会话或其他图。 |
| 按需回看 | 开启看图后，明确问引用图或最近生成结果的画面 | 在本轮共享预算内观察或复用缓存；没观察到时如实说明，不把生图意图冒充像素事实。 |
| 表情与照片 | 普通聊天发表情包，再明确问表情含义；另发普通照片问内容 | 表情不被默认逐项点评；明确问图时才提供支持的信息，普通图片仍可据描述回应。 |
| 更正与复读 | 更正上一句表达，观察下一轮是否回应更正 | 不连续逐字重复上一段长答复；不把模型自责当成技术诊断。 |
| 能力边界 | 问是否使用原图编辑、是否靠文件夹权限自动看图 | 如实说明当前是文生图、参考图仅有文字摘要；视觉来自实际输入或按需观察。 |

## 哪些还不能当作已实现

- 当前没有真正把原始三视图传给生图服务，也没有图片编辑能力；本轮修的是如实说明能力，未新增图生图接口。
- 不默认每次生成后额外调用视觉；自己产物和引用图按需观察，与入站图片共用一轮三张预算。
- 旧图缺少真实 prompt 或平台消息关联时不猜测回填；不能要求新资产链凭空恢复旧数据。
- 自然语言识别仍有边界。陌生说法应明确未启动或需要澄清，而不是承诺后台继续工作。
- 长答复逐字重复的守卫不等于解决所有语义重复；模型对更正、身份和来源的理解仍需真实对话观察。

## 若仍有异常，留哪些证据

记录发生时间、所在私聊或群、触发文字、正文是否发出、图片是否发出及引用的是哪张；优先保留当轮日志。检查 `imageAttempt`、`image.generation`、`replyDelivery.image` 与调用详情中的最终回复是否一致。不要仅凭角色的“我画了”“我编辑过”“是我偷懒”等自述判定实际执行。

真实账号、昵称、群号、聊天原文和截图只留在本地忽略目录中，不复制到公开文档或提交。后续验收结果应单独追加日期、通过项、失败项和证据边界，不覆盖本次未验收状态。
