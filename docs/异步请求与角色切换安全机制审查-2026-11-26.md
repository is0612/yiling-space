# 异步请求与角色切换安全机制审查（定稿）

> 日期：2026-11-26　状态：**只审查，未改代码、未提交**
> 本文合并了初审与复审两份报告，结论以复审为准。初审中被推翻的条目见附录 A，核实范围见附录 B。
> 相关约定：[frontend-api-requests](frontend-api-requests.md)、[test-organization](test-organization.md)

## 结论

1. **不需要建立大一统的异步请求安全机制。** 项目在真正有竞态风险的页面上已经有成熟的防护和回归测试，现有约定也明确写了「并发序号与过期结果保护由页面负责」。
2. **竞态风险只在「切角色不重建页面」的那一类页面上。** 路径里带角色 ID 的页面切角色时会整体重建，不存在旧角色数据残留。
3. **确认的问题共 3 个低到中、5 个低，没有高或中。** 初审的两条「高」和一条「中」是误报。
4. **建议本期范围**：三处小修（开关进行中保护、日常生活的进行中标记、进度完成信号），外加把「按路由类型选防护级别」这条规则写进约定。

## 一、现状

### 1.1 请求层

统一入口 `createRequestClient`（`app/utils/request.ts:16-29`）只负责传输：路径规范化、参数映射、固定 `retry: 0`、透传 `signal` 与 `timeout`。错误提示、超时、取消都交给调用方，这是 `docs/frontend-api-requests.md` 的既定设计，不是缺口。

实际使用情况：只有 `app/api/roleplay.ts:25,27` 设置了超时（240 秒），只有 `app/api/model-logs.ts:147,159` 透传了 `signal`。

### 1.2 两类页面，防护需求不同

| 页面类型 | 角色 ID 来源 | 切角色时 | 需要的防护 | 例子 |
|---|---|---|---|---|
| 路径参数型 `/characters/[id]/**` | 路径参数 | **组件重建**，`onMounted` 重新加载 | 只需操作级防重复、卸载后不弹提示 | 梗语录、表情包、记忆周期设置、模型设置 |
| 查询参数型 `?c=` | 地址栏与 cookie | **组件不重建**，ID 响应式变化 | 请求序号、角色代际、卸载作废，三件都要 | 聊天、日记手账、日常生活、角色扮演、形象档案、成长系统各页、各 Workspace 组件 |

依据：Nuxt 默认的页面 key 是「代入参数后的路径」（`node_modules/nuxt/dist/pages/runtime/utils.js:7-13`、`page.js:97`）；侧栏切角色时会替换路径参数（`app/components/AppShell.vue:152-158`）。

这条规则是本次审查最重要的发现，初审的两条「高」都源于不知道它。

### 1.3 已有的防护模式（保留，不重写）

| 模式 | 位置 | 适用 |
|---|---|---|
| 代际 + 上下文比对 | `app/utils/chat-session-state.ts:13-31`，用于 `chat.vue` | 查询参数型页面 |
| 序号 + 角色 ID 双重作废 | `characters/[id]/settings/memory.vue:98-137` | 路径参数型页面；按 1.2 实际不会触发，属防御性代码 |
| 多序号 + 切角色全量作废 + 卸载作废 | `journal.vue:81-87`、`:493-527`、`:547-555` | 查询参数型复杂表单 |
| 代际 + 卸载标志 + 服务端回显校验 | `growth/index.vue:26-90` | 查询参数型页面 |
| 用 AbortController 代替布尔值防挂死 | `useMemoryProgress.ts:96-160` | 轮询 |
| 切角色时归零所有忙碌标记 | `CharacterModelSettings.vue:34-64` | 被 KeepAlive 缓存的组件 |
| 动作入口布尔守卫 + `finally` 复位 | `useMemoryActions.ts:47-133` | 触发后台任务的按钮 |

### 1.4 服务端

- **鉴权入口**：`server/api` 下 291 个文件中 265 个直接调用 `requireActor*`。不直接调用的 25 个里，日记组经 `requireJournalCharacter`（`server/utils/journal-api.ts:10-21`）、角色扮演组经 `roleplayApi`（`server/utils/roleplay-api.ts:7`）完成校验，登录、注册、健康检查本就公开。
- **角色归属**：接口层普遍写成 `character.findFirst({ where: { id, ownerId } })`，没有共享封装，靠开发者逐个手写。
- **幂等与并发**：快照、忆泡整理、聊天发送都有幂等键；后台任务有租约和 fencing token。这部分不需要动。
- **没有全局鉴权中间件**，`server/middleware/` 只有同源校验 `api-origin.ts`。

### 1.5 测试

竞态相关测试已经成体系：`test:chat-session-state`、`test:memory-progress-poll`、`test:page-harness`、`test:role-switch-lock-reset`，以及 memory、snapshot、days、journal、friend、knowledge、users、growth-deliveries、reflection 各自的 `*-page-races`。`test-role-switch-lock-reset.ts` 里的 `loadScript` 能直接执行 `.vue` 的真实脚本并挂起请求，是补新测试现成的工具。

## 三、建议统一的部分

只抽「会重复出现、且规则不显然」的东西，不造新范式。

1. **一条判定规则**：在 `docs/frontend-api-requests.md` 里写明「路径参数型页面只需操作级防护；查询参数型页面必须有序号、角色代际、卸载作废」。这条规则能直接避免初审那类误报，也能避免给设置页加无用的序号。
2. **行级进行中标记用集合，不用单值**。问题 1、2 都是同一个写法问题，两处各改几行。
3. **进度完成信号记录本轮全部完成项**。问题 3，改 `useMemoryProgress.ts` 一处，四个消费端按角色过滤的写法不变。
4. **给新的查询参数型页面提供一个泛型版的请求守卫**。现有 `createChatSessionState` 绑定了聊天上下文类型，需要先泛型化。**只供新页面使用，不迁移存量页面**。

## 四、不应统一或暂不改造的部分

| 项目 | 理由 |
|---|---|
| 存量页面的手写序号模式 | 已被 `*-page-races` 测试锁定，是资产；迁移的收益低于回归风险 |
| 统一默认超时 | `frontend-api-requests.md` 明确写了「长时间生成不设置统一短超时」，取消也不代表服务端没写 |
| `useMemoryProgress` 的轮询实现 | 是项目里防挂死做得最好的一处，保留并作为参照 |
| `useAsyncData` 的页面 | Nuxt 自带去重，不强行改成手写模式 |
| 服务端幂等、租约、fencing | 已完整，不动 |
| `memory-progress-jobs` 全局状态 | 面板需要展示所有角色的任务，是有意设计 |
| `settings/memory.vue` 的序号与 `watch(id)` | 不会触发但无害，不必专门删除 |
| 全局鉴权中间件、归属校验封装 | 值得做，但属于服务端鉴权治理，应单独排期 |
