## 第三批自然私聊复核：可空外部 ID 的历史筛选

v75 新样本仍未通过：第一问有认知视图，后续变化追问没有。只读重放同一私聊、同一时间点的历史查询发现，原查询 40 条全部为 USER，助手回复没有选回；改成空值安全的筛选后，选回 USER 与 ASSISTANT 各 20 条，上一条回复的认知标记可见，原样追问的判断立即通过。

根因是私聊已提前保存当前 USER 消息，查询使用 `externalMessageId NOT IN (...)` 来避免重复。但本系统生成的 ASSISTANT 消息没有平台消息 ID，值为 NULL；SQL 的 NULL NOT IN 不会返回 true，因此连历史助手回复也一并被排除。助词漏匹配也是问题，但上一轮仅用 Web HTTP 和独立触发函数验证，没有覆盖实际 QQ 管道的可空消息形状，未能发现这个独立断点。

本次只修数据过滤，不新增人格或证据提示词：查询仍绑定同一 conversationId，允许历史 NULL ID 行，继续排除当前输入 ID。新隔离测试直接执行实际私聊管道，验证先存下 NULL ID 助手回复，再收到原样变化追问；模型请求必须包含自己的上文和历史 NULL ID 用户消息，不能再次包含当前输入，并能继承认知视图。另一身份不能读到这些上文。测试使用真实数据库与回环模拟模型，不向真实 QQ 发测试消息。
