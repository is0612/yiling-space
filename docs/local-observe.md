# 本地只读观察（阶段三第一块）

> 状态：2026-11-20 第一版。只读、仅管理员、默认项目根目录；写文件/终端/Git 都还没接。

## 能做什么

- 管理授权目录（添加 / 停用 / 移除；移除不删磁盘文件）；
- 列出授权目录内的目录；
- 读取文本文件（≤256 KB）；
- 按文件名或内容搜索（最多 100 条结果）。

入口：系统管理 → 本地观察（`/local-observe`）。

## 授权目录

- 内置「项目目录」永远存在，不能移除；
- 管理页可以添加任意**已存在的绝对目录**（最多 20 个）；
- 添加时会拒绝：盘符根、`C:\Windows` / `Program Files` / `ProgramData`、整个用户目录、`.data` 运行时目录；
- 停用的目录不参与观察，可以随时重新启用；
- 移除只删白名单记录，不删除磁盘文件。

## 写文件（需审批）

管理员可以把某个授权目录改成「可写」；即使可写，她也不能直接落盘：

1. 她在桌面聊天里调用 `propose_file_write`，提交 `root / path / content / reason`；
2. 服务端创建 `PENDING` 写请求，检查目录可写、路径在根内、敏感文件/忽略目录、内容 ≤32 KB；
3. 管理页「写审批」里显示路径、原因、将写入的内容；
4. 管理员批准后才真正写文件；拒绝则什么也不写；
5. 批准时还会校验文件在请求后有没有被改过（`baseHash`），改过就失败，避免覆盖别人的修改。

写请求表：`local_write_requests`。工具结果只返回 `PENDING_APPROVAL`，不会返回“已写入”。

## 终端命令（需审批）

可写目录还可以执行终端命令，但同样不能直接跑：

1. 她调用 `propose_terminal_command`，提交 `root / command / args / cwd / reason / taskId`；
2. 只接受白名单可执行文件：`node`、`python`、`python3`、`cargo`、`go`、`dotnet`。此列表限制入口，不是系统级沙箱；批准前仍需核对实际参数和脚本；
3. 不经过 shell，参数是数组，避免 `&`、管道和命令替换；
4. 管理页「命令审批」里确认后才执行；
5. 输出、退出码、耗时写进 `local_command_requests`；关联任务会自动追加一条 `COMMAND` 验收证据，但**不会**替你判断任务通过/失败。

超时 120 秒，stdout/stderr 各截断 64 KB；超时会杀掉整个进程树。

## Git 仓库

在「本地观察」选择授权目录后点「Git」。可查看当前分支、工作区/暂存区改动清单，以及单个文件的工作区或暂存差异；未跟踪的新文件按新文件展示。仓库需有实体 `.git` 目录；不支持链接工作树或子模块。聊天工具只返回分支和文件清单。

可写目录允许提议新建本地分支，走「命令审批」。提议固定在当前提交；如果批准前 HEAD 已改变，需重新提议。批准不切换分支。暂不提供暂存、提交、删除分支或推送动作。旧版通过通用终端生成的待审批 Git 命令不能继续执行。

## 任务档案与验收

一条任务按「目标 → 计划 → 写请求 → 验收证据」串起来：

1. `create_local_task`（桌面聊天，管理员）建立任务档案；
2. `propose_file_write` 可以带 `taskId`，写请求创建后任务变成「待审批」；
3. 写请求批准后任务变成「进行中」；
4. 管理页「任务档案」里可以记录 `PASS` / `FAIL` 验收证据，任务相应变成「已验收」/「验收失败」；
5. 待审批或正在执行请求未处理完时，不能提交最终验收结论；已完成或已取消的任务不能再改验收结果；
6. 取消任务会撤销关联的待审批请求。若已有操作正在执行，等它结束再取消；取消不回滚已执行的操作。

当前验收证据有两种：写文件验收由你人工记录；终端命令执行会自动追加一条 `COMMAND` 证据（退出码、
stdout/stderr），但**不会**自动把任务标成通过——最终 PASS/FAIL 仍由你确认。这样避免把执行者
自己的说法或“退出码 0”直接当成功。

## 从聊天发起一次写入

在管理员聊天中说明文件应保存在哪里、内容是什么。单独的写入提议会自动建立任务、步骤和验收标准。进入「本地观察 → 写审批」，核对文件路径与正文后批准。批准后会打开这次任务，显示实际保存路径和从磁盘读回的内容（较长内容只显示预览）。系统检查的是磁盘内容是否与批准的内容一致；最后由你确认它是否符合原始需求。无需手填步骤。QQ 不接入这条流程。

聊天中会显示「本次会话的本地任务」结果卡片，打开页面时和每 5 秒自动读取状态，切回页面也会刷新。它只展示当前管理员、角色和会话关联的任务；磁盘读回内容作为系统执行证据展示，不冒充角色回复、不写入聊天消息或长期记忆。首次对话生成的提案会在该轮成功保存时关联新会话。若模型请求失败，会话没有建立，申请仍留在原审批面板中。

## 回到聊天续办

任务结果卡片上的「继续下一步」会发起原会话的一轮聊天。系统先校验任务仍属于当前账号、角色与会话，且没有待审批或执行中的请求；角色必须先通过 `read_current_local_task` 读取实际结果，才能提出后续写入或命令。新的申请默认关联原任务，相同已完成写入会被拒绝。后续写入仍单独审批，并增加新的写入与读回步骤。任务已结束时不能继续；如果目标已经完成，角色应说明结果并等待人工验收。

此版本是主动点击续办，不是后台无人值守循环。重启后任务和证据仍在，重新打开原会话可继续。输入框有未发送文本时不会覆盖它。

## 多步骤任务

在「任务档案」选一个未结束的任务，点击「建立步骤」，每行填一个步骤。步骤一次建立，最多 20 项。当前步骤可以记录完成或失败，也可以关联本任务已有的写文件或命令审批。关联后，步骤状态以实际审批和执行结果为准。前一步完成后才能记录下一步，所有步骤完成后才能验收通过。

这是任务跟踪，**关联步骤不会提交审批或执行操作**。审批仍在原有面板中完成。旧任务无步骤时沿用原流程。

## 浏览器只读观察

「本地观察 → 网页观察」输入公开网址，可查看独立 Chromium 会话的截图和渲染后文字。复用本机安装的 Chrome 或 Edge 程序，但不使用你的日常浏览器窗口、用户资料、登录 Cookie。观察结束即关闭会话；截图只返回当前页面，不保存到数据库。

管理员桌面聊天也可使用 `observe_public_browser`，但只能观察用户本轮明确提供的精确 URL。模型获得渲染后文字，管理员手动观察时可看到截图；纯文本模型不会直接看图。QQ 不提供这个工具。

所有页面资源都经 DNS 固定与公网校验的下载器转交浏览器。只允许指定来源的 GET；不跟随跨来源重定向，不转发登录和认证信息，阻止提交、WebSocket、弹窗、下载和嵌入子页面。跨站图片或脚本不会加载，因此部分网页不完整。没有登录、点击、填写等操作接口。单次最长 25 秒、最多 40 个页面请求，可见文字最多 6000 字符。

回归：`yarn test:browser-observe` 使用真实浏览器和离线网络夹具，需本机已安装 Chrome/Edge；不访问真实 QQ 或付费模型。

## 网页操作（需审批）

「本地观察 → 网页操作」审批她提出的页面操作。步骤只有四种：按选择器点击、按文字点击、填写输入框、滚动。每次最多 10 步；某一步找不到元素就停下，不会带着错位的页面继续下一步。

批准后才执行，而且只在这一次独立浏览器会话里生效：

- 提交按钮、`input[type=submit]`、密码框、文件上传直接拒绝；
- 响应头带 `form-action 'none'`，即使点到提交也不会把表单发出去；
- 所有非 GET 请求在路由层被拦，跨站、弹窗、下载、WebSocket 同样被拦；
- 每一步和最终页面标题写进任务证据（`BROWSER`），最终验收仍由你确认。

聊天里她只能用 `propose_browser_actions` 提交申请，网址必须是你本轮消息里给出的那个。QQ 不提供该工具。

批准网页操作前可以点「先看页面」，用同一个只读入口渲染一次页面再看截图，确认选择器和文字确实存在，避免批准一个指向不存在元素的步骤。这个预览是只读的，不会执行申请里的任何步骤。

聊天结果卡片除了写文件和任务，也会列出本会话的网页操作及其状态。属于某个任务的待批网页操作会挡住「继续下一步」；没有关联任务的独立请求只显示状态，不冻结任务。

## 边界

- 接口只接受相对路径，绝对路径、`..`、根外符号链接都会被拒绝；
- 以下目录不进入观察范围：`node_modules`、`.git`、`.nuxt`、`.output`、`.data`、`dist`、`backups` 等；
- `.env*`、`*.key`、`*.pem`、`credentials-encryption.key`、`onebot-*.json` 等敏感文件不可读、不可写；
- 二进制文件不预览；超过 256 KB 的文件不预览；
- 读工具只读；写文件必须经过审批，且只能覆盖已存在的授权目录内文件或新建文件；
- 终端命令必须经过审批，只允许白名单可执行文件，不走 shell；
- Git 查看只读工作区与暂存区；新建分支必须单独审批。

## 审计

每次列表/读取/搜索会追加一行到 `<data>/local-exec-audit.jsonl`，包含时间、管理员 ID、动作、路径
和结果摘要；不记录文件正文。这个文件不是长期记忆，也不会自动进入提示词。

## API

- `GET /api/local/observe/root`
- `GET /api/local/observe/roots`
- `GET /api/local/observe/list?rootId=&path=`
- `GET /api/local/observe/read?rootId=&path=`
- `GET /api/local/observe/search?rootId=&q=&path=`
- `GET/POST /api/local/roots`
- `PATCH/DELETE /api/local/roots/{id}`
- `GET /api/local/write-requests?status=PENDING`
- `POST /api/local/write-requests/{id}/approve`
- `POST /api/local/write-requests/{id}/reject`
- `GET /api/local/command-requests?status=PENDING`
- `POST /api/local/command-requests/{id}/approve`
- `POST /api/local/command-requests/{id}/reject`
- `GET/POST /api/local/tasks`
- `GET /api/local/tasks/{id}`
- `POST /api/local/tasks/{id}/evidence`
- `POST /api/local/tasks/{id}/cancel`

全部仅管理员可用；契约见 `docs/openapi.yaml` 的 `LocalObserve` 路径。

## 她能用吗

可以，但只在**桌面聊天**里，且只有管理员：

- 管理员在桌面聊天时，模型会拿到 `list_local_roots` / `list_local_directory` / `read_local_file` /
  `search_local_files` 四个只读工具；授权目录开启可写时还会拿到 `propose_file_write` 和
  `propose_terminal_command`（都只提交审批，不直接执行）；
- 工具只能访问「授权目录」里的内容，走的还是同一套根目录白名单、敏感文件过滤和审计；
- QQ / 群聊不启用本地文件工具，避免群里的人借她读本机文件；
- 写文件只能提交审批，不能直接写；QQ 也不启用写工具；
- 每次工具调用写 `<data>/local-exec-audit.jsonl`，`source: "chat"`；
- 单轮聊天最多 4 次工具调用，允许逐次执行 4 个回合；查询目录后仍可提议写入。该限制按实际调用数量计算，不再在第 2 回合后强行关闭工具。
