# 轻量角色扮演

角色扮演入口在工作空间的日记手账下方。采用独立双人聊天，不引入世界书、GM、头像、玩家面板、工具或成长系统。

## 人设与存档

人设只包含名字、人设正文和可选开场白。同一人设可创建多份独立存档。存档复制创建时的人设；修改人设不自动改变旧存档，只有点击「应用新人设」才更新它。删除人设保留存档和人设快照；删除存档则连同该存档消息删除，并解除相应 QQ 扮演绑定。

模型配置按登录用户独立保存，所有扮演人设共用：接口地址、模型、密钥、思考、温度、输出上限、模型上下文容量、输入预算与近期消息条数。密钥服务端加密存储，读取设置只返回是否已配置。不自动沿用日常角色密钥，换接口时请核对密钥。

## 上下文与压缩

每轮只装配本存档人设、较早聊天摘要、近期 user/assistant 原文。不查询主人格记忆、表达习惯、关系、日记、忆泡；不调用语境助手或记忆助手。扮演消息和命令回执存入独立表，不进入日常 `messages`，不会被现有记忆、反思和成长任务消费。

超过近期条数或输入预算时，使用同一扮演模型压缩较早内容。完整原文始终保留，摘要仅影响后续模型上下文。压缩失败不覆盖旧摘要，也不删除原文；无法在预算内发送时返回明确错误，不默默丢弃故事。输入预算需为输出和安全余量留空间；token 数量为保守估计，实际分词因供应商而异。

每个存档有持久化处理租约，网页和 QQ 同时发送不会交错写入。每条发送带 requestId，相同编号重试不会重复追加已经完成的消息；未回答的用户消息保留，须先重试完成，后续不同请求不能跳过它。

## QQ 主人私聊

第一版只支持 QQ OneBot 主人私聊。主人依据连接配置中的 ownerQq 与真实发送账号精确匹配，不能凭聊天正文、自称或提示词里的 isOwner 判断权限。群聊不启用。

- `/扮演 列表`：列出最近 50 个人设及编号。
- `/扮演 开始 人设编号或名称`：新建存档并切入。
- `/扮演 存档`：列出最近 30 份存档。
- `/扮演 继续 存档编号`：恢复已有存档，网页和 QQ 可使用同一份存档。
- `/扮演 状态`：查看该私聊当前使用的存档。
- `/扮演 退出`：退出并保留存档，后续回到日常聊天。

编号是 UUID 前 8 位；仅唯一匹配时接受。重名或前缀冲突时不会猜测。更多人设与存档可在页面查看；完整 UUID 也可使用。命令由代码解析，普通聊天里的「结束」等词不会自动退出。

切换按 QQ 绑定和私聊窗口分别持久化，重启不丢失，不会让另一个 QQ 或群聊跟着切换。扮演期间同一私聊窗口暂停日常主人格主动找话，避免打断故事；QQ 空间审批口语也不会在扮演对话中误触发。切换命令有持久化回执，网关重投不会重复创建存档。扮演已开启时，生成失败也不会退回日常管线保存这条消息。第一版只生成文字，不接图片理解、语音、表情或本地工具。

## 存储与部署

新增 `roleplay_settings`、`roleplay_personas`、`roleplay_sessions`、`roleplay_messages`、`roleplay_routes`、`roleplay_channel_receipts` 表，所有读写按当前用户授权，不与日常角色记忆范围混用。角色关联只用于用量归属，不表示能读取该角色的历史或人设。

部署需先执行 Prisma migration。设置和存档随 PostgreSQL 备份，密钥解密仍依赖原安装的凭据主密钥，换机按本地开发与迁移规范一并迁移。模型用量单列「扮演聊天」「扮演压缩」。本功能不改变模型供应商本身的内容规则。
