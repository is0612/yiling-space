# 形象档案统一验收清单

本清单用于功能分支 `feature/character-visual-profile` 合并前的本地统一检查。不要只跑新增单测；需要验证迁移、角色隔离、页面状态和真实生图链路。

## 1. 数据库与生成代码

在项目根目录执行：

```bash
yarn db:validate
yarn db:generate
yarn db:migrate:deploy
yarn prisma migrate diff --from-config-datasource --to-schema=prisma/schema.prisma --exit-code
```

确认三条新增迁移按顺序应用：
- `20261123120000_character_visual_profile`
- `20261123123000_visual_outfit_default`
- `20261123130000_visual_version_archived`

如果 schema diff 报错，先判断是否为本分支新增模型/字段造成。当前已知一次 GitHub Actions 检查曾在既有 `character_expression_habits` 表上报告缺少 `(characterId, reviewedBy, reviewedAt)` 索引；这不是形象档案迁移，但会使完整 schema diff 失败，需要单独确认 main 的迁移状态。

## 2. 自动检查

```bash
yarn test:visual-profile-prompt
yarn lint
yarn typecheck
yarn build
yarn test:all
```

如果项目日常流程要求先运行 `yarn check`，也一并执行。测试失败要记录具体命令、首个错误和是否为既有问题，不要只报告“检查未通过”。

## 3. 页面与数据验收

### 角色隔离
- 选择角色 A，填写核心外貌与提示词，保存草稿。
- 切换角色 B，确认页面没有显示 A 的核心资料、造型和图片。
- 用 B 的会话/请求尝试访问 A 的素材 URL、版本 ID、造型 ID；服务端必须返回 404/拒绝访问。
- 切回 A，确认资料仍存在。

### 草稿与正式版本
- 保存核心提示词后，出现新的 DRAFT 版本。
- 不发布草稿，先触发一次生图；正式版本为空时只使用本轮场景，不应读取草稿。
- 发布草稿后，检查当前正式版本号推进。
- 再保存一份不同的草稿，确认未发布时生图仍使用上一个正式版本。
- 发布新草稿后，旧的未发布草稿应归档，不应继续作为可发布的当前草稿。
- 恢复一个历史版本，确认只创建新草稿，当前正式版本号不变；再次显式发布后才改变。

### 服装造型
- 新增两套造型，分别设置和取消默认造型。
- 保存造型变更后确认产生草稿。
- 发布后，未指定服装的生图应加入默认造型。
- 在本轮场景明确写出另一套服装（如“换上红色礼服”）时，应以本轮服装为准，不应同时拼入默认造型。
- 编辑、删除造型后，确认草稿快照和页面列表一致。

### 参考素材
- 分别上传 PNG、JPG、WebP，确认可预览、分类与标签正确。
- 上传伪装成图片的非图片文件，服务端应拒绝。
- 上传超过 12MB 文件，服务端应拒绝。
- 确认图片被转换成最长边不超过 1600 的 JPEG，并写入当前角色的数据目录。
- 删除素材后，数据库记录和磁盘文件都应清除。
- 角色 B 不得访问角色 A 的素材预览接口。

## 4. 绘图链路验收

- 群聊和私聊都使用同一套生图流水线，确认正式形象提示词能进入最终生成 prompt。
- 确认只读取 `currentPublishedRevision` 对应的 PUBLISHED 快照，不读取 profile 当前编辑字段或 DRAFT。
- 没有正式版本时，仍能按原逻辑使用本轮场景提示词完成绘图。
- 读取档案异常时记录服务端警告，并回退到原有场景提示词；不能借用其他角色档案。
- 三视图图片当前只支持上传、存档和预览，不得把它描述成已传给生图模型作为参考图。

## 5. 合并门槛

只有以下条件都满足才把 PR 从 Draft 改为 Ready：
- 数据库校验、迁移和 schema diff 通过，或已明确分离并处理既有迁移漂移。
- lint、typecheck、build 和完整测试清单通过。
- 角色隔离、草稿/发布/恢复、图片上传和生图链路手工验收通过。
- `docs/形象档案设计.md` 与 `docs/image-generation.md` 保持同步。

当前分支不应直接合并到 main。
