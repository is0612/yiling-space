# 从群聊积累接话经验：分步开发方案

状态：待开发。本次只交付方案，不改运行逻辑。阶段规划不代表后续阶段已经获准执行。

## 1. 已确定的目标

角色在不同群里旁观聊天，逐渐积累可迁移的接话经验，用自己的口吻组织内容。学习包括理解对方需要什么、补充缺失信息、承接玩笑、适度解释、承认误会与结束话题；自然程度不能用固定字数或标点率代替。

- 群是观察来源，不是口吻作用域。同一角色跨群积累，形成的通用习惯可用于其他群和私聊；仍遵守已有私人记忆隔离。
- 不恢复固定对话示例，不自动改基础人设，不要求用户持续手填规则，不模仿某个发言人的人格。
- 复用成长系统语言领域，在现有习惯前增加观察积累层；成熟结果继续走现有审核、版本和应用流程。
- 不修改模型权重。持久经验通过上下文影响输出，不宣称模型已经训练或保证越聊越自然。
- 不默认扩大群原文留存，不抓历史，不向真实群发送测试消息。

整体属于中等规模改动，涉及数据库、后台任务、来源校验、接口、页面与效果验收，不能只放宽一段提示词。

## 2. 核对后的现状

| 环节 | 当前实现 | 局限 |
| --- | --- | --- |
| 自动扫描 | `server/utils/group-observation-automatic.ts` | 按群启用，只扫描启用后、最近一天内已记录的新消息 |
| 选片段 | `selectAutomaticGroupWindow` | 引用链，或带明确确认措辞的往返，不是通读全部聊天 |
| 证据 | `server/utils/group-expression-evidence.ts` | 前因、接话、后续三个锚点；最多十二条、十五分钟；排除角色参与、已知 AI 和系统播报 |
| 分析 | `server/utils/group-expression-observation.ts` | 一个片段直接提出一条习惯，没有独立观察记录 |
| 保存 | `saveGroupObservationHabit` | 去同来源重复及部分完全相同候选，没有多次证据归并 |
| 审核 | `server/utils/expression-habits.ts` | 待确认、启用、驳回、停用、历史版本与审计；另有显式点击自审 |
| 聊天应用 | `server/utils/expression-habit-retrieval.ts` | 共用读取、场景词项匹配；最多六条、八百序列化字符预算 |

需要澄清：

- 当前每群两次模型尝试至少间隔半小时，不是半小时允许两次。
- 当前会过滤已知 AI。其他机器人的聊天可用于人工研究效果，但本方案首版不默认放开 AI 互学；如需支持指定 AI 来源，单独设计授权与避免循环学习。
- 模型自报 `usedExpressionHabitIds` 不能证明是否真正受影响或改善。历史长度统计还受时间、场景、分条落库影响，不能据此推断外部系统采用了微调。
- 现有记录策略可能导致旁观素材不足。扫描没有材料、选不到片段、分析跳过应分别展示，不能统称“模型没学到”。

## 3. 目标流程

`已启用群的新记录 → 有界片段 → 单次观察 → 角色级经验主题 → 多次独立证据 → 待确认表达习惯 → 现有审核 → 共用聊天应用`

### 单次观察

观察保存抽象场景、接话方法、适用边界、来源引用和指纹、分析版本，以及后续证据分类：

- `SUPPORTED`：有可对应的明确承接。
- `CONTRADICTED`：有能对应到这次表达的明确纠正或否定。
- `UNKNOWN`：没有足够可见后续。

没有后续也能观察可理解的接话方法，但只能标 UNKNOWN，不能增加成功计数。沉默、回复速度、笑脸或同意次数不能直接当成功或失败。这些分类描述证据，不证明表达造成了某个结果。

缺图导致内容不可理解、指代不清或系统播报时跳过。只学习表达行为，不把群友事实、立场、关系或具体命令转成习惯；不存可照念的原话副本。

### 经验主题

同角色按“相同场景、相同接话方法、相容边界”归并，不按群归并。都是短句不等于同种经验；补信息与安慰不能仅因措辞接近就合并。

代码负责唯一键、重放、重叠窗口、时间和数量上限；模型只判断语义是否相同。模型从有限现有主题中选择或建议新建，归并目标 ID 必须在白名单内，不能任意修改记录。

独立证据按接话消息去重；窗口共享核心消息时不能增加独立计数，同一谈话拆窗不涨分。跨群不是成熟条件，同群不同时间的独立对话也可支持同一主题。

提案门槛建议初值：至少三次独立观察，跨至少两个角色当地自然日，其中至少两次有明确支持，且没有未处理的明确反证。数字属于待验证的服务端参数，不是科学上“已经学会”的判据；UNKNOWN 既不支持也不反对。

### 习惯提案

达到门槛只创建一个 PENDING 习惯，默认 ALL，无原会话限定。聊天只读抽象习惯，不读来源群、原话和成员身份。

- 每个主题只允许一个当前提案；并发和重试不得重复生成。
- ACTIVE 正文不被新观察直接覆盖，修订另走待审建议和版本记录。
- 驳回、停用保留标记，不得换一种措辞反复提案；重新开启需显式操作。
- 保留现有人工确认和显式点击自审，不新增无人值守自动采纳。
- 实施时验证 TONE / WORDING / LENGTH 是否能准确容纳接话方法；确需新类型时同步契约和迁移，不把所有方法强塞为用词规则。

## 4. 数据设计草案

名称为建议，正式字段与约束在阶段 A 开始时细化。

| 实体 | 职责 | 关键约束 |
| --- | --- | --- |
| `GroupExpressionObservation` | 单次抽象观察、证据分类、来源指纹、分析版本 | 角色、接话消息及分析版本幂等；不得直接进提示词 |
| `ExpressionLearningTopic` | 角色级方法、场景、边界、状态、revision、关联习惯 | 跨角色不可归并；主题数量有界；版本化修改 |
| 主题观察关联 | 证据归属、独立性、有效性 | 不重复计票；有效计数可重算 |
| 提案记录 | 提案时主题版本和固定证据集合 | 一次版本最多提案一次；新增证据不静默改变待审正文 |

新增来源用版本化提案引用和指纹，不把不断增长的观察数组塞入习惯 sourceRefs。旧 GROUP_OBSERVATION 单片段来源保持旧校验，不伪造为多证据提案。

来源生命周期：

- 未采纳证据依赖原消息；删除、清理或改动后不再计数。首次采纳需在事务内重验有效来源、指纹、主题版本与提案门槛。
- 原文过期可能导致证据不足，显示“证据过期”，不默认延长所有群消息留存；指纹不等于仍可验证的原文。
- 已采纳习惯由语言领域独立管理，来源删除不连带删除习惯；历史界面标明来源不可回读。
- 观察保留期限、主题上限、失效重算与清理机制应在实现时明确，不无限积累，也不把观察写成长久事实记忆。

## 5. 开发顺序与止损点

### 阶段 A：观察积累与可见状态

最小切片：复用扫描、租约、游标、额度，增加观察表及角色级实验开关。新版自动路径只存观察，不直接产习惯；原手选流程保留。实验默认关闭，旧开关不自动启用新版；同一群同一时刻只有一个扫描模式负责消费。

先沿用原选片段规则，验证持久化闭环。语言页提供只读列表和扫描状态：最近扫描、扫描条数、可分析片段、跳过原因、失败、观察数量与证据过期，不将等待状态显示为“学会了”。

验收：重放不重复、双 Worker 不重复写；关闭、租约失效、分析中角色停用均阻止旧结果提交；跨角色和私人来源拒绝；无模型和超额度不丢待处理窗口；无新增习惯、无提示词变化。模型调用不持有数据库锁。

止损：积累为空时先定位记录覆盖、片段选择或分析原因，不继续做归并。

### 阶段 B：普通接话观察与主题归并

在阶段 A 可观测基础上扩展普通对话窗口，不再要求每次都有确认措辞；后续可未知。不能把所有相邻消息都当同一话题。

代码限定时间、条数、来源和确定引用关系；无引用、多人混聊时，由有界分析判断是否相关，歧义跳过，不对每条消息调用模型。加入白名单语义归并与独立证据计数。

每群沿用至少半小时尝试间隔；实施前增加有界的每角色每日分析和归并预算，防多群叠加失控。主题达到上限时暂停新建并报原因。

验收：同义方法可归并，不同场景与相反建议不合并；跨群可累计；重叠窗口不涨分；UNKNOWN 不增加支持；已知 AI、系统播报仍被排除；原文中的指令不能驱动动作。

止损：归并不可靠时保留独立观察，不拿错误归并推进提案。

### 阶段 C：多证据提案与审核连接

成熟主题创建待确认习惯，增加版本化来源校验，复用既有编辑、审核、自审与审计，所有入口用同一校验。

页面展示积累中、待确认、已采纳、驳回和停用，以及有效独立证据、日期覆盖、抽象原因和反证。群名只在拥有者溯源视图出现。

验收：门槛前不提案，并发只有一条；首次确认时失效来源或变更版本返回冲突；驳回不复活；旧手工、教育和原私聊经验不受影响；聊天不接收原话或来源身份。

止损：候选不具备可迁移价值时修正观察与归并过程，不扩大自动采纳。

### 阶段 D：聊天使用与内容效果验证

先沿用共用习惯检索，追踪形成、采纳、候选读取、词项匹配、预算排除、实际提供与自报引用。若证据确认词项检索漏召回，再单独改共用检索，不在网页与 QQ 分建规则，不直接增加每轮模型精排。

离线对照使用未参与形成经验的场景，覆盖补信息、解释、玩笑、误会修复、轻松回应及不宜插话；只给回复当时可见上下文，固定模型、人设和其他条件。

人工看是否接对人和话题、是否补到需要的信息、有没有硬加比喻和评价、重复、冒认身份或泄露。字数仅辅助，不作为通过线。合成用例可入库，真实片段仅放被忽略的本地笔记。真实模型调用先列预算，Mock 通过不表示语义效果通过。

止损：经验已提供却无稳定改善时保持实验状态，检查上下文与经验内容，不宣称已自然。

### 阶段 E：自身反馈修正，后续另行开启

先核对既有互动经验、“从反馈学习”和教育迁移职责，复用证据，不对同一反馈另建判断器。仅对可对应具体习惯的明确反馈提出修订或停用建议；自身反馈与旁观证据分开。

首版人工确认修订，不因沉默、速度或模型自报改变权重，不自动衰减 ACTIVE 习惯。无人值守采纳及自动权重不属于前面阶段隐含范围。

## 6. 工程约束与发布

- 新接口使用已有角色鉴权，列表分页；实施接口时同步 `docs/openapi.yaml`、DTO、Mock 与测试，本次不发布空接口。
- 新表、来源类型、状态及 CHECK 约束同步 Prisma migration 和所有解析器。旧数据不删除、不自动回填、不重写既有习惯。
- Worker 保持持久租约、fencing、有限重试；长任务续期或确保租约覆盖。关闭后再开启也不能让旧任务借新租约写入。
- 失败、合法跳过、额度不足分别记录；可重试任务与游标一起设计，不先推进游标再丢失结果。
- 禁用新版停止新产出，保留记录；已 ACTIVE 不自动停用。回切旧扫描需明确游标交接，不重置后反复消费。
- 更新 Worker 后新逻辑才生效；涉及适配器代码还需重启 OneBot，网页热更新不能代替。
- 本批不新增成长事件消费者。确需领域事件时再用事务 Outbox，只传引用。

## 7. 分阶段验证要求

| 类别 | 必须覆盖 |
| --- | --- |
| 正确性 | 独立计数、重放、重叠、跨日跨群、反向建议、反证 |
| 隔离 | 跨角色、私人来源、已知 AI、系统播报、群文本指令注入 |
| 生命周期 | 来源清理与修改、首次确认、采纳后独立、驳回不复活、旧来源兼容 |
| 并发 | 双 Worker、租约过期、关后再开、角色停用、重复提案、版本冲突 |
| 成本 | 无模型、日额度、角色预算、多群公平、有界主题、退避 |
| 效果 | 未见场景的内容与接话自然度、上下文完整性、隐私身份不退化 |

每阶段交付修改范围、迁移、实际检查、未验证限制、回退方式与下一阶段条件。按修改运行 typecheck、相关回归、隔离数据库迁移及并发测试、lint、build；改 Vue 加 `yarn check:sfc`；文档与注释跑 `yarn check:privacy`。测试命令以实施时仓库为准，未执行不得标通过。

建议下次只实施阶段 A。完成后先确认确实能积累有意义的观察，再决定阶段 B；不把五个阶段一次全部做完。
