# 形象档案

## 定位

形象档案是角色级的视觉身份资料库，为角色绘图、图片编辑与后续多模态生成提供稳定的视觉依据。它与角色设定、记忆、知识系统分离，不承担人格或经历记忆。

## 数据归属

- 所有资料必须绑定 `characterId`，沿用当前角色选择机制。
- 读取、写入、上传、删除和发布操作都必须在服务端校验当前用户对该角色的访问权限。
- 不允许仅凭前端传入的角色 ID 建立跨角色访问。
- 档案资料与原始图片资源应有明确的删除和引用策略。

## 资料结构

### 1. 核心形象

保存相对稳定的外貌特征：发色、眼睛、发型、体型比例、鲸鱼元素、整体视觉气质等。核心形象不包含某一套特定服装。

### 2. 造型

服装、配饰、发饰等作为独立造型记录。允许同一角色拥有多套造型，不应因换装覆盖核心形象。

### 3. 参考图片

图片需记录用途和排序，至少区分：
- 标准形象图
- 三视图：正面、侧面、背面
- 表情参考
- 服装与配饰参考
- 其他补充素材

图片资源应走项目统一的安全上传与本地数据目录机制，不把 base64 长期塞进业务表，也不依赖临时浏览器缓存。参考素材单独存放于 `.data/visual-profile/<characterId>/`，与生图结果目录隔离。

### 4. 绘图提示词

分开保存：
- 核心形象提示词
- 当前造型提示词
- 负面提示词
- 场景/动作扩展提示词

拼装时应保持“核心形象 + 造型 + 场景”的层次，不把所有内容合并成一段不可维护的大提示词。

### 5. 版本与确认

- 编辑先形成草稿。
- 只有用户明确确认后，草稿才成为当前正式版本。
- 历史正式版本可查看、恢复；恢复也应产生新的版本记录，不能抹掉历史。
- 绘图生成结果默认只是候选素材，不自动覆盖正式形象。
- 版本记录创建时间与版本说明；参考素材记录用途、标签和文件元数据。

## 绘图 API 集成

绘图调用应通过统一的档案提示词组合函数读取当前角色当前正式版本快照。没有正式版本时仅使用本轮场景提示词；读取异常时记录服务端警告并回退到现有调用方式；不得静默使用其他角色的资料。

推荐组合顺序：
1. 核心形象（外貌设定 + 核心提示词）
2. 当前默认造型提示词
3. 参考图说明（标明每张图只取什么，以及“姿势表情按文字重新安排”）
4. 场景与动作提示词
5. 负面提示词（作为自然语言“避免……”拼入 prompt，不是独立模型参数）

### 参考图怎么进模型

- 只取标准形象与正面/侧面/背面三视图，最多 4 张；表情、服装、配饰不发送——表情由画面决定，服装由造型负责。
- 仅在角色已有正式版本时使用，保证“没有发布就完全不碰档案”。
- 两种形状轮流试、不按服务商预判：先 `/images/edits`（multipart），路由不存在再试 MiniMax 的 `/image_generation` + `subject_reference`（只吃一张，说明段会同步裁成一张）。
- 参考图说明按字符预算判断：塞不下就**不带参考图**，绝不发一张没有约束的图。
- 任何失败（无该接口、参数被拒、超时）都回退纯文字生成，并记 `[image]` 警告；回退后 `imageGeneration.mode` 仍记 `text_to_image`，不说假话。
- 参考素材目前不在版本快照里，因此改动立即生效，不受草稿/发布约束。

私聊/群聊等不同入口不应各自复制一套形象拼装逻辑。

## 页面与菜单

- 菜单：工作空间 → 形象档案
- 路由：`/visual-profile`
- 使用全局当前角色选择器，页面内容随角色切换。
- 页面分区：概览、核心形象、造型、参考图片/三视图、绘图提示词、版本历史。

## 当前实现进度

已完成：
- 工作空间菜单入口与 `/visual-profile` 页面。
- Prisma 模型：角色档案、参考素材元数据、服装造型、不可变版本快照。
- 角色归属 API：读取与保存草稿均先校验当前用户拥有该角色。
- 保存核心提示词、服装造型变更和历史恢复都会产生新的草稿版本；只有显式发布接口才推进 `currentPublishedRevision`。发布时其他未发布草稿会归档，避免旧草稿误覆盖新版本。
- 页面已接入核心外貌、核心提示词、负面提示词编辑、草稿保存、显式发布和最新草稿恢复。
- 已增加参考图片上传、服务端解码与缩图（最长边 1600、JPEG q88）、角色目录隔离存储、私有预览和删除接口。素材元数据仅保存相对路径，不保存 base64。
- 已增加服装造型新增/编辑/删除、默认造型设置和历史版本恢复（恢复产生新草稿）。
- 现有群聊/私聊共用的生图流水线会读取当前角色的正式版本快照，将核心形象、默认造型、参考图说明、负面提示词与本轮场景组合；不会读取草稿。
- 提示词已改为分段结构：`【人物】…；【造型·名称】…；【参考图】…；【画面】…；【避免】…`，长度预算画面与参考图说明优先、都不截断。
- 标准形象与三视图会作为参考图走 `/images/edits` 一并发出（最多 4 张，只取长相）；不具备该接口时自动回退纯文字，`imageGeneration.mode` 如实记录。
- 新增纯函数提示词组合测试脚本 `test:visual-profile-prompt`。

尚未完成：
- 参考素材尚未纳入版本快照；删除素材不会回滚历史版本中的图片集合。
- MiniMax 形状一次只吃一张参考图（服务商限制），多张素材时只用优先级最高的那张。
- 三视图仍需手动上传，没有“从图片/文字生成三视图”的链路。
- 本地 Prisma validate / generate、迁移的最终验收尚未运行（lint / typecheck / build / 单测已通过）。

## 实施顺序

1. 菜单与页面入口（已完成）。
2. Prisma 数据模型、迁移、角色级 CRUD、参考图片安全上传/预览/删除（代码已完成，待本地验证）。
3. 服装造型 CRUD、默认造型、版本草稿/发布/归档/恢复（代码已完成，待本地验证）。
4. 群聊/私聊共用生图流水线读取当前角色已发布快照（已完成）。
5. 参考图进模型（`/images/edits` + 说明段 + 回退，已完成）。
6. 本地统一执行 Prisma 校验、迁移、lint、typecheck、测试和手工验收。

## 明确不做

- 不把形象档案写入记忆或知识系统。
- 不让 AI 生成结果自动覆盖正式形象。
- 不强制每次绘图都使用同一套服装。
- 不将向量数据库作为本功能依赖。
