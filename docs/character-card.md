# 角色卡：导出、导入与删除

> 换电脑通常不需要搬整个数据库。角色卡带走的是「她是谁 + 她记得什么 + 她认识谁」，
> 账号、渠道 Token、任务队列和会话原文都留在原机器。
> 整库迁移见 [本地开发与数据迁移规范](local-development-and-data-migration.md)。

## 1. 导出

角色管理 → 选中角色 → 「更多」，两个入口：

| 入口 | 给谁用 | 区别 |
| --- | --- | --- |
| **导出角色（含朋友）** | 搬家自己用 | 朋友段里有别人的 QQ 号和「她怎么看他们」 |
| **导出（不含朋友，可分享）** | 发给别人 | 朋友整段不写进文件 |

## 2. 会带走什么

| 会带走 | 不带 |
| --- | --- |
| 人设、对话示例、称呼、别名 / 简介 / 头像配色 | API Key（导出的 JSON 里没有任何密钥字段）、渠道 Token |
| 长期记忆：角色全局 + **导出者自己的**私人记忆 | 其他站内用户的私人记忆 |
| 忆泡、忆泡日历（哪些天整理过、整理到哪一刻） | 会话原文、阶段总结的来源记录、任务队列、用量与审计 |
| 日记与手账：正文、今日想法、今日一句、标签，**含历史版本** | 日记/手账里指向原文与忆泡的 id（换台机器是死指针） |
| 梗语录、当前版本的阶段总结 | 会话原文、任务队列、用量与审计 |
| 模型名 / Base URL / 温度 / Token 上限等参数 | 表情包图片（换机器后在「表情包」里从 QQ 收藏夹重新同步） |
| **她的声音与说话方式**（v7）：语音开关与节奏、TTS 音色 / 语气指令、转写模型、表情额度、看图模型、私聊主动与群内冷场主动、四个后台助手的模型选择、日额度 | 四个后台助手的**启用开关**（会自己花钱跑流水线，必须由新机器的主人亲手打开）；自动收集 / 自动总结开关同理 |
| **表达习惯 / 目标 / 偏好**（v7）：她现在怎么说话、在追什么、追完过什么、喜欢与不喜欢什么 | 这些条目的「待确认」与「已否决」状态（本机的决策现场）、目标进展记录 |
| **形象档案**（v8）：形象描述、形象提示词与负面提示词、装扮列表（含默认那套）、发布过的每个版本快照、参考图清单（几张、什么用途、原图尺寸） | 参考图**图片本身**（换机器后照清单重新上传）；版本快照里的素材 id 与磁盘路径（旧机器的，搬过去是死指针） |
| **表情包清单**（v8）：名字、什么时候用、开关状态、来源 | 表情包**图片本身**（条目会建成「缺图」并先停用，补图后自己打开） |
| **她的朋友**（默认带）：昵称、平台账号、她私底下的叫法（备注）、聊过几次、从哪认识、认识多久，以及她记得关于他们的 | 朋友的账号绑定（`status` / `linkedUserId`）—— 那是本站的验证结果，换人不该跟过去 |

## 2.1 语音、习惯与保留策略（v7）

v7 补的是「换台机器就换个人」的缺口，之前只带 9 个模型参数，带过去的是一个不会发表情、不主动开口、声音退回默认音色的版本。

- **设置**：`modelConfig` 白名单从 9 个键扩到全部非密钥设置（语音、TTS 音色与语气指令、ASR、表情额度、看图、收集开关、主动节奏、四个助手用的模型与 Token 上限、日额度）。`*ApiKey` 一个都不进包，新机器上缺 Key 的表现和别的模型一样是「未配置」。`proactive` / `groupInitiative` 是对象，字段级白名单 + 范围收口（越界值 clamp，未知字段丢弃），不做整卡拒绝。
- **三段内容**：表达习惯（`ACTIVE` + `DISABLED`，被关掉过的说法带过去仍然关着）、目标与愿望（`ACTIVE` / `PAUSED` / `COMPLETED` / `ABANDONED`，「放弃过」「实现过」都是她经历过的事）、口味偏好（`ACTIVE` + `DISABLED`）。每条导入时补一条 `CREATE` 历史并把来源写成「来自角色卡」；本机的历史版本不跟卡走 —— 那些行记的是「谁在什么时候改的」，复制过去等于伪造审计。
- **记忆设置**：原文保留天数与自动清理开关随卡走（老卡没有这一段时沿用 30 天；永久保留时强制关掉自动清理）。
- **不带**：互动经验的原始行（它绑着具体会话与消息，ID 换台机器全是死的；她学到的准则以「互动经验 / 渠道策略」两段随卡走）、表情包图片（图不带，换机器后从 QQ 收藏夹重新同步）。
- v7 卡给旧程序读会被版本检查挡下并提示升级，不会静默丢掉这些段。旧 v1–v6 卡照常导入，新段为空。

## 2.2 v5 成长数据

角色卡v5新增成长段：知识候选、正式知识、历史版本与关联；朋友社交关系状态、经历、评估、审核、变化及证据；反思记录、建议及成长结论；能够关联到本卡领域对象的成长事件与投递历史。导入预览显示成长分项，结果显示实际新增量与迁移提示。旧v1–v4仍兼容，成长段为空。

含朋友导出用于搬家，社交记录只关联本卡已包含的朋友。不含朋友导出不带社交记录，并跳过无法确认来源公开有效的反思建议。CHAT知识、其他用户私人来源、来源未能验证的知识不会进入成长段；过滤与无法映射的事件会提示，不能当作完整数据库备份。知识只保留可验证的MANUAL/IMPORT及全局MEMORY_EVENT来源。

成长身份账本按角色、领域与原始ID映射新的本机ID；重复导入和A→B→A认领原记录，合并不覆盖本地知识/反思或关系现状。忆泡、总结与知识引用重映射；失效反思来源标记为无效并保留历史摘要，不能采纳为新证据。社交原文证据清单不随卡走，旧评估不会凭失效原文改变关系。

未完成反思与投递归档，不恢复执行租约、调度任务或自动副作用；导入历史不支持恢复旧任务执行，可重新发起业务操作。每表最多4000条、成长总计最多20000条、整卡32MB，超限拒绝而不静默截断。部署前先备份并应用`20261110060000_character_growth_portable`迁移，再更新Web/Worker。

## 2.3 形象档案与表情包（v8）

v8 补的是「她长什么样」。之前人设文字带走了、形象设定留在原地，换台机器她就画不出自己。

- **形象档案整段随卡走**：形象描述、形象提示词、负面提示词、装扮列表（名字、描述、默认标记、排序）、`currentPublishedRevision`，以及每个版本的快照（版本号、状态 `DRAFT` / `PUBLISHED` / `ARCHIVED`、备注、创建与发布时间）。
- **参考图只带清单**：几张、什么用途（正面 / 侧面 / 表情 / 配饰……）、叫什么、原图宽高。图片本身不随包走 —— 角色卡是纯 JSON，把图 base64 塞进来，一张卡就几十兆，还会撞 32MB 上限。
- **版本快照要先洗一遍**：快照里原本记着素材的 `id` 与 `relativePath`，那是旧机器的主键和磁盘路径。导出时只保留 `kind` / `label` / `sortOrder`，其余丢掉；导入端**一行素材都不建** —— 建了就是一堆永远打不开的图。
- **表情包只带名字与用途**：导入时建成「缺图」条目（`fileName` 为空、`sizeBytes` 为 0）并**默认停用**。缺图的条目一旦进入选图，她发出去就是一条发送失败，主人还看不出原因；补上图后自己打开即可。页面用 `hasImage` 判断，缺图显示占位块而不是破图。
- **合并口径**：本机已有形象档案时，形象文字一个字都不动（那是刚调好的），装扮按名字补缺（同名的保留本地那套），**版本历史不合并** —— 两边的修订号会撞，混在一起就说不清哪一版是哪一版。本机没有形象档案时整段导入。
- **知识主题**（成长包 v2）：自动整理出的主题、主题成员、主题修订随成长段走。成员按条目重新映射到本机新导入的知识；`MERGED` 状态的主题不带（它只是指向另一个主题的指针）。修订里的成员 JSON 快照不带，导入后只作为「改过什么」的历史。
- v8 卡给旧程序读会被版本检查挡下并提示升级。v7 及更早的卡照常导入，这两段为空。

## 3. 导入

角色管理页头「导入角色」→ 选文件 → 先看预检摘要（名称、记忆 / 忆泡 / 忆泡日历天数 / 日记手账 / 阶段总结 / 梗 / 朋友 / 互动经验 / 渠道策略 / 表达习惯 / 目标 / 偏好 / 形象档案 / 表情包的条数）→ 确认导入。

- **默认新建**：没有同源角色时，新建角色并在名称后加「副本」后缀，不覆盖已有角色。若识别到同一个同步根，可选择合并；本机存在多个同源副本时必须明确选择目标。
- 记忆与忆泡不带来源消息指针（原文没随包走），阶段总结导入后记为第 1 版。
- 忆泡日历按天落库：状态（整理中 / 已收口）、当天条数、上次整理时间都保留。老卡（v1）没有这一段，导入时按忆泡日期反推，日历上照样看得见那些日子。
- 日记 / 手账版本号原样保留（第 3 版还是第 3 版）；手账「今日一句」的来源按版本号重新指向本机新建的那一版日记，正文与「今日想法」都带过来。
- 朋友按 `(平台, 平台账号)` 认人：本机已有同一个 QQ 号就沿用那条身份，不会重复建，也不会改写它原来的验证绑定；0 次互动的关系（群里出现过但没被搭理的残留）不进包。
- 朋友的**备注**（她私底下的叫法）随关系一起带过来：导入时按保存口径清洗（切分、截断 12 字、去重、去掉与本名相同的叫法），v2 及更早的卡没有这一段，导入后就是空备注。

导入之后要做三件事：到「模型设置」重填 API Key，到「记忆设置」确认归档周期，到「表情包」重新同步；带形象档案的卡还要到「形象档案」把参考图重新传一遍（预览页会写明缺几张）。

## 4. 合并：同一份数据，两边各长了一段时间

典型场景：先在 A 机器养了几个月，导出到 B 机器继续养；过一阵发现两边都长出了新东西，想把它们合起来。或者反过来 —— 从 B 导出一张卡，并回 A 原来的那个角色上。

### 怎么认出「同一个她」

角色卡里带一个 **稳定同步根 ID**（`origin.characterId`），它不是本机数据库主键，也不是账号，而是同一角色跨设备合并时使用的身份：

- 本机新建角色时，同步根 ID 就是它自己的 `Character.id`；
- 导入带 origin 的卡时，当前设备会生成新的本地 `Character.id`，同时继承卡片中的同步根 ID；
- 导入没有 origin 的旧卡时，以新实例自己的 `id` 建立独立同步根；
- 以后再次导出始终携带同步根 ID，因此家里 → 公司 → 家里可以继续合并；
- 同一同步根允许对应多个本地实例。导入时必须选择具体合并目标，不能把多个同源角色混为一个。

不按名字猜。两张都叫「一只鱼」的卡是两个不同的人，撞名了也不合并（服务端会拒绝，并提示改用「新建副本」）。

> 老卡（2026-11 之前导出的）没有 `origin`，认不出是哪个角色，只能新建。要合并，请在导出方用新版重新导一次。

### 怎么做

导入时选到卡 → 如果本机只有一个同源角色，弹窗默认选中「合并进去」；如果有多个同源角色，必须先明确选择目标；没有同源角色则只能新建。想并排养两个仍可选择「新建副本」。接口上是 `POST /api/characters/import?target=<角色 id>`，成功写 `character.merged` 审计。

### 冲突口径：本地保留，导入追加

| 数据 | 合并怎么做 |
| --- | --- |
| 人设、模型参数、记忆设置 | **完全不动**。合并是补数据，不是覆盖设置 |
| 长期记忆 | 按**内容**去重后追加（不比 `dedupeKey`：本地那条可能是模型按另一套规则生成的 key） |
| 忆泡 | 按「哪一天 + 一句话标题」认同一件事，去重后追加 |
| 忆泡日历 | 本地那天的状态不动（已收口就还是收口），条数取大、整理时间取晚；本地没有的日子补一行 |
| 日记 / 手账 | 本地版本**一版都不删**；导入的接在本地最大版本号后面成为新版本，「今日一句」重新指向这次进来的那一版日记 |
| 阶段总结 | 同一周期（起止时间）已有就不再写第二份 |
| 梗语录 | 同一句台词只留一条，本地那条的开关与使用次数不动 |
| 她的朋友 | 沿用已有关系：互动次数取大、最后互动取晚，记忆与总结去重后并进去 |
| 朋友的备注 | 取并集：本地叫法排在前（那是她在这台机器上亲手起的），导入的补在后面；重复的合并，超过 8 个按顺序截掉 |
| 来源指针 | 一如既往地清空（旧机器的消息 / 忆泡 id 带过来是死指针） |

**合并是幂等的**：同一张卡重复合并，结果只有「没有新内容」，不会堆出一串重复记忆或重复版本。所以合并完不放心可以再合一次，看看提示里是不是 0。

## 5. 删除是彻底删，先导出再删

删除**没有回收站**。角色、会话与消息、记忆与忆泡、阶段总结、梗、她的朋友关系、表情包清单都会被清掉，`.data/stickers/<角色 id>/` 与 `.data/sticker-originals/<角色 id>/` 两个目录也会整目录删除。

审计日志保留（`characterId` 置空，同时会写一条 `character.deleted` 记下名字和删除量），token 账单保留。删除和必要审计同事务提交，审计失败则回滚删除。文件在提交后清理：如果失败，接口仍表示角色已删除，并返回 `cleanupWarning`，页面以警告提示联系管理员处理残留文件，不会误报删除失败或让用户重试。

所以想换电脑重建时，顺序是**先导出角色卡，再在新机器上导入，确认无误后回旧机器删**。反了就只能重养。

历史遗留的孤儿行和孤儿目录用 `yarn clean:character-orphans` 查看，加 `--apply` 清理。

## 6. 角色资料操作

- 「复制角色」只复制名称、标签、简介、人设、对话示例、称呼和头像配色；不复制密钥、模型配置、记忆、原文或渠道绑定。名称为原名加「副本」，超长时截短原名以符合 100 字符上限。
- 新建角色只有未提供称呼时才默认「主人」，显式清空表示不特意称呼，与资料编辑一致。
- 编辑资料字段缺省表示不修改，可选文本传空字符串表示清空；错误类型（如 `null`、数字或对象）返回 400，不再静默清空原资料。
- 本人私人范围的阶段总结与全局总结都能回导，私人范围归当前导入者；合并保留本地已有周期的总结。
- 导入记忆不继承外机 `dedupeKey`，避免本机或同包键碰撞漏导，稳定身份和正文去重规则不变。
- 日记历史每天合计最多 80 版（日记/手账各 40 版），整包最多 8000 版，导出与导入口径一致。
- 「更多」菜单按角色阻止重叠操作（包括等待确认的阶段），取消或失败后释放；晚到的更新响应不会把已删除角色重新放回列表。
- 列表记忆数通过数据库的 ACTIVE 条目计数获取，不再为了数字加载全部记忆 ID；API 返回结构与统计范围不变。
