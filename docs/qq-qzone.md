# QQ 空间：发说说、评论别人的说说

让她用自己的小号在 QQ 空间说话：发一条说说、翻别人的说说、留一条评论。

**这不是聊天渠道的延伸，是「她自己账号上的动作」。** 所以权限、频率、确认流程都比群公告更紧一档：
只认主人 QQ、每条都要人工确认、日上限压到个位数。

---

## 1. 为什么没有一条省事的路

QQ 互联的开放平台早就关了空间能力，能用的只有三条路：

| 路线 | 能做到 | 代价 | 结论 |
|------|--------|------|------|
| 官方开放 API | —— | 已不对外 | 不存在 |
| 协议端扩展 action | 发说说（含图、可见范围） | 依赖网关实现，动作名/参数各家不同 | **发说说的主路径** |
| 空间网页 CGI（逆向） | 发、评论、点赞、转发、按人查说说列表 | 自己维护 cookie + `g_tk`，接口说变就变 | **评论与列表只能走这条** |
| Playwright 点网页版 | 全都能 | 要开浏览器、慢、并发差、headless 易被识别 | 不采用 |

所以最终是「两条通道并排」：**发说说优先走协议端**（不用管登录态），**评论和列表走网页 CGI**。

## 2. 通道与参数

### 2.1 发说说：`send_qzone_msg`（协议端扩展）

```
POST {httpUrl}/send_qzone_msg
{ "content": "正文", "ugc_right": 1, "images": ["..."] }
```

- `ugc_right` 是 QQ 空间自己的编码：**1 公开 / 4 好友 / 64 仅自己**。传错不会报错，只会发到不该发的范围。
- 返回 `tid` 是最好的情况；**没有 tid 不等于失败**。
- 明确「动作不存在」（`retcode 1404` / HTTP 404 / 文案含「不支持」）时才降级到网页 CGI；
  其余失败（风控、未登录）一律停手，**不许重试**。

### 2.2 网页 CGI（评论、说说列表）

凭证：`get_cookies { domain: "qzone.qq.com" }` → 从 `p_skey` 算 `g_tk`。

```
g_tk = 5381; 每位 h += (h << 5) + code;  每步 & 0x7fffffff
```

每步都要截断：JS 的 `<<` 是 32 位有符号运算，不截断会溢出成负数，接口只回 `-3000`。

| 动作 | 接口 | 关键参数 |
|------|------|----------|
| 发说说（兜底） | `taotao.qzone.qq.com/cgi-bin/emotion_cgi_publish_v6` | `con` / `hostuin` / `ugc_right` / `format=json` |
| 评论 | `taotao.qzone.qq.com/cgi-bin/emotion_cgi_re_feeds` | `topicId`=`{uin}_{tid}__1` / `hostUin`=**被评论的人** / `uin`=她自己 / `content` / `format=json` |
| 说说列表 | `taotao.qq.com/cgi-bin/emotion_cgi_msglist_v6` | `uin`=看谁的 / `pos` / `num` |

三个容易出错的地方：

1. **`topicId` 是 `{uin}_{tid}__1` 三段式，不是裸 tid**。之前直接传裸 tid，接口回
   `-10004 参数错误`；末尾 `__1` 是评论类型（1 = 普通评论，2 = 回复）。
2. **`hostUin` 和 `uin` 写反会变成给自己留言。** 这两个字段长得太像，改代码时先看这一行。
3. **列表接口的域名是 `taotao.qq.com`，没有 `.qzone` 那一段。** 抄错会 302 到登录页。

评论走 `format=json`（不是 `fs`）：`fs` 回 HTML、`jsonp` 回 script 包裹，只有 `json`
回纯 JSON，`assertQzoneOk` 才能校验。而 `parseQzoneJsonp` **必须先当纯 JSON 试**，
因为 `format=json` 的响应里 `data.feeds` 那串 HTML 带 `(`/`)`，先按 JSONP 切括号会把
整段切坏（2026-11-02 实测踩到）。

### 2.3 为什么不用 `feeds3_html_more`（好友动态）

一开始用的是它，2026-11-02 实测否掉了：

- 返回的是**非标准 JSON**（键不带引号、字符串用单引号），`JSON.parse` 直接失败；
- 里面只有 `data.main` 那堆翻页参数，**一条说说都没有**；
- 退一步走 `parseQzoneFeedsHtml` 抠 HTML 也行不通 —— 响应里根本没有 `f-single` 块。

换成 `emotion_cgi_msglist_v6?uin=<某人>`：干净 JSON，`tid` / `content` / `created_time` / `cmtnum` 全都有，
评论要的正是 `tid`。代价是它**按人查**，不是一条聚合流 —— 所以「看看空间」按名单逐个拉。

## 3. 指令（只认主人 QQ）

| 主人说 | 她做什么 |
|--------|----------|
| `发条说说：今天下雨了` | 拟稿 → 回「说说草稿…」→ 等确认 |
| `发个说说`（没主题） | 按此刻心情自己写一句，同样要确认 |
| `看看空间` | 按「空间好友 QQ」名单（留空则协议端好友列表）逐个拉最近 2 条，编号列出，并**顺手挑最新一条拟好评论**问「行吗」 |
| `看看 123456 的空间` | 只看那个人最近的说说，同样顺手挑一条问 |
| `评论第 2 条：好可爱` | 评论第 2 条；不带内容就让她自己写 |
| `确认发说说` | 真的发出去 |
| `确认评论` | 真的评论 |

三个不能省的细节：

1. **确认词分开**：公告是「确认发布」，空间是「确认发说说」/「确认评论」。
   共用一套的话，一句回执到底发公告还是发说说，代码无从判断。
2. **裸「确认」不算**：太容易误碰。
3. **评论必须有目标**：没列过列表就说「评论第 2 条」，她会让你先「看看空间」，**不猜**。

「看看空间」现在会**顺手挑最新一条（第 1 条）拟好评论**，一并问「行吗」——不用你再发「评论第 1 条」。
拟稿失败（模型没配、额度用完等）只回列表、不算错。想评论别的条，还是回「评论第 N 条：内容」。

群友说「发条说说」一律当闲聊 —— 空间是她自己账号，不是群资产。

### 3.1 空间主动：她自己想发 / 想评论，来问你「行吗」

上面是「你下指令，她执行」。还有一个反过来的模式：**她自己决定内容，你只做同意**。

开了连接设置里的「她想发 / 想评论时主动来问」之后，由常驻进程 `yarn proactive:run`
每 60 秒跑一轮 `runQzoneAutoTick` —— 但**只有到了你设的时间点**（见下）才会真的问她：

1. 到了时间点、且当天还没问够次数，她凭最近的记忆 + 朋友最近的说说，
   决定「要不要发一条说说 / 评论一条」；
2. 想好了就落成 `PENDING` 草稿，私信你：

   > 我想发一条说说：
   > 今天下雨了，想起你说喜欢雨。
   > 回复「确认发说说」我就发，回别的就当我没提。

   或

   > 我想评论 烟火清凉 的说说「…」，评论写的是：
   > 好会写。
   > 回复「确认评论」我就发，回别的就当我没提。

3. 你回「行 / 发 / 可以 / 好 / 嗯」就发；回「不行 / 算了 / 不要」就不发。

**时间点怎么定**（连接设置里两个字段）：

- 「主动问的时间点」：`12:00,18:00,22:00` 这种，逗号分隔。到点后 5 分钟内会触发，
  错过就等下一个点。**留空 = 她从不主动问**（即使勾了「主动来问」开关）。
- 「每天最多主动问几次」：跨所有时间点的当日总上限，默认 2。

几个刻意的约束：

- **内容永远她定**，你只点头摇头；她不会因为你回了句「行」就自己另写一条。
- **口语审批只认短词**：`isQzoneApprove` / `isQzoneReject` 只匹配「行 / 不行」这一档的
  单字短词，长句、带疑问（「行不行」）一律不触发，避免误判。
- **两条 PENDING 并存时**（一条说说 + 一条评论），口语「行」不指定发哪个，
  让她请你回「确认发说说 / 确认评论」——分不清就让人说清楚，别瞎猜。
- **没到时间点不花一分钱**：`isQzoneAutoAskTime` 是纯函数，到点判定在调模型之前，
  平时每 60 秒的 tick 只是算一下「现在几点」，不调模型。
- **已有待确认草稿时这轮跳过**，不会追问到烦人。
- 主动问**不占** `proactive.ts` 的日上限，它有自己的配额（发说说 / 评论各自算，
  默认每天 3 条说说、8 条评论），见第 5 节。

### 3.2 名单怎么来的

- 连接设置里的「空间好友 QQ」优先（逗号分隔，最多 10 个）。
- 留空则用协议端标准 OneBot 的 `get_friend_list`，取前 5 个。
- **设备号要滤掉**：`我的电脑 / 我的手机 / 我的Pad`（`2113929217~2113929219`）不是人，
  实测它们就排在好友列表最前面，不滤的话一次「看看空间」有 3 个请求打在空气上。
- 她自己也要排除：没人要自己评论自己的说说。

## 4. 数据与状态

`onebot_qzone_actions` 一张表装两类动作（`kind = POST / COMMENT`）：

```
PENDING → PUBLISHING → PUBLISHED
                     ↘ FAILED
PENDING → EXPIRED（10 分钟）/ CANCELLED（同连接来了新草稿）
```

- 同一连接同一 `kind` 只留一条 PENDING：连着说两次「发说说」，旧草稿会被 `CANCELLED`。
- 认领是原子的（`UPDATE … WHERE status='PENDING'`），重复投递的确认事件不会发两次。
- **没有 tid 也记 `PUBLISHED`**：记成 FAILED 会让人以为没发，然后重发一条。
- 审计写 `audit_logs`：`channel.qzone_published` / `channel.qzone_failed`，不含 cookie。

列表**不落库**，只在进程内缓存 10 分钟。落库会让下次读到一个早已翻页的 tid，
然后评论到一条牛头不对马嘴的说说下面。

## 5. 风控

腾讯《QQ 空间服务条款》禁止自动化。这条通道能跑，但代价是账号风险，所以默认值压得很低：

| 项 | 默认 | metadata 字段 |
|----|------|---------------|
| 每天说说 | 3 条 | `qzoneDailyPosts` |
| 每天评论 | 8 条 | `qzoneDailyComments` |
| 评论冷却 | 30 分钟 | `qzoneCommentCooldownMinutes` |
| 好友名单 | 空（取好友列表前 5） | `qzoneFriendQqs` |

`0` = 不限（与群聊限流语义一致）。**先用小号跑一周**，再考虑放宽。

一次「看看空间」最多 5 个请求（串行），已经不少了 —— 第一个回 `-3000` 就立刻停，
不会把剩下几个也撞上风控。

## 6. 怎么启用

1. 页面「系统管理 → QQ 渠道 → **QQ 空间**」勾上开关（默认关）。
2. 同一页填「主人 QQ」—— 空着等于这个功能不生效（空间只认主人）。
3. 想限定看谁的空间，填「空间好友 QQ」；不填就走好友列表。
4. 想要「她主动来问」的模式，再勾上「她想发 / 想评论时主动来问我」，并让常驻进程跑着：

```bash
yarn proactive:run     # 这个进程同时管「主动找话」+「群内找话题」+「空间主动问」
```

5. 跑一次探针，确认通道通：

```bash
yarn probe:qzone                 # 只读：登录信息 / cookie 有没有 p_skey / 好友列表 / 说说列表
yarn probe:qzone --post --content="测试，稍后删"    # 真发一条，默认仅自己可见
yarn probe:qzone --comment-test --index=1          # 真评论列表里第 1 条
```

6. 私聊她说「发条说说：…」；或等她主动来问你「行吗」。

探针不受开关限制，但正式使用要先打开开关；改了开关/名单/配额后适配器会自动重连
（`revision` 里带了这几个字段）。

## 7. 排错对照

| 现象 | 原因 | 做什么 |
|------|------|--------|
| `QZONE_NO_AUTH` | 协议端没实现 `get_cookies`，或返回里没有 `p_skey` | 跑 `probe:qzone`；退路是把 cookie 填进 `QZONE_COOKIE` 环境变量 |
| `QZONE_AUTH_302/401`、`QZONE_API_-3000` | 登录态过期 | 重启协议端、重新登录 QQ |
| `QZONE_API_-10000` / `-2` | 操作太频繁 | 等，别重试 |
| `QZONE_API_-10001` | 参数不对（评论最常见） | `probe:qzone --comment-test`，重点看 `topicId` / `hostUin` |
| 列表空 | 目标号没有可见说说，或名单不对 | 换「看看 123456 的空间」直接指定 |
| 说说没 tid | 协议端没回 | 去空间确认，**别让我重发** |

## 9. 还没做的

- **点赞**：接口是 `internal_dolike_app`，参数（`unikey` / `curkey`）要从动态列表里带出来，
  当前解析只保留 tid/uin，先不做。
- **说说正文进记忆**：现在只落在 `onebot_qzone_actions`，还没写进 `messages`。
  她记得「我发过一条关于雨的说说」要等这一步。
- **主动问的频率微调**：目前「每 60 秒判断一次、有 PENDING 就跳过」，没有像
  `proactive.ts` 那样独立的「几天一次 / 安静时段 / 最短间隔」闸门。现在靠
  「草稿确认期间不重复问」压着，够用；想让她更克制再仿照 `proactive-settings.ts`
  加一套。
- **自动挑人评论**：现在「评论谁」由主人挑，或她自己从名单里选。风险主要在频率和误判，
  名单已经限到最多 10 个。
